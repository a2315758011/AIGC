# AIGC 知识三级评级、晋级与调用规范

版本：V1.0.0
适用仓库：a2315758011/AIGC
目的：让有结果、有验证的知识优先进入 AI 的剧本分析、导演预演和分镜创作；未经验证的资料只能作为候选参考，不能伪装成事实或强制规则。

## 1. 三级评级

评级对象是**具体知识条目/方法及其适用范围**，不是整篇论文、整个 Skill 或整个专业领域。一个 Skill 可以同时包含高、中、低不同等级的知识。

| 评级 | 含义 | 最低证据要求 | AI 使用方式 |
|---|---|---|---|
| **高** | 已验证、可稳定复用 | 有明确方法和适用边界；有可检查的真实结果或可重复自动测试；验证记录、样本/版本/参数可追溯；关键结论经过独立复核或独立来源交叉印证；无未解决的严重反例 | 默认优先调用；可作为该范围内的标准工作方法，但仍需检查当前剧本条件 |
| **中** | 多源支持、部分验证 | 至少两个真正独立来源支持，或有可复现的代码/测试/案例；方法、限制和失败条件已记录；但目标模型/目标工作流的实测、独立盲评或样本量仍不足 | 作为优先候选方案；可用于预演和分镜草案，标注待验证点；不得宣称稳定有效 |
| **低** | 线索、推断或未验证方案 | 单一来源、二手转载、作者自述、理论推断、仅有规则草稿，或尚无有效结果 | 仅供探索、备选和实验设计；不得覆盖高/中级知识，不得自动成为强制规则 |

**评级是可信度，不是质量好坏。** 低级可能很有潜力；高级也只在明确验证范围内有效。

## 2. 高/中/低的硬性边界

### 高级必须同时满足
1. 知识条目写清楚：解决什么问题、输入条件、操作步骤、预期结果、适用边界。
2. 有可核验的结果：测试日志、样本、输出、评分或可重复自动化结果；只有“研究认为有效”不够。
3. 有复核：独立评审、独立复现或独立来源交叉验证；同一作者重复发布不算独立。
4. 记录失败样本和反例，不能只挑成功案例。
5. 结果只在实际验证过的范围内标为高。例如 CI 通过只能证明该 CI 覆盖的代码/结构合同通过，不能证明生成图片或视频质量通过。

### 中级适用情形
- 多个独立来源对同一机制给出一致支持，但目标模型尚未做配对测试。
- 开源代码和测试源码已审查，但未安装/运行。
- 有作者真实案例和可复现步骤，但缺少第三方复核或目标工作流复测。
- 有专项测试规程和基准集，但尚未生成目标模型样本。

### 低级适用情形
- 单一创作者观点、厂商宣传、搜索摘要、转载或无法确认归属的材料。
- 专业人员合理推断但没有结果证据。
- Skill 已写好，但没有同行审查、自动回归或真实生成验收。
- 测试受环境/权限阻塞，结果为 NOT_RUN、UNKNOWN 或 SERVICE_NOT_RUNNING。

## 3. 证据记录与独立性

每条知识至少记录：唯一 ID、知识名称、专业领域、具体主张、评级及理由、原始来源 URL/作者/机构/日期/版本、独立来源组、复现步骤、目标模型/软件/版本/参数/样本数、结果数据、失败案例、评审人数与盲评情况、已验证和未验证范围、关联 Skill/测试文件及 Git Blob SHA、最近复核日期与评级历史。

论文基准成绩不能直接转写为用户当前模型成绩；仓库 README 不能证明代码运行成功；静态测试不能证明视觉成片质量；作者自测不能标记为独立复现。

## 4. 评级与证据标签的关系

原有 E0-E4 证据标签继续保留，作为底层证据描述；低/中/高是面向 AI 调用的汇总评级。
- E0：未核实线索。
- E1：原始来源已访问并核对内容。
- E2：不同独立来源交叉支持。
- E3：方法、代码或案例已复现。
- E4：目标工作流中完成对照/回归验证。

默认映射：低通常为 E0-E1；中通常达到 E2 或 E3；高必须有 E4 或同等强度的重复可核验结果，并满足独立复核要求。存在重大未审查风险时不得机械升档。

## 5. AI 自动调用规则

每次收到剧本或分镜任务，按以下顺序执行：
1. 读取本文件和知识资产评级登记表-V1.json。
2. 解析剧本：人物、场景、道具、时空、剧情事件、动作、情绪、时长、用户锁定事实。
3. 按任务命中知识域：叙事/导演、场景真实性、人物资产、站位调度、分镜、运镜、动作特效、生成与验收。
4. 先选高级且适用的知识；再选中级作为补充；低级只在高/中级缺失或用户要求探索时作为候选，并显式标注。
5. 先建立共享事实底稿和场景/人物空间基线，再做导演预演，之后生成正式分镜。
6. 分镜逐镜检查人物位置、朝向、视线、动作因果、时间、景别、摄影机位置/运动、轴线、道具状态和跨镜连续性。
7. 对未知信息标记“未知/待确认”，不得为了填满结构而编造。
8. 对关键方法标注评级、证据来源和验证边界；不必把每个普通句子都塞入评级标签。
9. 交付前运行可用的结构校验/回归测试；真实图像/视频未生成时，明确标记“预演/文本设计，未做真实生成验收”。

### 冲突处理
- 当前剧本、用户明确要求和参考素材事实优先于通用知识。
- 高级规则与剧本事实冲突时，不得机械套用；判断是否不适用，并记录原因。
- 同一问题出现冲突知识时，优先选择验证范围更接近当前模型、场景和制作链路的知识，不只看等级。
- 不允许低级知识覆盖高级知识；若出现可信反例，先建立复核任务，不静默改写标准。

## 6. 晋级、降级与淘汰

- 低→中：补齐独立来源或完成可复现方法审查，并明确限制。
- 中→高：在目标制作流程取得可核验结果；使用受控对照/回归；保留失败样本；由独立评审复核。
- 任意等级降级：发现来源错误、许可证问题、版本失效、复现失败、关键反例或适用条件变化。
- 过期知识：模型/软件大版本变化后标记“需复核”，不能无期限沿用高评级。
- 失败方案不删除：保留在失败反例库，记录失败条件和不应调用的场景。

## 7. 剧本预演与分镜的标准产出

每个剧本至少产出：
1. 剧情事实与不可改动项；
2. 人物/场景/道具资产底稿；
3. 场景空间结构和人物初始站位；
4. 导演预演：场面目标、人物行动、情绪节拍、调度和关键事件；
5. 正式分镜：镜号、时长、景别、机位、构图、人物位置/朝向/视线、动作、台词、运镜、声音和转场；
6. 逐镜独立自检与修订终稿；
7. 使用的高/中/低知识清单及未验证项。

预演不是随意摆场景：先满足现实空间、建筑功能、物理支撑和人物动线，再服务剧情表达。分镜不是只写镜头形容词：每镜必须能说明观众看到什么、人物做什么、摄影机怎样拍、前后状态如何衔接。

## 8. 当前执行状态声明

本评级规范建立后，知识资产登记表中的评级是本轮基于已读取仓库证据做出的**初始评级**，不是全仓库当前 114 个文件逐条审计完成。未纳入登记表的资料默认不得自动视为高级；应在后续审计时逐条登记。


## 9. 版本漂移与失效知识门禁

- 评级登记表记录的来源版本与 Git Blob SHA 以本轮审计快照为准；每次调用前仍须核对当前主分支是否有更新。
- 专业 Skill 的 `SOURCE_LOCK.json` 与当前主线版本不一致时，旧快照不得作为最新权威；应直接读取当前主线对应 Skill、references、scripts 和 tests，并将集成状态标为“版本待同步”。
- 导演统筹包当前锁定的场景真实性、分镜和站位规则版本落后主线；在刷新锁与回归前，只使用其统筹思路，专业规则必须从当前主线单独读取。
- 运镜 Skill 的 frontmatter 版本与 SOURCE_LOCK 版本不一致，离线包发布前必须修正并重算锁。
- `authored_pending_review`、`NOT_RUN`、`BLOCKED`、`SERVICE_NOT_RUNNING` 均不能升级为高；只能按已取得的证据范围评级。
- 版本更新、模型切换、参数变化或生成服务变化后，旧的目标工作流结果应标记“需复核”，不得自动继承高评级。
