# 剧本 → 导演预演 → 分镜：AI 知识调用执行卡

版本：V1.0.0
关联规范：[三级知识评级、晋级与调用规范](./三级知识评级与AI调用规范-V1.md)  
完整资产+分镜执行：[漫剧资产与分镜生产 SOP（空间先行）](./漫剧资产与分镜生产SOP-空间先行-V1.md)
评级数据：[知识资产评级登记表](./知识资产评级登记表-V1.json)

## 目标
用户提供剧本后，AI 按当前剧本条件调用评级最高且适用的知识，先建立可信场面，再完成导演预演和可执行分镜。


## 阶段零：知识与依赖版本门禁

1. 读取本清单、三级评级规范和知识资产登记表；核对当前 `main` 提交及登记表更新时间。
2. 比较所有将调用 Skill 的 `SOURCE_LOCK.json` 与当前主线版本。发现版本漂移时，直接读取主线当前权威文件，不得沿用过期离线快照。
3. 当前主线核对基线为 `b47f00b965cd122296788db79f6d18d3dae90cdb`：导演统筹 V1.4.4、场景真实性 V1.15.0、分镜 V1.3.6、站位规则 V1.9.0、运镜 V1.1.1；执行时仍逐项比对当前 SHA。
4. 漫剧完整资产+分镜闭环使用 `manju-director-cn` V1.1.2 / 规则 V2.10.6，必须先锁定场景空间基线；禁止沿用旧版 V2.10.5 快照。
5. `fight-impact-vfx-cn` 尚待独立评审；可用于形成候选动作方案，不作为已验证成片规则。

### 预演复杂度选择

- **通常不必做 3D 白模**：单人简单对白、固定机位、无明显空间位移的低复杂度镜头。
- **建议做白模/关键帧预演**：多人调度、走位绕障碍、人物与摄影机相对运动、升降/环绕、多机位覆盖或跨镜空间关系容易冲突的镜头。
- 白模/结构化导演台只证明空间和运动意图被表达；不保证视频模型服从。必须把白模、角色身份参考、场景美术参考分开指定职责，并在成片中复核。
- 如果当前环境已有经授权的结构化导演台/MCP，先读取完整工程状态与真实角色/镜头/关键帧ID，保护人工锁定项，小步编辑后执行工程验证；若没有现成工具，不为简单镜头强制安装。时间基准按工具项目声明，不能默认所有工具都是24fps。
- 场景静态几何、动态角色/道具和摄影机运动分开保存；大角度环绕时检查角色未观测侧面，必要时增加同一角色ID下的正/侧/背视角锚点。研究论文/模型功能不等于目标消费级视频模型已经支持。

## 阶段一：剧本理解与事实锁定
- 提取原剧情顺序、人物关系、因果、台词意图、悬念和情绪变化。
- 保留用户指定的时长、风格、画幅、角色、场景和不可修改内容。
- 记录人物/道具初始状态与事件后的状态。
- 剧本没有交代的内容标记为未知，不擅自补成剧情事实。

## 阶段二：评级知识检索
1. 读取知识评级登记表。
2. 根据本场戏检索相关知识域。
3. 先选高级知识，再选中级；低级只在高/中级缺失或用户要求探索时作为候选。
4. 检查知识适用范围、来源版本、验证模型和限制。
5. 建立本场已采用知识/未采用知识/原因清单。

## 阶段三：资产需求总账与场景空间基线（空间先行）

1. 先建立角色、服装、场景、固定设施、家具、关键道具和状态变体的资产需求总账，分配稳定 ID；这一步只盘点，不先批量生图。
2. 对会议桌、讲台、床、车辆等影响空间占地的大型物件，先记录尺寸依据或代理占位；未知尺寸保留未知。
3. 调用 `scene-realism-director-cn`，先建立场景边界、墙体/门窗、固定设施、家具、通道、支撑面、稳定锚点、主要机位区和遮挡关系。
4. 生成/确认可复核的俯视/布局图与关键视角/白模，并维护唯一 `scene_id` 和结构化场景数据。
5. 达到 `SPACE_BASELINE_LOCKED` 后，才制作/绑定角色、服装和关键道具母版；尺寸改变布局时必须重锁场景。
6. 没有可定位空间锚点时只能继续剧本分析和资产盘点，不得开始正式逐镜分镜。

## 阶段四：导演预演与场面调度

- 导演先确定场面目标、观众信息、人物目标、动作节拍和情绪落点。
- 在已锁定的场景基线上安排人物初始位置、走位路径、停留点、视线和摄影机覆盖。
- 完整资产+分镜任务由 `manju-director-cn` 作为单一主入口执行；普通正式分镜由 `storyboard-director-cn` 内置导演推演执行。
- 只有完整导演方案、复杂跨专业冲突或完整成片统筹才额外调用 `director-previs-cn`；不得让导演层和分镜层各写一份相互竞争的分镜。

## 阶段五：正式分镜

正式逐镜稿必须引用已锁定的 scene_id、人物/道具 ID 和空间锚点。镜头景别不得改变人物世界坐标；每镜开始状态承接上一镜结束状态。远距离人物不得为双人近景强行靠近。
每镜至少写清：镜号、预计时长、景别、机位和构图；出镜人物、世界位置、身体/头部朝向、视线；动作起点、过程、终点及道具状态；台词、表演、情绪和观众信息；摄影机运动、焦点、轴线与切镜衔接；声音、特效和下一镜承接状态。

## 阶段六：独立自检与交付
按当前 main 的正式分镜编写和自检权威文件逐镜检查，修复 P0/P1 后重写完整终稿，再从头复检。根据使用情况运行 SCG、事件时长和运镜结构校验器。
最终分开标记：文本创作、结构/静态校验、白模或静态预演、真实图像/视频生成、人工/独立审片。没有实际生成与审片证据时，不得称为成片验证通过。

## 阶段七：程序化代码视频（按需）

只有当目标交付是代码驱动动画/MP4、动态 UI/HUD、动态图形、解释动画、程序化特效或可重复逐帧渲染时，才调用 `video-director-cn`。普通正式分镜不自动进入此阶段。

1. 先完成阶段一至六；锁定正式分镜、SCG、事件时间账本和批准资产。
2. 读取 `docs/代码动画与程序化视频制作规范-V1.md`、`skills/video-director-cn/SKILL.md` 和 `SOURCE_LOCK.json`。
3. 先运行 `node skills/storyboard-director-cn/scripts/分镜事件时长校验器-V1.js events.json`；Txx 错误回到源账本修复，Wxx 警告人工复核，Node.js 不可用标记 NOT_RUN。再复核 SCG，并使用 `compile_aigc_timeline.py` 派生渲染时间表。不得复制第二份世界状态账本，不能补造 shot_id/event_id 或时间。
4. FPS、分辨率、时钟类型来自项目批准规格；运行 `check_timeline.py`，ERROR 未清零不得进入渲染。
5. 先做静帧，再做纯函数式动画；渲染 MP4 后运行 `qa_video.py`，检查机器报告和 beat/phone/hook 联系表。
6. 独立检查关键帧、动作连续帧、手机可读性、剧情事实和音画同步。机器 PASS 不等于真实真人表演、目标视频模型或最终成片通过。
7. 交付源码、timeline.json、MP4、QA 报告、联系表、独立审片记录和来源锁；未运行的步骤标记 NOT_RUN。

## 交付顺序
1. 剧本事实与导演意图；
2. 场景空间与人物站位基线；
3. 导演预演（场面调度/情绪节拍/关键动作）；
4. 正式分镜脚本；
5. 分镜独立自检及完整修订终稿；
6. 知识调用与评级说明；
7. 未验证事项和风险。

## 阶段八：特效、剪辑与成片验收（按需）

只有用户明确要求继续制作特效、系统 UI/HUD、剪辑、声音、字幕或最终成片时，才加载对应专业 Skill。每个阶段以已批准的上游事实为输入，不自动重写剧本、资产或分镜。没有真实成品与独立验收证据时标记 NOT_RUN。
