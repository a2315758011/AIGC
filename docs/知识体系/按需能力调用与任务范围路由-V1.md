# 按需能力调用与任务范围路由

版本：V1.0.0  
适用范围：`a2315758011/AIGC` 全部专业 Skill、脚本、参考资料与生产工具。  
定位：本文件定义每次任务如何选择能力，不替代各专业 Skill 的具体规则。

## 1. 核心原则

**能力库完整，单次调用最小化。**

仓库覆盖完整制作链，不代表每个任务都要跑完整制作链。每次请求默认选择能够正确完成用户指定交付物的最小能力组合。

- 用户要一个局部结果，就只完成该局部结果。
- 用户要一个专业环节，就只执行该环节及其必要前置检查。
- 用户明确要求跨领域统筹或完整制作，才扩大到多个专业域或端到端流程。
- 不得把“可能有帮助”当成自动加载、自动执行其他 Skill 的理由。
- 不得为了调用某个下游工具，擅自重做已经批准的上游成果。
- 必须区分“读取上游事实/规则”和“执行上游专业任务”：读取已批准分镜、SCG 或资产信息，不等于重新制作分镜或资产。

本路由服从用户本轮明确范围。若用户说“只做 X”“不要做 Y”，X 是交付目标，Y 是禁止扩展项；只有涉及安全、事实正确性或工具可执行性的硬性依赖，才可做最小必要检查，并说明原因。

## 1.1 正式分镜默认由导演主导（强制）

分镜属于导演的核心职责范围。**正常的正式分镜制作必须经过导演推演/导演意图判断，不得因为本次只做分镜、没有跨专业任务，就省略导演职责。**

现有 `storyboard-director-cn` 已内置导演推演关卡，负责从剧情节拍、观众信息、场面调度、逐镜面部表演、跨 10 秒/15 秒生成段落表演尾态继承、镜头价值和可执行性推导正式镜头。因此，普通正式分镜任务的默认链路是：

**导演推演（由 storyboard-director-cn 内置执行）→ 分镜脚本编写 → 独立质检 → 必要修复 → 完整终稿。**

这里必须区分两个概念：

- **导演职责/导演视角**：正式分镜制作的必需环节，由 `storyboard-director-cn` 内置的导演推演承担。
- **`director-previs-cn` 独立导演统筹 Skill**：额外的整体导演方案、跨专业任务路由、共享事实协调与场面预演入口。它不是导演职责本身，也不是每次分镜任务都必须额外加载的第二套分镜总控。

因此：
- 用户要求正式分镜、继续分镜或重做一场戏：必须执行导演推演，再调用 `storyboard-director-cn` 完成编写与独立质检。
- 用户只要求审核已有分镜：执行独立质检；不得为了“导演参与”而自动重写分镜。需要导演判断时，对照原剧本和已锁定导演意图进行审查。
- 用户只要求局部镜头修复：只对受影响镜头执行必要导演判断和修复，并复检关联镜头，不重做整场。
- 用户要求完整场面导演方案、复杂多专业预演或跨域协调：再额外启用 `director-previs-cn` 作为统筹层，并把同一份已锁定事实交给分镜专业 Skill。
- 导演统筹不得与分镜制作重复产出两份相互竞争的分镜稿；导演负责意图与决策，分镜 Skill 负责镜头正文，独立质检负责审核证据。

## 1.2 完整漫剧资产+分镜必须空间先行

用户明确要求“根据剧本给出整套漫剧资产和正式分镜”时，主入口是 `manju-director-cn`，必须遵循 [漫剧资产与分镜生产 SOP（空间先行）](./漫剧资产与分镜生产SOP-空间先行-V1.md)。顺序固定为：

**剧本事实锁定 → 资产需求总账 → 场景空间基线（scene-realism）→ 角色/服装/关键道具母版 → 导演场面调度 → 正式分镜 → 独立质检。**

关键区分：
- 先盘点资产需求，不等于先批量生成所有道具图；大型固定物先用尺寸/代理占位参与场景布局。
- 场景空间基线必须在正式逐镜分镜前锁定，至少包含可复核布局/俯视图、关键视角或白模、稳定锚点和通道数据。
- 场景锁定后再生成/绑定角色与关键道具母版；若资产尺寸改变空间布局，必须先重锁场景。
- `manju-director-cn` 是完整资产+分镜闭环的单一主入口，不再并行产出第二份竞争性分镜稿。
- 只做正式分镜仍调用 `storyboard-director-cn`，使用其内置导演推演和独立质检；不自动生成全套资产。
- `director-previs-cn` 只在整体导演方案、复杂跨专业统筹或完整成片任务中作为外层协调，不是每次分镜的必经步骤。

## 2. 任务范围分类

| 范围 | 识别方式 | 默认执行策略 |
|---|---|---|
| S1 单点能力 | 单个角色资产、一个场景检查、一条运镜、一个特效、一个镜头修复 | 只调用该专业 Skill；读取必要事实，不启动导演总控 |
| S2 单项交付 | 一份剧本分析、一版分镜、一张角色表、一组宫格、一段动画 | 调用该交付的主 Skill 和必需验收；按触发条件增加依赖 |
| S3 跨专业任务 | 同一目标明确涉及两个及以上专业域，存在交接或冲突 | 调用 `director-previs-cn` 进行轻量统筹，再调用实际需要的专业 Skill |
| S4 完整生产 | 用户明确要求完整一集、完整漫剧/短片、从创意到成片 | 执行完整生产链，按阶段启用专业能力，不要求所有 Skill 同时常驻 |
| Q 质量检查 | 用户只要求检查、验收、定位缺陷 | 只运行与目标交付物相关的检查器和独立审查；不自动重写或重新生成 |
| R 研究评估 | 用户只要求调研、比较、判断是否采纳 | 只执行来源核验、许可证/维护状态/适用性与复现评估；不自动安装或接入生产 |

默认采用能够满足请求的最窄范围。无法判断是否需要扩展时，先保持窄范围，不自行升级为 S3/S4。

## 3. 每次任务的路由步骤

### 第一步：锁定交付范围

内部明确以下信息：
1. 用户本次要得到的具体产物或结论；
2. 已有且必须沿用的剧本、镜头、角色、场景、道具和时间轴事实；
3. 用户明确禁止修改或不需要的内容；
4. 本次需要达到的验收级别。

### 第二步：选定一个主能力

先确定最直接负责交付物的主 Skill/工具。一个任务原则上只有一个主能力入口；其他能力作为依赖，不得多个总控重复接管同一职责。

### 第三步：划分依赖等级

- **必需（MUST）**：缺少就会导致结果错误、不安全或无法执行的事实/规则/校验。只加载相关部分。
- **条件触发（WHEN）**：只有出现明确条件才加载，例如多人走位才加载站位规则，摄影机运动才加载运镜 Skill，程序化 MP4 才加载 video-director。
- **可选（OPTIONAL）**：可能提升效果但不是完成本次目标的必要条件。默认不调用，除非用户要求或有具体缺陷证据。
- **本次排除（EXCLUDED）**：与本次目标无关，明确不加载、不执行、不产生额外交付。

### 第四步：执行到请求边界

只完成用户要求的交付物及必要验证。不得自动继续进入下一生产阶段。例如，分镜完成不自动生成视频；角色设定完成不自动生成分镜；特效方案完成不自动剪辑成片。

### 第五步：按需验收

只运行适用于本次产物的检查器。不可用的检查标记 `NOT_RUN`；静态检查不能冒充真实生成，机器 QA 不能冒充独立审片。

## 4. 常见任务的最小调用矩阵

| 用户请求 | 主调用 | 必要读取/条件依赖 | 默认不调用 |
|---|---|---|---|
| 只做一个角色设定/三视图 | `AIGC人物资产指令` 及对应角色资产规则 | 已批准角色参考、身份/服装锁定 | 分镜、运镜、video-director、漫画出版 |
| 只检查教室/办公室/建筑布局 | `scene-realism-director-cn` | 用户参考图、空间用途与尺寸事实 | 正式分镜、运镜、视频渲染 |
| 只写剧本分析/场面意图 | 剧本转分镜指令中的对应分析规则 | 原剧本与用户约束 | 场景生图、分镜宫格、视频生成 |
| 只把剧本转正式分镜 | 剧本编写指令 + `storyboard-director-cn` + 独立自检 | 按本场需要读取人物/场景/道具事实；复杂多人调度才加载站位规则 | 漫画排版、程序化视频、完整后期 |
| 完整漫剧人物/场景/道具资产 + 正式分镜 | `manju-director-cn` | 空间先行 SOP；`scene-realism-director-cn` 必须先建立并锁定场景空间基线，再做角色/道具母版和正式分镜 | 未要求的视频生成、剪辑、漫画出版；不重复生成第二份分镜 |
| 只做 4/9/12/25 宫格联系表 | `storyboard-contact-sheet-cn` | 已批准镜头顺序、独立画格、角色/场景参考；需要时读取 storyboard 规则 | 漫画页面出版、视频渲染 |
| 只设计一条摄影机运动 | `camera-motion-director-cn` | 读取已批准镜头、源画面和结束状态；不重写分镜 | 导演总控、资产重建、视频剪辑 |
| 只制作打斗动作/受击反馈 | `fight-impact-vfx-cn` | 读取已有角色/武器/场景事实；需要拆镜时才联读 storyboard，需要运镜时才联读 camera | 全套资产重做、无关场景设计 |
| 只做系统 UI/HUD/粒子叠加 | `system-ui-vfx-cn` | 读取内容真值、人物/道具锚点、遮挡和镜头时间；需要时复用 ChatCut | 默认不调用完整分镜链；只有目标是代码动画/MP4 时才增加 video-director |
| 只把批准的时间轴做成代码动画/MP4 | `video-director-cn` | 读取批准的分镜、SCG、事件时间账本并执行源账本预检 | 重新编剧、重新分镜、重新建立人物/道具世界状态 |
| 只审查一段视频/一组镜头 | 对应目标的 QA 脚本或独立审片规则 | 用户验收标准、批准参考和待审成品 | 自动重生成、无关专业 Skill |
| 只制作漫画页面/排字/去字 | `comic-production-director-cn` | 原始画格、连续性台账、目标平台规格；场景/分镜事实仅按需读取 | 漫剧视频渲染与摄影机运镜 |
| 明确要求完整一集/完整作品 | `director-previs-cn` 统筹 + 各阶段必要 Skill | 共享事实底稿、依赖版本、阶段门禁 | 不相关技能；即使完整生产也不要求全部技能同时加载 |

矩阵是默认路由，不覆盖专业 Skill 内更严格的安全、许可证、事实锁定或验收要求。

## 5. 导演总控的启用边界

`director-previs-cn` 不是所有任务的默认启动器，也不是所有 Skill 的父级必经节点。

仅在以下情况启用：
- 用户明确要求导演整体方案、综合统筹或完整场面预演；
- 同一任务确实跨两个及以上专业域，需要协调职责、事实或交接；
- 多个专业方案发生冲突，需要统一裁决。

以下情况不启用：
- 单一专业问题可以由一个 Skill 直接完成；
- 用户只要求一个局部产物或一次局部检查；
- 只是读取已批准成果并交给下游工具；
- 仅为“显得完整”而加入统筹层。

## 6. 上下游事实复用，不等于重复执行

下游工作可只读引用上游批准事实：
- 做运镜：读取镜头构图、人物位置和结束状态，不重新创作分镜。
- 做 HUD：读取人物锚点、遮挡和时间，不重新设计整场戏。
- 做程序化渲染：读取 SCG 和事件时间账本，派生渲染时间轴，不重建世界状态。
- 做成片审查：读取批准脚本和参考资产，检查实际视频，不自动改写剧本。
- 做漫画排字：读取已批准画格和对白，不重新生成原画。

发现上游事实缺失或互相矛盾时，只回到产生该缺陷的最早节点修复；不得借机重做整条链路。

## 7. 任务路由记录与用户可见汇报

每次执行至少在内部记录：
- 本次范围：S1 / S2 / S3 / S4 / Q / R；
- 主能力；
- 必需依赖；
- 实际触发的条件依赖；
- 明确未调用的能力；
- 本次交付和适用验收结果。

面向用户简洁汇报即可，例如：

> 本次只处理 7-1-13 的摄影机运动。调用 camera-motion-director-cn；只读取已批准分镜和角色空间事实；未调用分镜重写、资产生成、系统 UI 或 video-director。运镜静态校验通过，真实视频生成未执行。

简单任务不必输出冗长清单，但不得隐瞒能力扩展、未执行的验收或关键依赖。

## 8. 与现有权威文件的关系

- 根目录 `AGENTS.md` 负责入口路由与强制读取。
- 本文件负责每次任务的范围选择和最小调用策略。
- `AIGC知识结构总图与跨技能调用规范-V1.md` 负责领域架构、专业边界、事实合同和质量门禁。
- 各专业 Skill、原始指令、references、scripts、tests、SOURCE_LOCK 仍是专业规则权威来源。

不得将本文件复制成每个 Skill 内的一套新规则。若专业 Skill 有更严格的必要前置要求，遵循专业规则，但仍只执行与本次范围相关的部分。
