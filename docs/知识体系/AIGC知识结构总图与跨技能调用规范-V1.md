# AIGC 知识结构体系与生产依赖图

版本：V1.0.0  
维护对象：`a2315758011/AIGC`  
定位：本文件是仓库知识导航、领域边界和跨技能调用的总索引；不是新的专业规则源。各专业规则仍以对应原始指令、Skill references 与 SOURCE_LOCK 为准。

## 1. 总体架构

本仓库按“创意输入 → 导演决策 → 世界与资产 → 空间调度 → 镜头表达 → 动作视听 → 生成/后期 → 独立验收 → 研究迭代”组织。

| 层级 | 知识域 | 核心问题 | 权威能力/入口 | 主要输出 |
|---|---|---|---|---|
| L0 创意与叙事 | 剧本、人物目标、冲突、节奏、情绪、观众信息 | 这场戏为什么存在、观众要看到什么 | 剧本转分镜指令、导演统筹 Skill | 剧情事实、场面目标、情绪节拍 |
| L1 导演统筹 | 导演意图、专业拆分、事实底稿、冲突消解 | 哪些专业要参与、按什么顺序交接 | `skills/director-previs-cn/` | 导演简报、共享事实表、任务路由 |
| L2 世界与资产 | 人物身份/外观/服装、场景、道具、建筑、材质、资产连续性 | 世界中有什么、哪些事实不可改变 | `AIGC人物资产指令/`、`scene-realism-director-cn` | 资产设定、场景骨架、资产锁定项 |
| L3 空间与调度 | 场景静态几何、人物/道具动态状态、稳定身份ID、站位、朝向、视线、路径、遮挡、支撑面、轴线 | 人和物在空间哪里、怎样移动且不穿帮 | `storyboard-director-cn` + 站位规则；场景问题调用 `scene-realism-director-cn` | 空间基线、站位表、路径/关键帧、连续性状态 |
| L4 镜头与摄影 | 景别、机位、构图、视轴、镜头组接、摄影机轨迹、焦点 | 观众从哪里、以何种运动看到事件 | `storyboard-director-cn`、`camera-motion-director-cn` | 分镜、运镜执行单、结束帧 |
| L5 动作与视听 | 表演、动作因果、攻防、接触、受击、特效、声音、剪辑节奏 | 动作是否可读、有无力量反馈、声画是否同步 | `fight-impact-vfx-cn`；分镜/运镜按需协作 | 动作链、打击节奏、特效/声音执行单 |
| L6 生成与后期 | 图像/视频模型适配、提示词编译、参考控制、合成、修复、程序化代码视频 | 当前工具能否实现设计、如何分步生成 | 各专业 Skill 的模型适配与工具资料；真人安全分镜负责真人风格/合规转换；video-director-cn 负责代码动画、渲染时间表与 MP4 QA | 可执行提示词、代码动画工程、渲染时间表、MP4 与 QA 证据 |
| L7 质量与验收 | 结构检查、空间/连续性检查、时间轴/逐帧/音频 QA、A/B、盲评、真实成片审片 | 结果是否真的符合要求 | 各 Skill tests/scripts、video-director-cn 的 check_timeline.py / qa_video.py、独立自检指令 | 缺陷清单、测试证据、通过/未通过状态 |
| L8 研究与知识治理 | 外部仓库/论文/创作者方法、来源、许可证、复现、版本 | 新方法是否可信、是否值得采纳 | `docs/Deepresearch/`、`docs/`、SOURCE_LOCK、更新协议 | 研究报告、采纳决策、回归案例、版本记录 |

## 2. 专业技能边界

- **导演统筹与场面预演**：只负责导演意图、共享事实、专业路由、冲突消解和综合验收；不复制下游专业规则。
- **场景真实性导演**：负责建筑/环境结构、空间功能、透视尺度、接触遮挡、光照材质、参考图保真和全景完整性；不负责正式人物调度和摄影机运动。
- **分镜导演**：负责剧本转镜头、人物站位/朝向/视线、走位、镜头轴线、跨镜状态、独立自检与修复。
- **中文运镜导演**：负责摄影机物理运动、源画面可行性、运动预算、提示词编译和视频运镜审片；不得擅自改变人物世界坐标或分镜事实。
- **打斗与打击感特效导演**：负责动作因果、接触/受击、力量传递、命中特效、节奏、声音同步和特效审片；不替代分镜、运镜或现实伤害教学。
- **真人影视安全分镜**：负责真人实拍媒介锁、逐镜暴力视觉风险诊断、非图像化合规表达和 GPT 原生生图局部修复；不替代分镜结构、打斗动作因果、运镜或场景规则。
- **人物资产指令**：负责人设、外观、服装、人物/场景/道具资产一致性；与场景/分镜技能共享事实，不各自重造角色设定。
- **程序化视频导演**：负责已批准分镜之后的代码动画、动态图形、UI/HUD、程序化特效、音画时间表、逐帧渲染和 MP4 QA；不负责正式分镜、SCG 世界状态、真实演员表演或目标视频模型服从性。

## 3. 跨领域调用顺序

### 3.1 普通漫剧制作主链
创意/原剧本 → 导演意图 → 人物/场景/道具资产 → 场景空间基线 → 人物调度与正式分镜 → 运镜设计 → 模型提示词/生成 → 独立质检 → 修复与复检 → 交付。

### 3.2 场景图真实性任务
参考图/场景用途锁定 → 建筑与空间骨架 → 摄影几何 → 功能/支撑/接触 → 光照/材质 → 生成或局部修复 → 场景真实性检查表 → 配对盲评（用户要求效果验证时）。

### 3.3 多人走位/复杂场面
场景真实性（若空间本身有问题） → 共享空间基线 → 分镜导演/站位规则（位置、朝向、视线、路径、时间、支撑脚、遮挡） → 运镜导演（独立摄影机路径） → 连续性复检。

### 3.4 真人影视分镜与安全视觉转换
先锁定剧本和批准的人物/场景参考 → storyboard-director-cn 确定镜头事实 → live-action-safety-storyboard-cn 锁定真人实拍风格并逐镜评估实际画面风险 → 对不适合直观呈现的细节使用非图像化电影表达 → GPT 原生生图逐镜生成 → 风格/连续性/安全表达检查。涉及打斗动作因果时再调用 fight-impact-vfx-cn；涉及摄影机运动时调用 camera-motion-director-cn。不得将提示词改写用于隐藏被禁止内容，也不得声称提示词可保证通过审核。

### 3.5 打斗场面
先锁定场景/角色/武器事实 → 打斗技能设计动作因果和接触反馈 → 分镜技能拆镜并验证站位/动作连续性 → 运镜技能设计摄影机路径 → 生成/后期分层 → 声画与跨镜状态审片。只调用任务真正需要的专业技能，不机械加载全部技能。

### 3.6 程序化代码视频
原剧本/已批准分镜 → SCG 与事件时间账本复核 → video-director-cn 编译渲染时间表 → 静帧/代码动画 → 逐帧渲染 MP4 → 时间轴/成片机器 QA → 关键帧与连续帧独立审片。若内容包含真人表演，video-director-cn 仅承担可控 UI、字幕、动态图形、程序化叠加或预演，不得替代真实演员视频。

## 4. 跨技能共享事实合同

每个项目/场面只维护一份共享事实底稿，至少包括：

1. **创作事实**：原剧本、剧情顺序、时长、画幅、用户锁定内容。
2. **人物事实**：身份、外观、服装、体型、初始位置、身体/头部朝向、视线、动作能力。
3. **场景事实**：空间边界、入口出口、墙门窗、固定设施、地面/支撑面、通行区、光源。
4. **道具事实**：身份、尺寸依据、持有者、握持状态、位置、损坏/变化状态。
5. **时序事实**：动作起止、路径关键点、事件先后/并行、镜头起止状态。
6. **摄影事实**：机位、视轴、景别、摄影机路径、注视点；摄影机运动与人物运动分轨。
7. **证据等级**：用户明确、参考图可见、多源证实、合理推断、未知。未知不得补造。

下游技能只能在明确标注的可变字段内提出修改；不得无理由重置已锁定事实。发生冲突时回到最早产生冲突的决策节点修复。

程序化视频的 `timeline.json` 是渲染时间表派生视图：镜头/事件 ID 与时序必须追溯 SCG 和事件时间账本；不得复制第二套 entities / relations / events 或人物/道具世界状态。

## 5. 统一质量门禁

| 门禁 | 必须回答的问题 | 不通过时的处理 |
|---|---|---|
| G0 需求与事实 | 是否忠于原剧本、参考图和用户硬约束？ | 暂停设计，补齐/标注未知 |
| G1 世界可信 | 建筑、空间、功能、比例、支撑和光照是否成立？ | 回到场景/资产层修复 |
| G2 调度可信 | 人物路径、站位、朝向、视线、遮挡、时间是否连续？ | 回到调度层修复 |
| G3 镜头可信 | 景别、可见范围、机位、轴线、组接是否合理？ | 回到分镜层修复 |
| G4 运动可信 | 摄影机/主体/环境运动是否可执行且不破坏连续性？ | 降低运动幅度或拆分镜头 |
| G5 动作视听可信 | 接触、受力、受击反馈、特效来源和声音是否同源？ | 先修动作因果，再修特效 |
| G6 工具可执行 | 目标模型/软件是否真实支持所需控制？ | 降级为可实现方案，不虚构参数 |
| G7 结果验收 | 是否有真实生成物、检查范围和缺陷记录？ | 标记未验证，不得宣称通过 |

所有交付统一区分：**已设计、已静态校验、已真实生成、已人工/独立审片、已通过验收**。前一状态不能冒充后一状态。

## 6. 研究证据与采纳治理

外部方法进入正式规则前，至少记录：来源链接、作者/机构、发布日期/版本、许可证、研究日期、具体方法、复现步骤、适用范围、限制、独立交叉证据、采纳/暂缓/拒绝理由。社交平台经验、仓库 README、论文结果和真实生产验证属于不同证据等级，不得混为一谈。

建议证据标签：
- E0：未核实线索；
- E1：来源可访问且内容可核对；
- E2：有独立来源交叉验证；
- E3：方法/代码/案例可复现；
- E4：在目标工作流中完成对照或回归验证。

只有通过相应验收的内容才可升级为强制规则。研究资料放入 `docs/Deepresearch/` 或现有专题目录；可执行规则放入对应专业 Skill；跨域导航和路由只放在本总索引、根 README 与 AGENTS 中，避免重复维护。

## 7. 权威来源与更新顺序

1. 根目录 `AGENTS.md`：任务路由与强制读取顺序。
2. 根目录 `README.md`：仓库总入口。
3. `docs/知识体系/AIGC知识结构总图与跨技能调用规范-V1.md`：知识分类、依赖关系、共享事实与统一门禁。
4. `skills/README.md`：专业 Skill 目录。
5. 各专业原始指令、Skill、references、scripts、tests、SOURCE_LOCK：具体规则的唯一权威来源。
6. `docs/Deepresearch/`：研究证据，不自动等同于已采纳规则。

更新专业规则必须遵守 `skills/SKILL_UPDATE_PROTOCOL.md`：先修订权威指令，再冻结 SHA，更新 references/Skill，运行测试，最后发布。不得只改本总索引来替代专业规则更新。


## 9. 三级知识评级与 AI 调用

知识可信度统一使用低/中/高三级，具体标准见 [三级知识评级与AI调用规范](./三级知识评级与AI调用规范-V1.md)，当前已审计条目见 [知识资产评级登记表](./知识资产评级登记表-V1.json)。

- 高：在明确适用范围内有可核验结果和复核，默认优先调用。
- 中：多源支持或方法可复现，但目标工作流实测尚不充分，作为优先候选。
- 低：线索、推断、规则草案或未执行测试，仅用于探索。
- 评级对象是具体知识条目，不给整个领域或整个 Skill 一刀切评级。
- 低级不得覆盖高级；当前剧本事实、用户硬约束和参考素材事实优先于通用规则。
- 静态 CI 通过只证明其覆盖的静态合同，不代表真实图像/视频生成质量通过。
- 未登记的资料不得默认视为高级；首次调用前按评级规范评估。

剧本制作统一按 [剧本预演与分镜创作调用清单](./剧本预演与分镜创作调用清单-V1.md) 执行：剧本事实锁定 → 评级知识检索 → 场景/人物预演 → 导演预演 → 正式分镜 → 独立自检 → 分级证据报告。
