# 专业漫画制作外部项目与技能研究

研究日期：2026-11-02  
研究对象：欧美彩色漫画、网漫、漫画去字修复、对白排字、分页出版  
目的：为 AIGC 仓库补齐真正的漫画生产能力，不把影视分镜或漫剧技能直接冒充漫画专业技能。

## 一、研究结论

漫画生产至少需要以下独立专业能力：
1. 漫画叙事与脚本：页/屏节奏、悬念、对白密度、翻页钩子。
2. 漫画分格与页面设计：格数、格框、出血、跨格、阅读方向、视线流。
3. 角色资产与连续性：角色母版、服装版本、表情、身高关系、伤势/道具/状态时间线。
4. 场景与道具连续性：场景固定拓扑、机位、光线、时间、道具状态。
5. 单格绘制与局部返工：单格比例、构图锁定、参考图、候选版本、差异比较。
6. 漫画去字与底图修复：文字检测、气泡/文字遮罩、局部补画、人工修复、伪影检查。
7. 漫画排字：对白/旁白/拟声词独立矢量层，气泡形状、尾巴、阅读顺序、字体与字号。
8. 页面合成与出版：网漫长条、印刷分页、PDF/CBZ/EPUB、分辨率、色彩、出血、安全区、字体嵌入。
9. 独立质检：逐格对剧本、角色母版、场景状态、文字、阅读顺序和出版规格验收。

现有 AIGC 的导演、场景真实性、人物站位和运镜技能可作为上游能力，但不覆盖漫画页面语法、气泡排字、漫画去字和出版 preflight（印前检查）。因此新增独立漫画生产 Skill，不覆盖现有影视/漫剧技能。

## 二、外部项目审查

### 1. OpenManga
- 地址：https://github.com/pr0h0/OpenManga
- 许可证：Apache-2.0（GitHub 仓库元数据）。
- 研究价值：角色圣经、角色参考图审批/锁定/废止版本、服装版本切换、世界/地点/道具参考、逐角色状态时间线、跨章节连续性检查、逐格规格、面板版本、局部遮罩编辑、页面排版、气泡、脸部识别与气泡避让、PDF/CBZ/EPUB/网漫导出。
- 采纳：角色/服装版本与状态时间线；固定规则 pass/warn/fail；单格版本与回滚；排字和图像分离；导出前健康检查。
- 风险：需要用户自备模型服务/密钥；成本文档中的价格和测量会过期；项目自述的能力不等于本机已实测。
- 级别：高（架构方法）；运行状态未验证。
- 来源：README、docs/COSTS.md、docs/EXTENDING.md、LICENSE。

### 2. agent-comic-kit
- 地址：https://github.com/Saeyeon-developer/agent-comic-kit
- 许可证：Apache-2.0。
- 研究价值：AI Agent Skill + Python CLI；先生成角色表并人工批准，角色表附着到每页；脚本逐格定义镜头、人物、动作、背景、气泡留白、权重和对白；页面生成后拆格，逐格对照脚本与角色表审核；坏格只重绘该格；气泡由程序绘制，文本可编辑；输出目标比例和社交媒体规格。
- 采纳：未批准角色表不得进入正式页面；用户锁定的构图/角度/表情字段不可被模型改写；每次只修一个明确缺陷；同一问题两次失败后停止循环并升级人工决策；气泡与文字由排版程序绘制而非生图模型。
- 限制：仓库当前版本 v0.1；README 标明当前布局偏向纵向堆叠，网格布局仍在路线图；默认图像中继依赖 Windows Codex 桌面环境。
- 级别：高（工作流方法）；工具实测未执行。
- 来源：README.md、SKILL.md、LICENSE。

### 3. manga-text-removal
- 地址：https://github.com/Arybil/manga-text-removal
- 许可证：MIT（README 声明；需发布前复核 LICENSE 文件）。
- 研究价值：CTD（漫画文字检测）+ LaMa（图像补全）生成文字掩码并修复；另有 Tesseract OCR 方案及 PanelCleaner 气泡方案；支持 CLI/FastAPI；强调 OCR 而非单靠视觉模型确认残留文字。
- 采纳：检测器生成掩码→膨胀边缘→局部补全→保持原始尺寸→OCR 残留检查→人工检查纹理/结构伪影；对复杂人物/建筑背景必须局部人工修复，不能无条件自动擦除。
- 限制：仓库报告的 0 残字和伪影百分比是作者自测数据，不是本项目独立复测；CPU/GPU、模型下载、依赖版本可能造成环境差异。
- 级别：高（技术路线）；质量指标待独立复现。
- 来源：README.md、SKILL.md。

### 4. Comic Pipeline
- 地址：https://github.com/adachi0130/comic-pipeline
- 许可证：GPL-3.0-only。
- 研究价值：大纲/正文→AI 分镜→逐格提示词→ComfyUI→候选比较→页面编辑；版本化产物 lineage（血缘）与下游失效追踪；69 个布局模板；气泡、网点、速度线；PDF/CBZ 导出；安全路径隔离与回归测试。
- 采纳：生产产物必须有来源和版本；上游修改仅使相关下游失效；单格候选不覆盖已批准版本；页面模板与脚本可编辑；导出中心统一管理。
- 限制：GPL-3.0-only 有强 copyleft（著佐权）义务。若复制、修改或组合其受许可代码形成衍生作品并分发，需法务评估；本仓库仅记录方法，不复制代码。
- 级别：高（工程架构）；本机运行未验证。
- 来源：README.md、LICENSE。

### 5. Manga Editor Desu
- 地址：https://github.com/new-sankaku/manga-editor-desu
- 许可证：GPL-3.0（GitHub 仓库元数据）。
- 研究价值：本地浏览器漫画页面编辑；格框模板、对白气泡、竖排文字、网点、图层、字体和印刷分辨率导出。
- 采纳：页面编辑器应具备可编辑格框/气泡/文字层、阅读顺序、字体与印前输出；不让图像生成模型直接烘焙对白。
- 限制：GPL-3.0 需注意衍生代码分发义务；功能数量以仓库当前版本为准。
- 级别：高（排版专业参考）；本机运行未验证。
- 来源：项目 README/官方项目页与 GitHub 元数据。

### 6. Sloom Studio
- 地址：https://github.com/Es00bac/sloom-studio
- 许可证：GPL-3.0-or-later（项目说明）。
- 研究价值：同一项目文件内整合分层图像编辑与漫画/书籍页面；气泡尾巴、漫画拟声词、文字排版、CMYK、PDF/X、CBZ 等。
- 采纳：图像编辑和出版排版应共享项目资产，但保持图层独立；正式印刷需 CMYK、出血、字体和 PDF/X 检查。
- 限制：项目较新、单人维护；不能仅凭功能列表认定生产稳定性。
- 级别：中（有价值的集成方向，稳定性待验证）。
- 来源：README、项目网站、LICENSE。

## 三、证据等级

- 高：能读取到实际源码/Skill/文档，专业流程明确且可转化为可执行规则；不等于本机运行已通过。
- 中：功能方向有用，但维护、版本、测试或可复现性证据不足。
- 低：仅有宣传/概念，或许可证/源码身份不清晰。
- 所有外部项目的许可证仅适用于其代码/文档，不自动授予其示例图片、角色、模型、字体或训练数据的商业使用权。

## 四、对 MOONKEEP 的直接改造

1. 禁止用整页生图替代用户锁定的原画修复。
2. 原画、分格裁切、文字遮罩、修复候选、批准底图、排字层分别存储。
3. 角色表、服装、发型、伤势、诅咒、道具、场景空间作为锁定事实。
4. 去字前先检测和人工复核掩码；保护脸、手、服装关键纹理、诅咒和场景锚点。
5. 自动补全只产生候选；必须 OCR 残字检查、结构伪影检查和人工批准。
6. 对白必须独立存储为可编辑文字层，气泡位置、宽度、尾巴和阅读顺序可编辑。
7. 网漫长条与印刷分页分别排版，不允许简单裁切冒充正式分页。
8. 每格有版本、来源、修复记录和 SHA-256；失败不覆盖原图。
9. 发布前核对字体、素材授权、AI 披露、平台尺寸和印前规格。
10. 不将软件项目的 GPL 代码复制进用户商业仓库；优先通过独立运行、文件交换或松耦合接口使用。

## 五、下一轮验证计划

- 第一优先：用 manga-text-removal 在一张用户授权的测试画格上验证文字检测、掩码覆盖、LaMa 补全、OCR 和伪影率。
- 第二优先：用 agent-comic-kit 的流程规则构建一个本地测试项目，验证角色批准、逐格返工、独立排字与导出。
- 第三优先：比较 OpenManga 的角色状态/连续性架构与现有 AIGC SCG 事实合同，避免重复数据结构。
- 第四优先：评估 Manga Editor Desu / Sloom Studio 作为独立排版软件，不复制其 GPL 代码。
- 任何未运行的测试标记 NOT_RUN；任何自述指标标记 SELF_REPORTED。
