## 1. 核心结论

当前仓库并不缺少“分镜导演”。缺少的是将已经批准的镜头序列转换成**可检查、可返工、可重新合成的视觉分镜板**的生产层。

因此不应新建第二套导演/分镜规则，也不应把 SCG（场景连续性图谱）复制成另一份镜头事实账本。

建议增加一个边界明确的模块：

- 输入：现有分镜导演输出、SCG 镜头状态、已批准人物/场景/道具参考。
- 负责：宫格版式选择、逐格图像任务编译、参考图绑定、镜头编号/时间码、逐格质检、联系表合成。
- 不负责：改写剧情、重排人物世界坐标、重建场景事实、擅自设计新镜头、覆盖 SCG。
- 默认图像后端：GPT 原生生图；第三方模型或本地 FLUX 仅作为明确可选实验。
- 正式输出：独立画格原图、完整宫格板、镜头清单/提示词档案、质检结果。图像内不放进度条、宣传文案或无关装饰。

**关键生产原则：镜头事实先锁定；每格独立生成；所有画格引用同一批准母版；排版器只负责合成与标注；失败只返工对应格。**

### 3.3 Story2Board：学术方法与源码审查

论文：<https://doi.org/10.1111/cgf.70319>  
预印本：<https://arxiv.org/abs/2508.09983>  
官方代码：<https://github.com/DavidDinkevich/Story2Board/tree/92ef11077c3a596a32241e434b0c527ec54f2546>  
代码提交：`92ef11077c3a596a32241e434b0c527ec54f2546`  
许可证：MIT  
论文：2025-08-13 发布预印本；期刊 Early View 于 2026-04-08 首次发表。

方法：
- Latent Panel Anchoring（潜在分镜锚定）：每格共享同一角色/参考画格锚点。
- Reciprocal Attention Value Mixing（双向注意力值混合）：在扩散模型内部对强互相关联的视觉特征进行有限混合。
- 由语言模型先生成共享参考提示词和每格独立提示词，再由扩散模型逐批生成。

源码审查结果：
- 主入口加载 `black-forest-labs/FLUX.1-dev`，并使用自定义 Transformer、Attention Processor 与 Pipeline。
- 官方 README 指定 Linux、Python 3.12、CUDA 12.x 为官方支持环境；Windows/macOS 仅提供“可尝试”的替代依赖文件。
- 该实现需要直接控制扩散模型内部 latent/attention，不是普通图片 API 的提示词层功能。
- 主入口在生成器中固定创建 `torch.Generator("cuda")`，即使后续 device 参数回退到 CPU，CPU 分支也存在潜在不兼容风险；该分支本轮未运行验证。
- 论文讨论了 attention entanglement 等限制；多角色场景（例如超过两个主要角色）可能需要额外提示工程，不能将其视为复杂多人分镜的通用解法。

适配判断：**只采纳“共享锚点 + 画面多样性分开衡量”的设计思想，不接入其模型代码**。GPT 原生生图是封闭式宿主接口，当前没有权限访问其 latent、Q/K/V 或 Transformer block；因此不能直接实现 LPA/RAVM，也不能声称已将论文算法用于 GPT Image。

采纳等级：**中（学术方法参考）**；代码适配 GPT 原生生图：**不适用/未实现**。

## 5. 建议的目标架构

新建的应是一个视觉生产模块，而不是新导演技能。建议暂定名：`storyboard-contact-sheet-cn`（中文：多宫格视觉分镜板）。

### 5.1 输入合同

只接收现有权威数据的引用和派生镜头提示，不创建第二套世界状态：
- `source_script_ref`：原剧本来源。
- `scene_id` / `shot_id`：现有场景与镜头稳定 ID。
- `scg_state_ref`：现有 SCG 的镜头状态引用。
- `character_asset_refs[]`：已批准人物母版。
- `scene_asset_ref`：已批准场景参考。
- `prop_asset_refs[]`：已批准道具参考。
- `panel_layout`：2×2、3×3、3×4/4×3、5×5。
- `panel_image_ratio`：按最终媒介确定，不能默认所有漫画、广告和影视镜头都使用同一比例。
- `label_policy`：编号/时间码/镜头说明是否显示；不允许生成进度条、宣传语或无关装饰。

### 5.2 逐格生产

每格提示词由三部分组成：
1. **共享锁定段**：角色外观、服装、场景拓扑、道具外观、时间/光照、风格基线。对同一场景保持原文一致。
2. **本格变化段**：景别、机位、人物可见动作、构图、焦点、画面左右关系和镜头新增信息。
3. **否决段**：不得改变人物身份、服装、道具、场景固定结构、世界坐标、轴线与用户锁定事实；禁止新增人物/家具/门窗；禁止无关文字与装饰。

所有画格都引用同一批准母版。不得将上一格作为唯一参考，以免错误累积。需要持续动作时，额外使用 SCG 的上一镜 state_out 与下一镜 state_in 做连续性审核，但仍以原始批准母版和权威世界状态为锚点。

### 5.3 宫格版式

| 用户要求 | 默认布局 | 说明 |
|---|---|---|
| 4 格 | 2×2 | 起承转合/四镜概览；也可按镜头方向选择 1×4 |
| 9 格 | 3×3 | 短场景或广告节拍 |
| 12 格 | 3×4 或 4×3 | 根据最终板面方向和每格比例选择，不固定单一布局 |
| 25 格 | 5×5 | 复杂动作、多人交互、完整镜头覆盖；必须优先逐格生成 |

布局只是版面规则，不自动决定剧情。每格必须对应权威镜头清单，禁止为填满格子擅自新增剧情或重复镜头。

### 5.4 排版与文字

- 生成器只生产画格图像；程序只做缩放、裁切（按明确规则）、留白、编号、时间码和合成。
- 镜号和时间码由确定性程序添加，不能依赖图像模型正确拼写。
- 对白气泡、旁白、UI 数值和长说明默认放在独立排版层；除非用户明确要求漫画成品，否则分镜图不应自带复杂气泡。
- 每格原图必须保留；排版板是派生文件，不得覆盖画格原图。
- 5×5 的联系表缩略后可读性会下降，必须同时交付独立画格和可放大查看的板面；必要时按镜头段落再分组导出，不得缩小到看不清动作。

## 6. 25 格压力测试方案（尚未执行）

### 6.1 测试目标

验证 GPT 原生生图是否能在同一场景、同一人物、同一套服装和道具条件下，产出 25 个镜头不同、空间关系连续、动作状态不跳变的独立画格，并由程序合成为准确的 5×5 联系表。

### 6.2 固定测试场景

使用简单但有连续动作的室内场景，避免同时引入复杂群演、天气和大规模特效。优先使用已批准的人物/场景资产；若没有批准资产，使用纯测试角色并明确标记为测试，不写入正式角色母版。

### 6.3 25 镜覆盖分组

- 01–05：建立空间、人物入场、方向关系。
- 06–10：人物与关键道具交互，动作开始。
- 11–15：动作持续、状态变化、反应镜头。
- 16–20：冲突升级、遮挡与不同景别覆盖。
- 21–25：动作完成、结果确认、情绪/剧情落点。

具体镜头必须来自测试脚本；以上分组仅为覆盖结构，不是自动补造剧情的许可。

### 6.4 对照组

- A 组：一次性生成 5×5 完整宫格。
- B 组：25 格逐格生成，统一引用批准母版，之后自动排版。
- 两组使用同一剧本、角色参考、场景事实、镜头清单、风格和图像比例。
- 不同时改变提示词策略、镜头内容、模型和参考图数量；否则无法归因。
- 不得把 A 组的 25 格与 B 组的 25 张独立图混为相同预算；记录调用次数、失败率、返工数和实际耗时。

### 6.5 评分维度

| 维度 | 主要检查 |
|---|---|
| 格数与顺序 | 25/25、无缺号、无重复号、阅读顺序正确 |
| 人物身份 | 面部、发型、体型、服装、配饰稳定 |
| 场景拓扑 | 门窗、家具、出入口、固定物件和方向关系稳定 |
| 道具连续性 | 尺寸、颜色、持有人、损坏/变化状态有来源 |
| 动作连续性 | 起始/结束状态衔接，不瞬移、不跳过必要动作 |
| 镜头多样性 | 景别、机位、构图和信息增量不同，不重复肖像 |
| 摄影连续性 | 轴线、画面左右、视线方向和机位关系不无故翻转 |
| 画面可读性 | 缩略图仍能辨认动作主体与关键道具 |
| 可返工性 | 单格失败能独立重做，其他格和镜头事实不变 |
| 合成准确性 | 排版器输出与镜头清单、编号、时间码完全一致 |

验收不只看平均分。人物身份、场景拓扑、道具归属、动作连续性或镜头顺序任何一项出现 P0 级错误，都不能将整组标为通过。

### 6.6 失败归因

- **生成失败**：角色漂移、场景变形、动作错位、构图不可读。
- **提示词编译失败**：共享锁定段遗漏、变化段含糊、互相冲突。
- **数据交接失败**：SCG 引用丢失、镜头 ID 不一致、状态字段来源不明。
- **排版失败**：编号错误、缺图、顺序错误、比例不符、标签遮挡。
- **验收失败**：只检查总图，未逐格检查；只检查角色，不检查场景/道具/轴线。

## 7. 采纳决策

### 立即采纳为设计约束（中级候选）

1. 逐格生成是正式生产默认路线；整图一次性生成只用于草稿/快速构图探索。
2. 每格引用同一批准人物/场景母版；不串联上一格作为唯一参考。
3. 镜头事实、人物状态和场景状态继续由现有 SCG/专业 Skill 管理。
4. 画格、编号、时间码和对白分层；文字不由图像模型承担最终准确性。
5. 自动合成必须读取权威镜头清单，按稳定 ID 排序，不按文件名字典序猜顺序。
6. 4/9/12/25 格布局作为版式选项；镜头数量由剧情覆盖和镜头信息量决定，不由时长阈值单独决定。
7. 逐格返工，保留原图、候选图、批准图和质检结果的血缘。

### 暂缓采纳

- Story2Board 的 LPA/RAVM：当前 GPT 原生图像接口无法访问模型内部 latent/attention。
- Scenario MCP 的具体 API：当前目标环境未连接该服务。
- 一次性 25 格大图直接作为正式生产：需先通过受控对照实验。
- 复制 Storyboard Generator 的 Python 脚本：上游未声明许可证。

### 不采纳

- 新建第二套人物/场景/道具世界状态账本。
- 仅按视频时长自动决定宫格数量。
- 让图像模型在同一张图中承担准确对白、复杂 UI 数值和全部编号。
- 用静态拼图、SVG 或程序画框冒充真实画格图像；程序只可用于后期排版与标签。
- 将 25 格一次性生成结果直接认定为 25 个有效镜头。

## 8. 后续实施顺序

1. 先建立模块的最小输入/输出合同和 4/9/12/25 布局测试夹具。
2. 编写确定性联系表排版器：数字自然排序、缺失/重复/多余文件阻断、比例检查、编号/时间码校验、保留源图。
3. 使用 GPT 原生生图进行 4 格小样，先验证人物母版、单格返工和排版链。
