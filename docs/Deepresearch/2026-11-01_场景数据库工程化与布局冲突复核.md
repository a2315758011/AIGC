## 发现并修正的内部空间冲突

复核原教室逻辑布局时发现：
- 中间桌列中心 x=0.50；
- 旧版却把“中央通道”设为 x=0.43..0.57；
- 这意味着通道直接穿过中间桌列中心，是明确的空间拓扑冲突。

已修正教室参考基准：
- 删除与中间桌列重叠的“中央通道”定义；
- 改为三列之间两条连续列间通道；
- 左右侧通行区域单独定义；
- 明确本样例是 3 列 × 5 排布局，不代表所有教室的通用标准；
- 真实桌椅占地宽度未知，因此通道净宽与规范合规性仍标记为未验证。

这项修正很重要：场景数据库不仅要保存模型生成的设定，还必须在写入前检查设定本身是否互相矛盾。

## 第三阶段：碰撞区域与镜头连续性校验（V1.8.0）

新增能力：
1. 场景数据库 Schema 增加 `footprint`（地面占地宽度/深度）和 `clearance_zones`（通道/操作净空区域）。
2. 教室实例为 30 个家具对象显式登记 `footprint: null`，并定义 4 个逻辑通行区域。由于真实桌椅尺寸未知，当前不执行或宣称真实碰撞/净空通过。
3. 场景校验器新增物体占地矩形互相重叠、占地侵入通道区域检查；对缺少 footprint 的可通行要求对象发出未验证警告。
4. 新增逐镜连续性校验器，检查 scene_id、shot_id、previous_shot_id、state_in 与上一镜 state_out 是否一致，以及状态变化是否有事件记录。
5. 新增正向样例与负向瞬移样例。

本轮静态逻辑回归（在工具执行环境中对已提交 JSON 执行同等比较逻辑）：
- 正向连续性样例：0 项连续性错误。
- 负向瞬移样例：检出 state_in 与上一镜 state_out 不一致，并检出状态变化缺少事件。
- 教室数据：15 张桌子、15 把椅子；30 个 footprint 均显式为 null；4 个通行区域。
- Schema 中 footprint/clearance_zones 字段存在；校验器包含物体重叠和通道侵入判定分支。

证据边界：
- 上述为本轮工具环境中的 JSON 结构和校验逻辑检查，不等同于在 Windows 工作站运行 Node.js 脚本。
- Node 校验器尚未在目标工作站执行；没有真实尺寸，因此教室碰撞与通道净宽仍未验证。
- 连续性校验器目前检查数据快照继承，不推断物理路径可行性；人物路径碰撞仍需对象占地数据与路径几何。
- 尚未接入正式分镜/剧本流水线，不能声称已在真实漫剧项目中自动生效。
