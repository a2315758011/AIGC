## 发现并修正的内部空间冲突

复核原教室逻辑布局时发现：
- 中间桌列中心 x=0.50；
- 旧版却把“中央通道”设为 x=0.43..0.57；
- 这意味着通道直接穿过中间桌列中心，是明确的空间拓扑冲突。

已修正教室参考基准：
- 删除与中间桌列重叠的“中央通道”定义；
- 改为三列之间两条连续列间通道；
- 左右侧通行区域单独定义；
- 明确本样例是 3 列 × 5 排布局，不代表所有教室的通用标准；
- 真实桌椅占地宽度未知，因此通道净宽与规范合规性仍标记为未验证。

这项修正很重要：场景数据库不仅要保存模型生成的设定，还必须在写入前检查设定本身是否互相矛盾。

## 第五阶段：三维代理碰撞与摄影机路径（2026-11-01）

### 本轮发现与架构修正

复核发现仓库原本已经有独立的长期场景空间数据库（固定事实、家具、占地、通行区、摄影机预设），上一轮 SCG 扩展若不明确职责，容易造成两套固定几何/动态状态数据源。本轮明确：
- 场景数据库负责固定建筑、家具、空间坐标和碰撞体积。
- SCG 负责逐镜实体、人物/道具动态关系、动作事件及相机运动。
- 场景数据库的 dynamic_state 仅作为兼容迁移/展示快照，不得与 SCG 同时成为动态状态权威来源。
- 新增场景对象 collision_volume（box）可选字段，要求底面中心锚定于 position。
- SCG 扩展新增 XYZ 坐标、人物 capsule 代理、摄影机 sphere 代理和独立相机路径约定。

### 本轮实际修改

- 新增 `references/SCG三维预演与碰撞检查扩展契约-V1.md`。
- 新增 `tests/validate-scg-3d-motion.cjs`，不依赖第三方库；支持从 SCG 读取路径事件，并可选读取场景数据库补充固定障碍。
- 新增 `tests/fixtures/SCG三维碰撞回归-V1.json`，包含人物正常地面路径、穿过桌子、越过低障碍、摄影机穿墙四种情况。
- 更新场景数据库 JSON Schema，明确 dynamic_state 权威边界并加入三维 box 碰撞体积字段。
- 更新场景真实性 Skill 与 SCG 扩展契约，接入三维预演调用门槛。

## 第六阶段：清除重复动态状态源（2026-11-01）

进一步审查场景数据库 schema、模板和校验器后，发现旧 schema 曾把 `dynamic_state` 设为必填，模板也预置了人物状态快照。这与 SCG 逐镜实体/关系/事件重复保存同一动态事实，存在双重权威风险。

本轮已处理：

- 场景数据库校验器不再要求该字段；旧数据若仍保留非空数组，会提示迁移到 SCG；错误类型仍会报错。
- README 中清理了一个经 GitHub 实际核对不存在的课堂项目路径，避免文档/锁文件把不存在的项目数据说成已交付。
- 场景真实性 Skill 升级至 V1.10.0，固定几何由场景数据库维护，动态镜头状态由 SCG 维护。

## 第七阶段：复用现有 DirectorDesk 三维导演台

本轮读取了用户工作站已安装 DirectorDesk 的本地 Skill 与 references，并核对以下能力：
- 三维世界坐标以米为单位、+Y 向上；摄影机位置 path 与 targetPath 分离。
- 支持场景几何、家具、人物白模、动作 clips、物理近似、static/dynamic/kinematic、碰撞与惯性。
- 内置自动避障仅覆盖同高度地面和静态障碍；不支持楼梯/攀爬/完整动态人群寻路。
- 空间查询可提供桌面、座面等 contactAnchors；物理/碰撞为简化近似，高速细物体可能穿透。

关键发现：AIGC 场景数据库约定 Z 轴为高度，而 DirectorDesk 约定 Y 轴向上。若不做显式转换，人物会被错误地放到错误高度/深度。本轮新增 `references/DirectorDesk三维白模预演适配规范-V1.md`，规定坐标轴映射、单位、原点、固定场景与 SCG 动态状态分工，以及 DirectorDesk 的适用边界。
