# 2026-11-02_漫剧粒子特效与系统UI可控制作Skill专项研究

研究日期：2026-11-02  
目标仓库：`a2315758011/AIGC`  
研究范围：外部 Agent Skill、动态视觉代码工作流、粒子系统、系统 UI/HUD、后期跟踪合成  
状态：研究记录；候选方案，不代表已安装、已接入或真实漫剧成片验收通过。

## 1. 研究结论

漫剧中的系统 UI、全息界面、粒子和魔法/战斗特效，不应全部交给单次 AI 生图或单条文生视频提示词完成。建议将制作拆成可独立修改的层：

1. **内容/数据层**：剧情事件、面板文案、数值、图标 ID、特效触发条件。
2. **界面结构层**：SVG/HTML/JSX/React 组件，文字、边框、按钮、属性条、图标和面板布局。
3. **动画/粒子层**：关键帧、时间函数、粒子发射、扫描线、流光、能量轨迹、噪声和着色器。
4. **空间合成层**：人物/手部跟踪、透视、遮罩、前后景遮挡、光照/色彩/运动模糊匹配。
5. **镜头连续性层**：同一 UI/特效稳定 ID、跨镜位置/颜色/尺寸/状态、镜头内触发时刻。
6. **验收层**：文字准确、边缘无抖动、跟踪无漂移、遮挡正确、动画可逐帧复现、音画同步。

核心决策：**界面主体用程序化可编辑图层；特效用粒子/着色器/矢量动画；与人物和环境融合用后期跟踪合成；剧本状态负责驱动所有图层。**

不建议将复杂系统界面作为一张完整生成图片：AI 图片中的文字、数值、图标数量、排版和跨镜状态不可可靠编辑。生成图可作为风格参考或局部材质，不作为文字与数值真值。

### 3.1 Motion Graphics Skills — 优先复现

来源：Mort1d/motion-graphics-skills  
固定来源：`7f0c3714dc81bea52644a5287c6350345009e579`  
技能文件：<https://github.com/Mort1d/motion-graphics-skills/blob/7f0c3714dc81bea52644a5287c6350345009e579/skills/motion-graphics/SKILL.md>  
许可证：该版本仓库 LICENSE 明确为 MIT；仓库说明其模板字体另受 SIL OFL 1.1 管理，字体许可不能与 Skill 代码许可混为一谈。  
依赖：Node.js 22.4+、FFmpeg/ffprobe、Chrome/Edge/Chromium/Brave；无 npm 包/API key 的基本渲染路线。

可借鉴能力：
- HTML 场景逐帧渲染，画面由时间参数决定。
- 真实子帧运动模糊。
- 参考视频节奏分析、关键帧/时间条提取、技术拆解。
- 先做关键静帧，再逐场制作；渲染后复核、评分、返工。
- 交付可重渲染工程，而非只有 MP4。

适配判断：**高**。非常适合系统弹窗、技能图标动画、属性升级、数据面板、标题/提示条、魔法阵图形等可编程二维动态图形。它是宣传/动态设计流程，不是专门的粒子模拟器或角色遮罩工具。先借鉴确定性时间轴、帧级渲染和审片流程，不应整套照搬其音乐/品牌营销流程。

### 3.2 UI Animation — 系统 UI 动效候选

上游：mblode/agent-skills，来源快照可由 <https://github.com/nexu-io/open-design/blob/5a0c47777975ddb91d09c1c16b423a3ef74bf572/skills/ui-animation/SKILL.md> 核查。  
许可证：镜像中的来源记录明确标记 MIT，并给出上游仓库和 commit；正式采纳前仍应回到上游固定 commit 核对完整 LICENSE 和文件。  
能力：缓动/弹簧、拖拽/手势、SVG 动画、路径变形、文字/图标动效、界面声音、录屏抽帧/跟踪/曲线拟合、动效代码审查。

适配判断：**高**。可用于系统 UI 的开合、卡片展开、数值跳变、进度条、通知、技能槽、标签切换和状态反馈。它主要处理 UI 组件动效，不负责全息投影空间合成，也不负责大规模粒子模拟。

重要规则：
- 让持续存在的组件在状态变化时连续移动，避免旧界面消失、新界面突然出现。
- 动画应服务于反馈、方向感和连续性，不能为了“炫”而给所有元素加动效。
- 高频界面反馈应短而明确。
- 动效需要成对设计（打开/关闭、进入/退出）。
- 录屏测量结果与肉眼估计必须区分。

## 5. 推荐技术组合

### 路线 A：低成本二维漫剧（优先）
- 界面：现有 ChatCut Motion Graphics，使用 JSX/SVG 组件。
- UI 动效：吸收 UI Animation 的缓动、弹簧、状态连续性原则。
- 粒子：先用可控 2D 粒子素材/Canvas 或程序化矢量粒子，暴露颜色、数量、速度、寿命、发射方向、随机种子等参数。
- 合成：有人物遮挡、跟随和透视需求时再进入 AE/现有视频合成工具。
- 输出：透明背景/Alpha 视频或分层素材（具体能力需在目标工具实测）。

### 路线 B：程序化可重复的 UI/VFX 视频
- 使用 Remotion 或 Mort1d 的 HTML 逐帧渲染思路。
- 所有动画由帧号/时间参数驱动。
- 同一效果通过 JSON 参数复用。
- 逐帧可重现，适合自动化回归和镜头复用。
- 不与 ChatCut 重复建设：先对现有 ChatCut 能力做实际验证，缺失时再引入替代渲染器。

### 路线 C：复杂三维空间特效
- 需要 3D 粒子、人物/武器挂接和真实空间透视时，评估 Niagara。
- 需要 UI 与实拍/AI 视频人物融合时，采用跟踪、遮罩、Corner Pin、光照匹配与颗粒统一。
- 不为普通弹窗或数值升级镜头引入完整 UE 工程。

## 6. 系统 UI 数据合同建议

以下为待实现的建议字段，不是已发布的权威 SCG schema。正式接入前必须与当前 SCG/共享事实规范对齐，避免平行数据合同。

```json
{
  "effect_id": "SYS_UI_001",
  "effect_type": "holographic_panel",
  "owner_entity_id": "CHARACTER_01",
  "anchor_id": "RIGHT_HAND_PALM",
  "screen_or_world_space": "world",
  "transform": {
    "position": [0.0, 0.0, 0.0],
    "rotation": [0.0, 0.0, 0.0],
    "scale": [1.0, 1.0, 1.0]
  },
  "style_id": "SYSTEM_BLUE_01",
  "content_ref": "CHARACTER_STATUS_01",
  "animation_state": "opening",
  "trigger_event_id": "EVT_SYSTEM_AWAKEN",
  "visible_from_frame": 24,
  "hidden_after_frame": 156,
  "occlusion_policy": "character_foreground_matte",
  "continuity_group": "SCENE_01_SYSTEM_UI"
}
```

建议可控参数至少包括：
- 几何：位置、旋转、缩放、透视角、锚点、屏幕/世界空间。
- 外观：主色、辅色、透明度、发光强度、线宽、圆角、字体、图标集。
- 内容：标题、数值、单位、标签、排序、文本方向。
- 动画：进入/退出、持续时间、延迟、缓动、循环、暂停/恢复。
- 粒子：数量、速率、速度范围、方向、扩散角、寿命、尺寸、颜色、重力、噪声、随机种子。
- 合成：人物遮挡层、前后景顺序、阴影、光照包裹、模糊、颗粒。
- 连续性：稳定 ID、跨镜位置、内容状态、颜色、尺度、触发事件、结束状态。

## 7. 必须建立的验收用例

1. **文字准确性**：中英文、数字、单位、标点与源数据逐字一致；不得让生图模型负责最终文字。
2. **布局稳定性**：不同画幅/安全区下不裁切，不遮挡对白、脸部、手部和关键动作。
3. **时间确定性**：同一帧重复渲染结果一致；跳帧、倒放、随机抽帧无状态漂移。
4. **粒子可控性**：同一参数能复现；更改颜色/密度/速度/寿命只影响对应效果。
5. **空间绑定**：跟随锚点不漂移；透视变化合理；遮挡顺序正确。
6. **镜头连续性**：同一 effect_id 跨镜结构、风格、数值状态连续；剧情触发/关闭时点正确。
7. **合成融合**：边缘、黑位、色温、光向、运动模糊、景深和颗粒匹配背景。
8. **画面可读性**：主视觉重点清晰；粒子不遮住 UI 文字、人物表情、命中点或剧情证据。
9. **声音同步**：点击/确认/升级/警告/能量触发音效与画面事件对齐。
10. **交付完整性**：保留工程源文件、可编辑参数、素材依赖、字体许可和可重渲染说明。

## 11. 第二轮深读：工程化能力与关键限制

### 11.1 Mort1d Motion Graphics 的真实强项

已进一步读取固定版本的 `references/pipeline.md`、`scripts/new-project.mjs` 和相关目录结构。

额外确认：
- 项目把 `timeline.mjs`（画幅、FPS、时长、场景窗口、节拍和事件 cue）、`copy.mjs`（全部文案）与场景代码分离。
- 每个场景按 `build(ctx) → (t, frame) => void` 方式绘制，要求所有像素由时间/帧驱动。
- 具备联系表、逐帧静帧、快速运动条、倒序/乱序渲染一致性检查、黑帧/冻结帧/闪帧/文字出界/语言错误等 QA。
- 支持局部时间范围重渲染，避免改一处就全片重做。
- 可以导出时间线 JSON 给 Remotion、HyperFrames 或传统剪辑器继续使用。
- `new-project.mjs` 对已有文件采取保留策略，默认不覆盖。

**重要限制：** 该技能的标准交付明确是 H.264 MP4 和 AAC 音频，不是透明 Alpha 合成素材包。它可以产出可编辑的程序化 UI 动态画面和帧序列，但本轮没有证据证明其默认流程能直接导出透明背景视频。因此不能把它当成“透明特效叠加层导出器”。若采用，需单独验证透明 PNG 序列/ProRes 4444 或其他透明通道路线，未验证前不计入可用能力。

### 11.4 系统 UI 生产最合适的职责拆分

- 文字/数值真值：剧情/SCG 数据，不交给图像生成模型。
- 面板结构：现有 ChatCut Motion Graphics 的 JSX 组件优先；SVG 负责清晰边框、图标和路径。
- 界面动画：参考 UI Animation 的缓动、弹簧、开合、连续性和逐帧测量原则。
- 粒子：少量 2D 粒子用程序化 Canvas/SVG/现有素材即可；复杂 3D 粒子才考虑 Niagara。
- 光效：着色器负责扫描、流光、溶解、扭曲等材质变化。
- 人物融合：跟踪、遮罩、透视、前景人物遮挡、光照与颗粒匹配；优先检查现有工具能否做，AE 是候选不是前提。
- 成片渲染：优先沿用现有 ChatCut 时间线；只有其能力无法满足确定性/透明通道/帧级 QA 时才引入独立渲染器。

### 11.5 最小原型的测试矩阵

第一轮不做整套特效库。只做一个镜头来证明控制链：
- 人物抬起右手，掌心上方出现一张系统属性面板。
- 面板中文字、数值和图标全部为独立真实图层。
- 面板按事件时间打开；数值从旧值滚动到新值。
- 边框按 SVG 路径绘制；扫描线和小粒子单独开关。
- 人物手掌/手指前景遮挡面板的一部分，不能让 UI 穿过手掌。
- 镜头轻微移动时面板跟随掌心锚点，透视和遮挡稳定。
- 同镜头导出首帧/峰值帧/尾帧；重复渲染比对像素或容差，检查时间确定性。

原型通过标准：中文无错字、数值精确、跟踪无明显漂移、遮挡正确、UI 不遮脸和对白、动画开合完整、粒子不遮住关键信息、重复渲染稳定。只完成代码或静态预览不算真实镜头通过。
