# 2026-11-02_漫剧粒子特效与系统UI可控制作Skill专项研究

研究日期：2026-11-02  
目标仓库：`a2315758011/AIGC`  
研究范围：外部 Agent Skill、动态视觉代码工作流、粒子系统、系统 UI/HUD、后期跟踪合成  
状态：研究记录；候选方案，不代表已安装、已接入或真实漫剧成片验收通过。

## 1. 研究结论

漫剧中的系统 UI、全息界面、粒子和魔法/战斗特效，不应全部交给单次 AI 生图或单条文生视频提示词完成。建议将制作拆成可独立修改的层：

1. **内容/数据层**：剧情事件、面板文案、数值、图标 ID、特效触发条件。
2. **界面结构层**：SVG/HTML/JSX/React 组件，文字、边框、按钮、属性条、图标和面板布局。
3. **动画/粒子层**：关键帧、时间函数、粒子发射、扫描线、流光、能量轨迹、噪声和着色器。
4. **空间合成层**：人物/手部跟踪、透视、遮罩、前后景遮挡、光照/色彩/运动模糊匹配。
5. **镜头连续性层**：同一 UI/特效稳定 ID、跨镜位置/颜色/尺寸/状态、镜头内触发时刻。
6. **验收层**：文字准确、边缘无抖动、跟踪无漂移、遮挡正确、动画可逐帧复现、音画同步。

核心决策：**界面主体用程序化可编辑图层；特效用粒子/着色器/矢量动画；与人物和环境融合用后期跟踪合成；剧本状态负责驱动所有图层。**

不建议将复杂系统界面作为一张完整生成图片：AI 图片中的文字、数值、图标数量、排版和跨镜状态不可可靠编辑。生成图可作为风格参考或局部材质，不作为文字与数值真值。

### 3.1 Motion Graphics Skills — 优先复现

来源：Mort1d/motion-graphics-skills  
固定来源：`7f0c3714dc81bea52644a5287c6350345009e579`  
技能文件：<https://github.com/Mort1d/motion-graphics-skills/blob/7f0c3714dc81bea52644a5287c6350345009e579/skills/motion-graphics/SKILL.md>  
许可证：该版本仓库 LICENSE 明确为 MIT；仓库说明其模板字体另受 SIL OFL 1.1 管理，字体许可不能与 Skill 代码许可混为一谈。  
依赖：Node.js 22.4+、FFmpeg/ffprobe、Chrome/Edge/Chromium/Brave；无 npm 包/API key 的基本渲染路线。

可借鉴能力：
- HTML 场景逐帧渲染，画面由时间参数决定。
- 真实子帧运动模糊。
- 参考视频节奏分析、关键帧/时间条提取、技术拆解。
- 先做关键静帧，再逐场制作；渲染后复核、评分、返工。
- 交付可重渲染工程，而非只有 MP4。

适配判断：**高**。非常适合系统弹窗、技能图标动画、属性升级、数据面板、标题/提示条、魔法阵图形等可编程二维动态图形。它是宣传/动态设计流程，不是专门的粒子模拟器或角色遮罩工具。先借鉴确定性时间轴、帧级渲染和审片流程，不应整套照搬其音乐/品牌营销流程。

### 3.2 UI Animation — 系统 UI 动效候选

上游：mblode/agent-skills，来源快照可由 <https://github.com/nexu-io/open-design/blob/5a0c47777975ddb91d09c1c16b423a3ef74bf572/skills/ui-animation/SKILL.md> 核查。  
许可证：镜像中的来源记录明确标记 MIT，并给出上游仓库和 commit；正式采纳前仍应回到上游固定 commit 核对完整 LICENSE 和文件。  
能力：缓动/弹簧、拖拽/手势、SVG 动画、路径变形、文字/图标动效、界面声音、录屏抽帧/跟踪/曲线拟合、动效代码审查。

适配判断：**高**。可用于系统 UI 的开合、卡片展开、数值跳变、进度条、通知、技能槽、标签切换和状态反馈。它主要处理 UI 组件动效，不负责全息投影空间合成，也不负责大规模粒子模拟。

重要规则：
- 让持续存在的组件在状态变化时连续移动，避免旧界面消失、新界面突然出现。
- 动画应服务于反馈、方向感和连续性，不能为了“炫”而给所有元素加动效。
- 高频界面反馈应短而明确。
- 动效需要成对设计（打开/关闭、进入/退出）。
- 录屏测量结果与肉眼估计必须区分。

## 5. 推荐技术组合

### 路线 A：低成本二维漫剧（优先）
- 界面：现有 ChatCut Motion Graphics，使用 JSX/SVG 组件。
- UI 动效：吸收 UI Animation 的缓动、弹簧、状态连续性原则。
- 粒子：先用可控 2D 粒子素材/Canvas 或程序化矢量粒子，暴露颜色、数量、速度、寿命、发射方向、随机种子等参数。
- 合成：有人物遮挡、跟随和透视需求时再进入 AE/现有视频合成工具。
- 输出：透明背景/Alpha 视频或分层素材（具体能力需在目标工具实测）。

### 路线 B：程序化可重复的 UI/VFX 视频
- 使用 Remotion 或 Mort1d 的 HTML 逐帧渲染思路。
- 所有动画由帧号/时间参数驱动。
- 同一效果通过 JSON 参数复用。
- 逐帧可重现，适合自动化回归和镜头复用。
- 不与 ChatCut 重复建设：先对现有 ChatCut 能力做实际验证，缺失时再引入替代渲染器。

### 路线 C：复杂三维空间特效
- 需要 3D 粒子、人物/武器挂接和真实空间透视时，评估 Niagara。
- 需要 UI 与实拍/AI 视频人物融合时，采用跟踪、遮罩、Corner Pin、光照匹配与颗粒统一。
- 不为普通弹窗或数值升级镜头引入完整 UE 工程。

## 6. 系统 UI 数据合同建议

以下为待实现的建议字段，不是已发布的权威 SCG schema。正式接入前必须与当前 SCG/共享事实规范对齐，避免平行数据合同。

```json
{
  "effect_id": "SYS_UI_001",
  "effect_type": "holographic_panel",
  "owner_entity_id": "CHARACTER_01",
  "anchor_id": "RIGHT_HAND_PALM",
  "screen_or_world_space": "world",
  "transform": {
    "position": [0.0, 0.0, 0.0],
    "rotation": [0.0, 0.0, 0.0],
    "scale": [1.0, 1.0, 1.0]
  },
  "style_id": "SYSTEM_BLUE_01",
  "content_ref": "CHARACTER_STATUS_01",
  "animation_state": "opening",
  "trigger_event_id": "EVT_SYSTEM_AWAKEN",
  "visible_from_frame": 24,
  "hidden_after_frame": 156,
  "occlusion_policy": "character_foreground_matte",
  "continuity_group": "SCENE_01_SYSTEM_UI"
}
```

建议可控参数至少包括：
- 几何：位置、旋转、缩放、透视角、锚点、屏幕/世界空间。
- 外观：主色、辅色、透明度、发光强度、线宽、圆角、字体、图标集。
- 内容：标题、数值、单位、标签、排序、文本方向。
- 动画：进入/退出、持续时间、延迟、缓动、循环、暂停/恢复。
- 粒子：数量、速率、速度范围、方向、扩散角、寿命、尺寸、颜色、重力、噪声、随机种子。
- 合成：人物遮挡层、前后景顺序、阴影、光照包裹、模糊、颗粒。
- 连续性：稳定 ID、跨镜位置、内容状态、颜色、尺度、触发事件、结束状态。

## 7. 必须建立的验收用例

1. **文字准确性**：中英文、数字、单位、标点与源数据逐字一致；不得让生图模型负责最终文字。
2. **布局稳定性**：不同画幅/安全区下不裁切，不遮挡对白、脸部、手部和关键动作。
3. **时间确定性**：同一帧重复渲染结果一致；跳帧、倒放、随机抽帧无状态漂移。
4. **粒子可控性**：同一参数能复现；更改颜色/密度/速度/寿命只影响对应效果。
5. **空间绑定**：跟随锚点不漂移；透视变化合理；遮挡顺序正确。
6. **镜头连续性**：同一 effect_id 跨镜结构、风格、数值状态连续；剧情触发/关闭时点正确。
7. **合成融合**：边缘、黑位、色温、光向、运动模糊、景深和颗粒匹配背景。
8. **画面可读性**：主视觉重点清晰；粒子不遮住 UI 文字、人物表情、命中点或剧情证据。
9. **声音同步**：点击/确认/升级/警告/能量触发音效与画面事件对齐。
10. **交付完整性**：保留工程源文件、可编辑参数、素材依赖、字体许可和可重渲染说明。

### 12.4 系统 UI 可控生产合同（落地建议）

每个 UI 图形必须具备稳定 ID，并将可变内容和动画状态与表现组件分离。建议最小字段：

| 字段 | 作用 | 必须可编辑 |
|---|---|---|
| effect_id | 跨镜唯一识别 | 否（稳定） |
| ui_type | 状态面板/通知/技能卡/属性条/地图等 | 是 |
| content | 标题、标签、数值、单位、说明 | 是 |
| style_id | 颜色、字体、边框、图标体系 | 是 |
| anchor | 屏幕坐标/人物手掌/道具/空间标记 | 是 |
| transform | 位置、旋转、缩放、透视 | 是 |
| timing | 出现、停留、更新、消失帧 | 是 |
| animation | 入场/循环/数值变化/退场 | 是 |
| fx_params | 扫描线、发光、粒子数量/速度/寿命/颜色/随机种子 | 是 |
| occlusion | 前景人物、手指、道具遮挡关系 | 是 |
| continuity_group | 同一场景/跨镜状态组 | 是 |

这份合同是待与 SCG 共享事实规范对齐的草案，不可未经核对就成为第二套权威 schema。

### 12.5 特效图层拆分规范

一个“掌心系统面板”至少拆成：
1. 面板底板/边框（SVG 或 JSX 矢量组件）。
2. 标题/标签/数值（独立文本，数据驱动）。
3. 图标（独立 SVG/图片资产，带稳定 ID）。
4. 动画控制层（开合、位移、缩放、透明度、数值滚动）。
5. 光效层（扫描线、边缘辉光、局部闪烁）。
6. 粒子层（单独发射与销毁，可关闭、调参、复用）。
7. 遮挡层（人物手掌/手指前景 matte 或分层素材）。
8. 声音 cue（与 UI 事件同一时间轴）。

不允许把 1–8 合成一张不可编辑 PNG 来交付正式工程。静帧可用于预览和风格确认，但正式图形保留可编辑源。

### 12.6 透明 Alpha 的使用边界

- ChatCut 官方文档确认 ProRes 4444 Alpha 输出，但本轮未验证用户账户是否有 Pro 权限。
- 透明视频解决的是“把 UI 图形叠加到视频上”，不自动解决人物遮挡、掌心锚定、镜头透视和遮罩漂移。
- 如果 UI 仅需屏幕空间叠加，透明导出通常足够；若 UI 位于人物手前/手后或随三维空间运动，必须额外提供跟踪与 matte/遮挡数据。
- ProRes 4444 Alpha 的真实导出文件必须检查 Alpha 通道、帧率、尺寸、时长和边缘预乘/直通问题，不能只看导出菜单或预览背景。

### 15.1 Lower Thirds：透明叠加层的可执行生产技能

固定文件版本：Skill 文件最近一次修改 commit `aa8ef7ed9fa59d0a79fc57701e493cfd8197b5d8`（2026-09-30）；Skill blob SHA `4496f062375c94de1cac9970ed505aa13e6fc149`。

依赖：Node.js 18+、Playwright/Chromium、FFmpeg；脚本需要在工作目录安装 `playwright-core`。

它不只是“做字幕条”，真正可迁移的能力：

适配判断：**高（透明导出与验收），中（系统 UI 本身）**。它最值得复用的是透明素材导出、Alpha 通道验证、首尾帧、可读性和逐帧 QA。它本身不是掌心空间跟踪器，也没有自动解决人物前后遮挡。其下三分之一字幕条布局规则不能直接套用到魔法阵、全息面板和技能 HUD。

### 15.2 Particle System：粒子模拟与确定性回放

来源：<https://github.com/iart-ai/webgl-animation-skills/tree/master/skills/particle-system>  
固定 Skill 文件 commit：`c3301183bffedb3be65a5588c954da99f1073d1e`；Skill blob SHA `819edffebf0134bdb326dcfec02615846ae4dba2`。  
许可证：仓库根目录 MIT（已读取）。  
输出：单文件 HTML，可用 Canvas 2D（数百粒子）或 Three.js GPU Points（数千至数万粒子）；本轮未安装/运行。

核心技术：
- 粒子逐帧状态：位置、速度、加速度、寿命、尺寸、旋转和颜色。
- 力场组合：重力、阻力、吸引/排斥、弹簧和流场。
- Burst（一次性爆发）与 Continuous（持续发射）分开处理。
- Curl Noise（无散度旋涡噪声）适合烟雾、能量流和水流式轨迹。
- 空间网格减少粒子互连时的 O(n²) 两两比较开销。
- GPU Points + ShaderMaterial 支持高粒子数量、每粒子 seed/life 属性和加色发光。
- 通过固定随机种子 + 固定时间步长 + `?t=N` 冻结指定时刻，确保同一时刻能重复截图/验收。

适配判断：**高（粒子参数化），中（直接用于 ChatCut）**。技术适合火花、尘埃、能量点、魔法流、雪/雨/烟雾和背景星尘。要接入 ChatCut，仍需把模拟输出变成它可接受的 Motion Graphic JSX/Canvas 组件或可导入素材；当前没有证据表明该 Skill 能直接调用 ChatCut API。

关键改进建议：粒子配置必须至少公开 `count`、`emitRate`、`burstCount`、`speedMin/Max`、`spread`、`lifeMin/Max`、`sizeMin/Max`、`gravity`、`drag`、`noiseStrength`、`colorRamp`、`seed`、`blendMode`、`anchor`、`depth/occlusion`。其中 seed 和事件时间不可省略，否则跨镜复现和 A/B 比较会失控。

### 15.4 After Effects：专业透明导出与可控层级

来源：<https://github.com/iart-ai/motion-design-skills/tree/master/skills/after-effects>  
固定文件 commit：`3110f145d92bfbb0d3da88940de6c50225b79bf7`；Skill blob SHA `c7f266baccb546ab893153d62c4d80753e40fec4`。

值得迁移的工程规则：
- 用 Null + Slider / Checkbox / Color / Angle / Point 控件驱动多个图层。
- 通过 Essential Graphics / MOGRT 暴露可编辑参数。
- Alpha 交付明确分清 ProRes 4444、PNG/TIFF 序列、VP9 WebM Alpha 和 H.264（无 Alpha）。
- 解释 Straight / Premultiplied Alpha，避免透明边缘黑边。
- 工程文件按层级组织、素材收集和路径重链，确保可移交。

适配判断：**高（专业后期控制与合成），中（当前用户实际可用性）**。本轮只审查技能内容，没有确认用户电脑是否安装 AE、插件或许可证。

## 16. 修正后的最优组合

**主生产链：现有 ChatCut 直接 JSX Skill + ChatCut 时间线。**

- UI 主体：ChatCut 直接 JSX 图形，真实文字和数据独立可编辑。
- 透明导出：优先 ChatCut ProRes 4444 Alpha（账户权限待核验）；若当前账户无 Alpha 导出权限，再评估 Lower Thirds 的独立透明渲染脚本作为补充，而不是先购买其他软件。
- 粒子：从 Particle System 迁移 2D Canvas 粒子状态/参数/种子原则；简单效果优先 Canvas，不直接上 3D。
- 能量纹理：只在确有需要时采用 Shader GLSL；不要为普通面板引入 WebGL。
- 复杂人物遮挡/透视：再考虑 After Effects 跟踪、遮罩和分层合成。
- 质量检查：吸收 Mort1d 的逐帧/随机顺序检查 + Lower Thirds 的透明通道解码检查 + Particle System 的固定时刻冻结截图。

### 16.1 生产层级选择

| 场景 | 采用方式 | 不要做的事 |
|---|---|---|
| 普通系统通知/数值变化 | ChatCut JSX/SVG 组件 | 生图模型直接写最终数字 |
| 技能卡/属性面板 | 多层 JSX + SVG + 文字数据 | 合成一张不可编辑 PNG |
| 小型光点/火花 | Canvas 2D 粒子 | 一开始就上 UE/Three.js |
| 大量粒子/复杂流场 | Three.js Points / Shader | 每个粒子单独 DOM 节点 |
| 全息能量材质 | Shader GLSL | 把 Shader 当文字布局工具 |
| 角色手部空间投影 | UI 图层 + 跟踪/遮罩/透视合成 | 只靠 Alpha 视频声称已实现手部遮挡 |
| 跨镜连续 HUD | 稳定 effect_id + 事件/状态数据 | 每镜重新随机生成外观和位置 |
