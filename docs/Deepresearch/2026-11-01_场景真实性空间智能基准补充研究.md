## 1. 新增一手来源

### A. SpatialGenEval（ICLR 2026）
- 仓库：https://github.com/AMAP-ML/SpatialGenEval
- main HEAD：8b294b5fd0bca204fcfbf2cd74b75d9c359e40f6
- 论文：https://arxiv.org/abs/2601.20354
- README 声明：1,230 条信息密集提示词，覆盖 10 个空间子领域；配套 12,300 个全维度选择题；论文评测 23 个 T2I 模型。问题不仅问“画了什么”，也问“在哪里、如何、为什么”；高阶关系、遮挡与因果空间推理比基础物体组合更困难。
- 采纳：把“对象数量/属性、相对位置、方向参照系、遮挡、可通行/交互关系、空间因果”纳入提示词约束和评分维度；借鉴其按场景提示词配套可判定问题的做法，为每个测试场景建立可客观核对的验收问题。
- 许可证：本轮 GitHub 内容 API 未发现可读取的根目录 LICENSE（返回 404）；不复制代码、数据或提示词，只提炼公开论文/README 中的方法。使用其数据集前必须另行确认许可与使用条款。

### B. GenSpace（NeurIPS 2025）
- 论文页：https://proceedings.neurips.cc/paper_files/paper/2025/hash/4e582b104248a396a703646755071329-Abstract-Datasets_and_Benchmarks_Track.html
- arXiv：https://arxiv.org/abs/2505.24870
- 研究结论：一般 VLM 评估经常漏掉细粒度空间错误；其评估管线通过多个视觉基础模型重建 3D 场景几何，以更贴近人类的方式评估空间忠实度。论文指出对象透视理解、第一人称/第三人称参照转换、度量尺寸遵从仍是生成模型弱项。
- 采纳：不能只让同一个通用 VLM 对生成图说“真实/不真实”；对关键测试图必须进行逐项人工检查，必要时用深度/多视图/3D 几何交叉核验。

### C. InSpace（ECCV 2026）
- 仓库：https://github.com/naver/inspace
- main HEAD：acb0310b7b751427fc49665b7b97575004d7c415
- 项目页：https://kookie12.github.io/InSpace-Project-Page/
- 模型：https://huggingface.co/GwanHyeong/InSpace
- 数据集：https://huggingface.co/datasets/GwanHyeong/ERP-FRONT-30K
- 论文/会议：ECCV 2026。
- 方法：从单张 360°等距柱状投影（ERP）全景图生成完整室内 3D 场景；先估计深度并反投影为部分场景几何，再生成粗场景结构、3D 定向包围盒，最后生成分离的家具资产与纹理；输出 scene.glb、layout.glb 和各独立 assets/*.glb。将 ERP 解包为 6 个立方体视图（每面 FOV 120°）进行视角选择式注意力。
- 采纳：将“场景布局与家具资产分离、深度几何先验、立方体面覆盖检查、结构/资产分别验收”作为 360°全景后续研究路线。
- 重要术语边界：该项目输入是 360°水平 ERP 全景，通常覆盖完整球面 360°×180°视域；它不是所谓“720°角度”，也不是自动生成任意超出原始球面视域的额外空间。对用户要求的球形全景，应明确检查水平 360°闭环与天顶/地底覆盖，不用角度数字混淆覆盖范围。
- 环境限制：README 建议 Linux、PyTorch 2.6、CUDA 12.4、NVIDIA 至少 24GB 显存（测试 A100/H100）；需下载多个模型 checkpoint 和数据。当前不作为 Windows 工作站默认安装项，不启动重型部署。
- 许可证：仓库 LICENSE 为 MIT；TRELLIS.2 基础项目也标注 MIT。模型权重/数据集条款仍应分别查看 Hugging Face 页面。

## 2. 对现有 Skill 的具体增量

1. 提示词必须包含可判定的空间关系，而不是只列对象名词：谁在谁左/右、从谁的视角、前后遮挡、距离等级、支撑关系、入口连通、可操作空间。
2. 每个场景测试提示词附 5—10 个客观检查问题，输出图逐题判定，不以“看起来像办公室”代替布局验收。
3. 十维盲评继续使用现有 V1.1 模板；先记录 P0/P1 缺陷，再评分。至少两名盲评者为正式建议，单人评估须注明。
4. 一般 VLM 只能辅助定位缺陷，不作为唯一裁判；关键结构需人工或几何证据复核。
5. 360°场景优先评估水平闭环、天顶/地底覆盖、结构布局、家具资产边界和重复/镜像伪影；InSpace 仅作为重型 3D 重建候选，不是轻量图像提示词 Skill 的默认依赖。
