# GPT 原生生图第二轮复合图失败分析

日期：2026-11-01  
测试目标：检查场景真实性工作流能否按要求产出单张独立场景图及可核验的空间样本。  
结果：本轮生成器连续输出多面板信息图，未得到合格的独立场景图。

## 1. 本轮观察到的失败

连续生成的图像均采用多面板/拼贴/信息图形式，包含正视图、俯视图、侧视图、评分文字或“通过”结论。用户要求的是实际场景图片测试，不是信息图设计，因此这些图不属于有效场景样本，不计入 A/B 统计或质量通过率。

## 2. 图像自身存在的可见问题

- 多面板之间的家具数量、行列、房间尺寸和门窗关系不能证明属于同一真实空间。
- 生成的尺寸、排列参数及“通过”结论没有测量或独立证据支撑。
- 正视照片、俯视平面和侧视照片由模型分别构造，不能因画面并置就声称多视角一致。
- 个别俯视面板虽看似规则，但与其他面板的桌椅数量和布局不完全对应。
- 画面上的标签与评分是模型自行生成的装饰性内容，不构成验收数据。

## 3. 失败分类

| 失败项 | 级别 | 说明 |
|---|---|---|
| 输出形态偏离任务 | P0 | 要单张真实场景图，却输出复合信息图 |
| 多视角一致性无证据 | P0 | 不同面板不能证明是同一空间 |
| 自动生成未测量尺寸 | P1 | 参数文字不具备测量依据 |
| 自我宣布“通过” | P1 | 模型生成的结论不能充当独立验收 |
| 文字/标签干扰图像检查 | P2 | 信息图装饰占用画面 |

## 4. 对提示工作流的修订

1. 单次生成只指定一个输出对象：一张图片、一个机位、一种投影方式。
2. 禁止拼图、网格、分镜板、信息图、对比海报、文字标签、评分、尺寸标注和自我验收结论。
3. 单张照片、90°正交俯视图、侧视图必须拆成独立生成任务，不能要求一张图同时完成。
4. 多视角一致性不能靠模型把几张看似相似的图拼在一起证明；必须使用同一份明确的场景布局/参考图，并逐张核对锚点。
5. 所有尺寸必须由用户给定或由独立几何/测量流程确定；模型自行生成的数字一律视为未经验证。
6. 生图完成后由独立检查流程验收，禁止模型在生成图内写“通过”来替代检查。

## 5. 当前结论

- 本轮有效独立场景样本：0。
- 本轮合格 A/B 配对：0。
- 本轮 Skill 效果提升：不能判断。
- 生成器任务服从性问题：已观察到，需在后续测试中单独评估。
- 不能将本轮复合图保存为教室、办公室或厨房的正式资产母版。

## 6. 下一轮测试方式

从一个场景开始，例如教室后部人眼高度照片。一次只生成一张，不要求平面图或其他视角。确认该单图合格后，再另行发起 90°正交俯视图任务。俯视图合格后，再生成侧视图。每张独立编号、独立检查，最后对照布局锚点核验空间一致性。

本轮失败本身是有效的生成服从性观察，但不是场景真实性提升证据。


## 7. 第三轮：单张教室实景生成测试

日期：2026-11-01  
生成方式：GPT 原生图片生成  
样本编号：GPT-SINGLE-CLASSROOM-01  
结果文件：本轮会话生成的单张教室照片（尚未上传二进制文件至 GitHub）

### 输出形式检查
- 通过：单张独立实景照片。
- 通过：没有拼图、多面板、平面图、尺寸表、评分框或自我验收标签。
- 通过：相机位于教室后部，朝向黑板和讲台。
- 通过：左侧窗户、右侧门、黑板和讲台基本符合普通教室常识。

### 空间质量检查
- P1：左右桌椅总体朝向黑板，但行列错位、间距不均；前景桌椅出现过密与裁切。
- P1：左右桌椅组的行数和横向对齐关系不够稳定，不能作为精确排布母版。
- P2：中央通道可辨，但两侧桌椅边缘不规则，通道宽度观感不稳定。
- P2：右侧门开启后能看到室内/走廊空间，但走廊连接细节没有充分展开。
- P2：画面材质与使用痕迹较自然，未见明显悬浮物体；部分桌椅腿和前景边界因遮挡无法逐一验证。

### 结论
- 输出形式控制：通过。本轮单图约束有效避免了此前的多面板信息图偏航。
- 场景基本常识：部分通过。
- 桌椅布局严格验收：不通过。
- 本轮有效单图样本：1。
- 合格布局母版：0。
- A/B 配对实验：未完成，不能宣称 Skill 已带来提升。

### 下一轮修订
只针对桌椅布局做单图再生成：
1. 先明确 3 列桌椅组，每列 6 排；每张桌子和椅子组成一套，所有桌面朝向黑板。
2. 每列内部桌椅中心线平行，前后排间距一致；横向列距一致。
3. 中央通道连续且宽度明显大于桌椅之间的普通间距；左右侧通道保留可通行空间。
4. 镜头位于最后一排之后，画面容纳完整桌椅组，不用极广角夸大近景。
5. 不生成俯视图、文字、尺寸、标签、评分、拼图或多视角。
6. 若生成结果仍出现桌椅错位，记录为失败并修改约束，不允许模型自行声称通过。


## 8. 第五轮：明确列数与中央通道的单图测试

日期：2026-11-01  
样本编号：GPT-SINGLE-CLASSROOM-02  
输出形式：单张实景照片，无信息图/拼图/评分面板。

### 可见改善
- 黑板、讲台、门窗关系清楚。
- 桌椅总体朝向黑板。
- 中央通道连续，空间比前两轮更规整。
- 左、中、右三个桌椅区域可辨。
- 画面无多视角拼贴，输出形式符合单图要求。

### 仍然存在的布局错误
- 提示词要求三列，但图像把“列/区域”解释为三个桌椅块；每个块内部又有双列桌椅，整体看起来接近六列，而非明确三列。
- 桌椅并非严格 8 排；由于透视、遮挡与画幅裁切，不能可靠地逐一计数。
- 中央通道存在，但其两侧桌椅组的边界与列中心线仍不够清晰。
- 画面中的文字标语虽不是主要错误，但生成了提示词未提供的文字，说明模型仍会擅自补充场景内容。

### 验收
- 单图输出形式：通过。
- 基本教室常识：通过。
- 中央通道连续：通过。
- 指定三列结构：不通过。
- 指定八排及数量：未验证/不通过严格验收。
- 合格布局母版：仍为 0。
- Skill 有效性：尚无配对盲测证据。

### 规则修订建议
后续不要只写“3 columns / 三列”，必须改用可见的空间定义：
- 全教室只有三条连续的桌椅纵向带，分别位于左侧、中央、右侧。
- 每条纵向带在横向上只能有一张桌子，不允许并排双桌。
- 中央纵向带与左右带之间明确留出两条过道；左右墙边另留侧向通行净空。
- 明确“横向列数”与“沿前后方向的排数”是两个不同维度，禁止把桌椅块/分区误当成列。
- 下一轮先测试 3 列 × 5 排，减少遮挡和远景计数误差；画面必须容纳全部 15 张桌子及对应椅子。
- 不生成文字标语，避免模型擅自补充未要求的文字内容。
