## 四、外部工具源码适配结论

### manga-text-removal / CTD-LaMa
- 源码：`scripts/ctd_lama.py`。
- CTD 模型产生的是“文字检测遮罩”，随后 LaMa 只对该遮罩区域补全。
- 该脚本没有自定义完整气泡/尾巴遮罩的 CLI 参数。
- 所以它可以用于擦除气泡内文字、旁白文字、字幕文字；但如果目标是连同整个白色气泡主体与尾巴一起移除，单独运行 CTD-LaMa 不足以保证气泡轮廓消失。
- 需要把用户已有的人工气泡遮罩与文字检测遮罩进行人工确认/合并，再调用 LaMa；不得将自动文字检测遮罩直接当作完整气泡遮罩。
- 本次环境具备 OpenCV、Tesseract、PyTorch；缺少 `lama_cleaner` 和 `pcleaner`，也没有已验证的 CTD 模型权重。因此本轮只做 OCR/遮罩预检，LaMa/CTD 实际补全标记 NOT_RUN。

### agent-comic-kit
- 已读取当前 SKILL、CLI、pyproject、letter.py 和 imaging 测试文件。
- 许可证 Apache-2.0；CLI 版本 0.1.0；Python >=3.11；基础依赖 Pillow、PyYAML；图像生成默认 `codex-relay` 依赖 Windows Codex 桌面端的 codex-image-relay；agent 后端会返回待生成提示，需要外部图像生成器生成后再导入。
- 源码具备独立格拆分、画布合成、气泡/尾巴绘制、自动换行、脸部位置约束、阅读顺序、导出和版本状态。
- 测试源码覆盖 split/compose/letter/export 等流程；本次未下载完整仓库运行 pytest，故外部工具真实运行仍为 NOT_RUN。
- 对 MOONKEEP 的价值是“把已有干净画格作为底图，生成可编辑文字/气泡层”，不是重新生成原画。必须人工填写/核对角色脸部中心坐标、气泡位置、尾巴目标和阅读顺序，不能信任自动放置一次就发布。
- 默认生成后端依赖 Codex Relay，不是当前 GPT 原生生图直接调用接口；如果要用 GPT 原生生图，需走 agent backend 的提示词导出/人工导入流程，不能声称 CLI 已自动调用 GPT 原生生图。

## 五、对 MOONKEEP 的生产路线修正

1. 原始逐格源画格只读保留，SHA-256 不变。
2. 第一话 P01–P06 继续使用 V1.0 的原始画格和人工遮罩作为工作基线；V1.1 新生成图只作为独立视觉样稿，不能覆盖原画。
3. 每格先审核手工气泡遮罩，特别是 P03（28%）和 P04（手部/伤口保护区）。
4. 将完整气泡/尾巴遮罩与 CTD 文本遮罩区分；若目标是去掉整个气泡，必须使用完整气泡掩码，而不是只擦字。
5. 先在单格副本上测试 LaMa；保留同尺寸输出；对比原图和修复图的像素尺寸、构图、人物、背景和纹理。
6. OCR 作为残字筛查，人工 100% 放大检查作为最终验收；检查失败不覆盖源图。
7. 英文对白只使用 `Episode_01_Verified_Lettering_Transcript_EN.md` 作为当前对白事实来源；旧版 `Episode_01_Lettering_Master_EN.md` 明确标注已被替代，不得使用。
8. 用 agent-comic-kit 或 Speech Bubble Editor 进行独立排字时，文字源文件、气泡、尾巴保持可编辑；逐格人工确认说话人、尾巴、气泡阅读顺序和不遮脸/手/关键道具。
9. 完成第一话逐格排字与校对后，才制作真正的分页重排；不能用竖屏长图裁切代替分页出版。
10. 不安装外部软件前先核许可证、依赖、系统资源、图像样本和隔离路径；本轮没有向工作站安装任何依赖。

## 六、验收结论

- 两个 ZIP 的完整性：V1.0 清单 97/97 PASS；V1.1 清单 8/8 PASS。
- 原始画格尺寸与 V1.1 新图尺寸对照：6/6 均不一致。
- P01 语义对应：不一致（喷泉对话变为城堡远景）。
- OCR/手工遮罩预检：完成；不是去字完成。
- CTD-LaMa 实际运行：NOT_RUN（缺少 pcleaner、lama_cleaner 和模型权重）。
- agent-comic-kit 实际运行：NOT_RUN（未安装完整仓库/依赖，未运行其 pytest）。
- 独立英文排字：归档中有英文对白稿，但没有因此证明 V1.1 新画格已与原剧本匹配。
- 正式分页出版：NOT_RUN；旧分页校样仍需与独立重排版本区分。

本报告只用于修正技能规则与下一步测试路线，不修改或替换用户的 MOONKEEP 原始项目包。
