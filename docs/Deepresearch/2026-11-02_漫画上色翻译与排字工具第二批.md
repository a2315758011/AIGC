## 三、针对 MOONKEEP 的工具优先级

1. 最高：独立英文排字与文字源数据。现有 V1.1 档案的下一阶段就是独立英文排字和正式分页；先用已批准的六格无文字图建立排字稿，验证气泡位置、尾巴归属、英文校对和可编辑源文件。
2. 高：逐格连续性和返工。继续以 agent-comic-kit 的角色批准、锁定字段、单格返工流程为方法基准，但不依赖其 Windows Codex 专用图像后端。
3. 中：去字/修复。仅在仍有原文字或修复失败的格子上做局部修复，不批量重做已完成无字画格。
4. 低（当前）：上色工具。项目为彩色漫画，除非发现确切黑白源页/色彩损坏，否则不上色。
5. 不采纳：无许可证代码（Comtexia、MangaColorAI、Manga Colorizer）用于商业集成；可记录技术方法，但不得复制实现。

## 四、必须补充的生产规范

- 英文台词源文必须单独保存，含角色、格号、文本类型、发言顺序和校对状态；翻译/改写不得覆盖原剧本。
- 术语表固定人名、地名、组织、魔法/设定专有词；同一术语跨章节一致。
- 对白气泡/旁白框/拟声词各自独立图层；每个对象可调整位置、大小、尾巴、字体、行距和换行。
- 每页排字后以目标移动端实际显示尺寸检查可读性，不能只看桌面原尺寸。
- 英文文字不得由图像模型直接绘制；任何烘焙进像素的文字都需要人工逐字核对。
- 排字层与画格底图分离，修改一句台词不触发重新生成画格。
- 未获得字体授权文件或清晰许可证记录，不得作为商业发行字体。
- 翻译/去字工具的第三方漫画示例图、角色和模型权重不因代码许可证而自动可商用。

## 五、结论

本轮真正适合优先验证的不是“全自动漫画生成器”，而是两类工具：
- Speech Bubble Editor：局部人工气泡/排字编辑。
- Free Comic Panel Maker：零安装 SVG 单格排字。

Comtexia 的流水线设计很完整，但许可证缺失且依赖/API 复杂；MangaColorAI 有专业的颜色一致性技术，但未声明许可证且对当前彩色漫画项目不是优先需求。暂不安装任何未通过许可证、依赖和运行验收的工具。


## 六、源码级补充审查（agent-comic-kit / manga-text-removal）

### agent-comic-kit
- 已读取 `SKILL.md`、`pyproject.toml`、`comic/cli.py`、`comic/imaging/letter.py`、`tests/test_imaging.py` 和测试目录清单。
- `pyproject.toml` 版本为 0.1.0，Python >=3.11；基础依赖仅 Pillow、PyYAML，pytest 是测试可选依赖。
- `letter.py` 通过 Pillow 3 倍超采样绘制 speech/shout/thought/narration 气泡，具备自动换行、尾巴、脸部中心坐标、阅读顺序和位置约束；这属于程序绘制的可编辑前置数据，不等于 PSD/AI 等图层工程文件。
- `tests/test_imaging.py` 明确覆盖 split、compose、letter、export 的单元与流水线测试；本次仅审查测试源码，未执行外部仓库 pytest。
- 默认 `codex-relay` 后端依赖 Windows Codex 桌面端的 codex-image-relay；`agent` 后端会等待外部图像生成并通过 `comic import` 导入。因此它不能被描述为已经能自动调用本会话 GPT 原生生图。
- 结论：适合作为逐格页面数据、单格返工、自动气泡/尾巴几何的研究候选；必须人工核对气泡位置和尾巴。当前不直接部署到 MOONKEEP。

### manga-text-removal
- 已读取 `scripts/ctd_lama.py` 和 `scripts/clean_manga_lama.py` 的实际源码。
- CTD-LaMa 的输入是原图，内部通过 comic-text-detector 生成 `_raw_mask.png`，再对文字掩码膨胀并调用 LaMa；脚本没有接受人工完整气泡/尾巴掩码的 CLI 参数。
- 因此：它能擦除检测到的文字，但若要求移除整个白色气泡主体与尾巴，不能仅凭 CTD 文本掩码保证完成。需要将人工气泡掩码与文字掩码合并审核，再调用 LaMa。
- `clean_manga_lama.py` 的 OCR 引擎也只围绕文字框生成掩码，不能替代完整气泡轮廓遮罩。
- 结论：采纳“CTD/OCR 检测 + LaMa 局部补全 + OCR 残字验证”的方法；MOONKEEP 需增加完整气泡掩码输入/合并步骤。该工具在目标工作站实际运行仍为 NOT_RUN。
