### 2. 阿超掏上了：三张参考图锁定人物/道具站位
- B站视频：https://www.bilibili.com/video/BV1TK4r6eEBs/
- 页面标题：AI人物/道具锁站位方法；发布日期：2026-08-29。
- 搜索页面摘要描述的工作流：先生成 720° 全景与垂直俯视图，再用平视图、道具图和彩色标注明确人物、道具方向、左右关系和距离，最后把参考图一起导入视频节点。
- 可采纳的角色分工：
  - 全景图：提供环境视觉和周边空间参照，不默认视为精确几何模型。
  - 垂直俯视图：表达人物/道具的世界平面位置、通道、左右关系。
  - 平视/机位图：表达人物在目标视角中的大小、遮挡、朝向与画面关系。
  - 道具特写/标注图：绑定道具身份、朝向和接触点。
- 不应把多张图无说明地堆在提示词里；必须逐张声明“只参考什么、不参考什么”，角色与道具使用稳定ID/颜色辅助映射。

## 二、WorldCast：大角度摄影机运动下保持角色身份的研究代码

- 论文：https://arxiv.org/abs/2610.33135（2026-10-23）
- GitHub：https://github.com/PixCtrol/WorldCast
- 项目页：https://pixctrol.github.io/WorldCast/
- HuggingFace 权重：https://huggingface.co/ly56/worldcast/
- 本次检查的 main commit：`7ccf2e0ded1238bf6dea1b285c29bcf322e337cb`
- 许可证：Apache-2.0（仓库说明继承自 DiffSynth-Studio；基础 Wan 模型有独立许可）。
- 方法：
  1. 从首帧深度估计反投影为 3D 点云。
  2. 将点云尺度与目标摄影机轨迹对齐。
  3. 沿摄影机轨迹渲染几何指导和覆盖掩码。
  4. 使用 1-4 张不同视角的角色锚点图，补充首帧未显示的身体区域。
  5. 通过几何对齐的记忆注意力，在统一坐标系中检索目标视角的角色特征。
- 对漫剧的启示：如果需要大角度环绕/从正面转到背面，单张角色参考图信息不足；多视角锚点与统一坐标系有助于降低身份漂移、服装/体型变形。
- 运行门槛和商业限制：
  - 依赖 Wan2.1-I2V-14B 基础模型；仓库建议 480x832 下 14B 模型使用 CUDA GPU，推荐显存至少 48GB。
  - WorldCast 训练模块约 2GB，不包含基础 DiT 权重；两个 checkpoint 必须来自同一发布版本。
  - 训练代码和 CLACT 数据集尚未发布。
  - 仓库说明 SpatialVID 数据仅用于学术研究，遵循 CC BY-NC-SA 4.0 及其条款，不能默认用于商业漫剧生产。
- 结论：研究价值高，但不作为当前普通电脑/免费漫剧生产的默认方案；仅用于理解多视角身份锚定和几何一致性。

## 三、学术研究交叉补充

### 1. ActCam：联合控制人物动作与摄影机
论文：https://arxiv.org/abs/2605.06667（2026-05-07）
- 输入动作驱动视频、目标场景首帧和逐帧摄影机轨迹。
- 生成与目标相机一致的姿态图和深度图；通过相机对齐的条件信号同步人物运动与摄影机运动。
- 将静态场景深度与动态人物分离，避免角色被错误固化到静态几何里。
- 研究指出，仅用2D关键点时，移动摄影机下可能出现多种3D解释；相机转动/平移会使2D控制信号产生歧义。
- 采纳：人物根节点路径、骨骼姿态、静态场景几何和摄影机轨迹应分开建模，再在同一坐标系下对齐。论文实验不等于当前商业模型支持这些输入。

### 2. 3DScenePrompt：静态场景记忆与动态内容分离
论文：https://proceedings.iclr.cc/paper_files/paper/2026/hash/77f2e9559888c4ebf794dc0e3b0e5da6-Abstract-Conference.html（ICLR 2026）
- 同时使用时间邻近帧维持动作连续性、空间邻近内容维持场景一致性。
- 通过动态 SLAM 与动态遮罩，建立只包含静态几何的 3D 场景记忆。
- 静态场景可投影到新的摄影机视角，动态人物则由时间上下文自然变化。
- 采纳：场景墙体、门窗、家具、道路等静态拓扑不能与人物动作状态混成同一“参考图”；跨镜时先继承静态场景，再单独更新人物/道具状态。

### 3. MoCa：区分摄影机运动与物体运动
论文：https://proceedings.iclr.cc/paper_files/paper/2026/hash/f73c04538a5e1cad40ba5586b4b517d3-Abstract-Conference.html（ICLR 2026）
- 使用摄影机轨迹编码与语义引导保持物体视角、外观和纹理一致。
- 通过物体感知的运动解耦机制，区分物体自身运动与整体摄影机运动。
- 采纳：画面左右变化不能直接推断人物世界位置改变；运镜与人物位移分别验收。

## 四、合并后的站位/预演工作流

### 阶段A：建立场景世界底稿
1. 先锁定房间/建筑拓扑：墙体、门窗、走廊、家具、通道和固定物。
2. 给场景建立稳定局部坐标系，标明原点和方向。
3. 建立静态场景参考与动态人物/道具状态分离的资产。
4. 至少用俯视图+目标机位图复核空间；全景图仅作环境补充，不能代替几何真值。

### 阶段B：建立人物身份与位置合同
1. 每个角色有稳定 character_id，角色图/多视角图映射到该ID。
2. 记录世界位置、身体朝向、头部朝向、视线目标、姿态、支撑面、可见性。
3. 颜色只辅助识别，不能替代稳定ID。
4. 人物位置/动作关键帧与摄影机轨道分别记录。

### 阶段C：动态预演
1. 读取导演工程当前状态，使用真实对象/镜头/动作ID。
2. 固定当前项目时间基准；若选择24fps，则用整数帧，不把24fps强制推广到所有生成平台。
3. 设置起点、终点、路径控制点、动作姿态、停留时间和朝向。
4. 设置摄影机位置、注视目标、FOV、滚转和时间关键帧。
5. 对已经人工确认的站位/动作/机位关键帧加锁；AI不得静默覆盖。
6. 每次编辑后执行工程验证；错误只撤销最近一项，不重置整个场景。

### 阶段D：生成与独立验收
1. 白模视频只负责动作/空间/机位/节奏；场景图负责美术；角色多视角图负责身份和外观；道具图负责形状/朝向/接触关系。
2. 生成前核对每份素材职责，避免重复提示词覆盖结构化轨迹。
3. 生成后逐帧检查世界位置、人物ID、身体姿态、摄影机轨迹、场景拓扑和镜间连续性。
4. 工程校验通过不等于视频模型服从；目标模型必须另做 A/B 与重复样本测试。

## 五、新增规则建议与证据评级

| 方法 | 评级 | 理由 | 当前使用边界 |
|---|---|---|---|
| 稳定ID + 工程状态读取 + 人工锁定 + 可撤销编辑 | 低（候选） | 开源仓库源码和测试定义可审查，但本轮未运行测试 | 作为结构化导演台选型/接入候选，不假定当前已安装 |
| 24fps整数帧时间线 | 低（工具特定） | Kunpeng当前实现明确采用24fps | 只在该工具工程内使用；其他模型/平台按其时间基准 |
| 全景+俯视+平视/道具多参考图 | 低（创作者自述） | 单个公开视频页面摘要，视频内容未逐帧核验 | 作为实验输入，不成为强制标准 |
| 多视角角色锚点 + 3D几何对齐 | 低（研究候选） | WorldCast论文与代码/权重可查，但硬件高、目标平台未集成 | 大角度镜头研究，不作为免费/低配置默认路线 |
| 静态场景记忆与动态角色分离 | 低（研究候选） | ActCam、3DScenePrompt等研究支持，未在用户目标模型复现 | 用于规则设计和测试变量拆分 |
| 摄影机运动与物体运动解耦 | 中（多源研究支持） | MoCa、ActCam等独立研究从不同路线讨论相机/主体运动一致性 | 作为导演规划的分轨原则；成片服从率未验证 |

评级按知识库规范执行：低级方法不能覆盖高级事实；未运行代码/未生成视频不能晋级为高级。

## 六、目标模型A/B测试用例升级

使用同一校园三人场景，至少比较：
- A：文字站位。
- B：俯视图 + 角色身份映射。
- C：全景 + 俯视 + 平视/道具图，各自声明职责。
- D：C + 结构化3D导演台白模（仅当工具可用且无需额外付费时）。

每组至少3次，固定模型/提示词/场景图/角色图/画幅/时长，记录任务ID。逐帧检查：
- 人物世界位置与画面位置是否混淆；
- 人物身份/服装/体型是否漂移；
- 门窗、墙体、桌椅等静态拓扑是否变形；
- 摄影机绕行时人物背面/侧面是否崩坏；
- 人物动作与根节点位移是否同步；
- 人物与摄影机同时运动时是否发生滑步、穿模、突然换位；
- 人工锁定位置是否被后续镜头覆盖。
报告服从率、身份漂移、几何错误、轨迹误差、关键事件时间误差、返工次数和成本。不得以一条成功样片作为稳定结论。
