# 代码动画与程序化视频制作规范 V1

版本：V1.0.0  
制定日期：2026-11-03  
状态：已采纳为中等级候选方法；仓库静态回归通过后可复用，真实生产成片仍须逐项目验收。  
上游来源：win4r/video-director，固定提交 `4747e5c153509ef7f8f7fd1a0aad6acfda36280d`，MIT License。

## 1. 目标与适用范围

本规范把代码驱动的视频制作纳入 AIGC 分镜生产链，适用于：

- HTML / Canvas / SVG / Three.js / GSAP / Remotion 等程序化动画；
- 产品宣传片、解释视频、数据故事、动态排版、动态图表；
- 系统 UI、HUD、全息屏幕、信息图、片头片尾、转场和可控后期叠加；
- 粒子、能量线、屏幕投影、程序化材质等可参数化视觉效果；
- 风格化、插画式或程序化角色动画；
- 需要重复渲染、逐帧检查、精确控制时长和节奏的 MP4。

本规范不把代码动画包装成真人视频生成能力。真人演员表演、真实皮肤/毛发/布料、复杂人体接触、写实场景和模型生成服从性仍由现有真人影视、场景真实性、动作/接触和目标视频模型工作流负责。

## 2. 专业边界与权威事实源

程序化视频是**分镜之后的执行与渲染层**，不是第二套分镜系统。

权威事实按职责分开：

1. 原剧本与用户锁定事实：剧情、人物关系、台词、事件结果和明确禁止项。
2. `storyboard-director-cn` 的 SCG：每镜完整 entities / relations / events 世界状态快照的唯一事实源。
3. `storyboard-director-cn/references/分镜事件时间数据契约-V1.md`：镜头与动作事件的统一毫秒时间基准、可见事件、前置依赖和互斥关系。
4. 人物站位与场景调度规则：人物世界位置、姿态、朝向、视线、路径、支撑与轴线。
5. `scene-realism-director-cn`：静态场景拓扑、建筑/家具、尺度、物理与光材质。
6. `camera-motion-director-cn`：摄影机轨迹、运动类型、机位与注视点。
7. `director-previs-cn`：跨专业导演意图和数据交接；只引用 SCG 镜头 ID，不复制第二份世界状态账本。
8. 本规范与 `video-director-cn`：只负责代码动画、渲染时间表、音画编排、自动 QA 和交付证据。

### 2.1 timeline.json 的地位

上游 video-director 将自己的 `timeline.json` 作为一部代码视频内部的统一渲染时间表。本仓库必须增加一层边界：

- `timeline.json` 是从已批准分镜/事件时间账本**派生的渲染视图**，不是项目世界状态的权威来源。
- 不得在 `timeline.json` 中复制或重新定义 SCG 的 entities、relations、events、角色位置、道具持有关系或场景几何。
- `timeline.json` 可管理渲染层自己的画面 cue、字幕、音乐、SFX、文字可读时间、转场、切点、色彩/排版和 QA 采样点。
- 每个渲染 scene 必须保留原始 `shot_id`；每个 beat 必须能追溯到原始 `event_id` 或明确标注为渲染层 cue。
- 改变人物、道具、场景或动作事实时，必须回到原剧本/SCG/事件时间账本修订，不能只改渲染时间表。

### 2.2 时间单位转换

AIGC 事件时间契约使用毫秒；video-director 使用秒浮点数：

`render_seconds = (source_time_ms - episode_start_ms) / 1000`

只做单位换算，不做无来源的时间重估。保留源镜头 ID、源事件 ID、源起止毫秒和来源文件引用。帧编号只在最终渲染阶段按项目已批准 FPS 换算。

若事件早于当前镜头开始、但在该镜头内仍持续可见，渲染 beat 可以锚定到镜头起点；必须在 cueRef 中记录这是“跨镜持续事件的镜头内锚点”，不能冒充事件真实开始时间。不可见事件不得自动成为画面 beat。

## 3. 调用条件

满足以下任一条件时调用 `video-director-cn`：

- 用户要求把简报、脚本、已批准分镜或图形方案变成代码渲染视频；
- 目标是可重复渲染的动态 UI、动态图形、解释动画、数据故事或程序化特效；
- 需要精确控制逐帧时间、节奏、文字停留、音效同步、转场或循环接缝；
- 用户要求检查或修复已有 HTML / Canvas / SVG / Three.js / Remotion 视频工程。

以下情况不要单独调用它：

- 只要求写普通分镜脚本：先调用 `storyboard-director-cn`。
- 只要求设计摄影机运动：调用 `camera-motion-director-cn`。
- 目标是 GPT / Seedance / Kling 等视频模型提示词：走对应模型适配流程。
- 目标是写实真人表演、真实接触或复杂人体动作：不得用程序化动画冒充真人成片；必要时只将本技能用于字幕、HUD、能量叠加和后期图形。
- 只要静态分镜图或多宫格联系表：调用现有分镜/联系表技能，不以 MP4 流程替代。

## 4. 标准生产流程

### 阶段 0：恢复与锁定

读取当前项目事实、分镜、批准资产、目标交付规格、相关 Skill 的 SOURCE_LOCK 和现有工程。确认当前主线版本，不覆盖其他执行者成果；有写入冲突时停止写入。

### 阶段 1：一句话简报与缺口标记

接收一句话目标后，先整理：

- 观众、发布渠道、观看设备和是否静音自动播放；
- 目标时长、画幅、分辨率、FPS 和交付格式；
- 核心主张、Hook、CTA、必须显示的术语/数字；
- 现有剧本、分镜、人物/场景/道具和品牌资产；
- 音乐、旁白、SFX 和可用素材；
- 缺失项、未知项与需要用户确认的事实。

可以自主选择普通技术默认值，但不得编造剧情事实、数字、品牌承诺、人物动作、场景结构或未提供的资产。

### 阶段 2：创意方案与结构选择

先写 `TREATMENT.md`，列出三种结构方向，选择一个并解释原因；参考作品只学习构图、节奏、镜头语法和色彩组织，不复制角色、故事、镜头、Logo、字体或音乐。

明确一个主要视觉概念、一个视觉焦点、一个高潮/核心揭示点和结尾回扣。避免把作品做成无叙事的动态屏保。

### 阶段 3：编译渲染时间表

1. 先运行现有事件时间校验器：`node skills/storyboard-director-cn/scripts/分镜事件时长校验器-V1.js events.json`。该校验器不解析普通中文分镜稿；任何 Txx 硬错误必须先回到事件账本修复，Wxx 警告须人工复核并记录。Node.js 不可用时标记源账本校验 NOT_RUN，不得声称时序已验证。
2. SCG 结构校验沿用 `storyboard-director-cn` 的现有规则与回归，不在 video-director 中复制 SCG；timeline 只保留 SCG 来源引用。
3. 使用 `scripts/compile_aigc_timeline.py` 将已通过源账本复核的事件时间投影为 video-director 时间表。
4. FPS、分辨率、时钟类型来自当前项目批准的渲染规格，不得无依据固定为 24/30/60 FPS。
5. 只把当前镜头可见的事件映射为 beat；保留 shot_id/event_id 来源。
6. 音乐、旁白、字幕、文本、SFX、切点和 Hook/CTA 属于渲染层安排，必须有明确来源或标记为设计决策。
7. 运行 `scripts/check_timeline.py`；有 ERROR 不进入动画编码。WARN 必须修复或逐项写明为何保留。

### 阶段 4：静帧先行

先输出 styleframes / 关键构图 / 首帧 / 结尾海报，再进入动画编码。先确认构图、字级、色彩、主体尺度、素材分辨率和手机端可读性。高成本渲染前先解决方向错误。

### 阶段 5：确定性动画编码

- 每帧必须是时间 `t` 或 frame index 的纯函数；任意帧可单独、乱序、并行渲染。
- 禁止依赖 `setTimeout`、`setInterval`、`Date.now()`、CSS 自主 transition、跨帧隐式状态或未设种子的随机数。
- 随机过程必须显式固定 seed；字体、图片、模型、纹理和外部资源必须等待加载完成后才允许捕帧。
- 统一场景坐标、锚点、对象 ID、相机轨迹、色彩 token 和文字安全区。
- 对人物/角色动画保持屏幕方向、体积转身、脚底接触、手部姿态和道具关系；超出程序化模型能力时降级，不伪造真实表演。
- 对已有工程修复必须限定修改范围；修复后比较影响范围外的帧，确认没有意外变化。

### 阶段 6：声音与文字

画面、音乐、旁白、SFX、字幕和检查点共享同一渲染时间表。SFX 应绑定事件/beat，而不是随意输入绝对时间。旁白时间优先使用真实 TTS/ASR 词级时间戳；估算时间必须标记 ESTIMATED，不能冒充实测。

文字必须足够大、对比度足够、停留时间足够。Hook/CTA 的首屏规则适用于相应短视频发布场景；有明确例外时写明理由，不机械套用。

### 阶段 7：渲染与机器 QA

- HTML/Canvas/SVG/Three.js 可采用 Playwright/Chromium 逐帧捕获；Remotion 使用其项目构建/渲染工具。
- 渲染前和每次改动时间表后运行 `check_timeline.py`。
- MP4 输出后运行 `qa_video.py`，生成 JSON/Markdown 报告和 beat/phone/hook 联系表。
- `qa_video.py` 需要 ffmpeg、ffprobe、Python、NumPy、Pillow；无音轨时音频检查不适用，必须明确说明。
- 机器 QA 主要检测时间轴、文字尺寸/对比度、首帧、闪帧、画面突变、冻结/平帧、切点、循环接缝、响度、峰值和静音；它不理解剧情，不证明真人动作正确，也不替代审美判断。

### 阶段 8：视觉审片与独立验收

至少检查：

1. 每个 beat 后约 0.3 秒的关键帧；
2. 每个快速动作、转场和切镜的连续帧条；
3. 360px 手机尺寸的可读性；
4. 首帧、高潮帧和结尾海报；
5. 全片节奏、视觉焦点、信息是否清楚、音画是否同步；
6. 与原分镜/SCG/事件时间账本的事实一致性；
7. 由非构建者或独立上下文进行第二次审查。

机器 PASS 只证明脚本覆盖的检测项通过，不代表视频“好看”或剧情准确。

### 阶段 9：局部修复与回归

每次只修一个主要问题，记录修复卡和影响范围。对修改范围之外的帧做渲染前像素差异检查；不要用两个有损 MP4 的全文件差异代替渲染帧比较。修复后重新运行相关时间轴、QA 和视觉审查。

## 5. 交付清单

按项目需要交付：

- `TREATMENT.md`：创意方案与制作决策；
- `timeline.json`：渲染时间表及 AIGC 源 ID 引用；
- `src/` 或项目源码：可修改的 HTML/JS/TS/Three.js/Remotion 工程；
- `film.mp4`：最终渲染；
- `poster.png`：代表帧/封面；
- `qa/report.md`、`qa/report.json` 和联系表；
- `review.md`：人工/独立审片问题与结论；
- `SOURCE_LOCK.json`：上游版本、依赖、文件 SHA 和测试状态。

不要把临时测试视频、渲染缓存、第三方临时素材或凭据混入正式交付目录。

## 6. 验收状态

必须分别报告：

- 需求与事实已锁定；
- 时间表已编译；
- 时间轴静态检查通过；
- 动画代码已构建；
- MP4 已真实渲染；
- 机器 QA 已执行；
- 关键帧/连续帧已人工检查；
- 独立审片已完成；
- 最终交付已验证。

任何未执行的步骤均标记 NOT_RUN / 未验证。文件已上传、脚本已运行或 CI 通过，不等于真实生产成片通过。
