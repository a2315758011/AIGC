# 漫剧系统 UI 与程序化特效制作规范

版本：V1.0.0  
状态：本轮权威源指令候选，待技能包结构与测试验收  
维护仓库：`a2315758011/AIGC`  
适用：AI 漫剧、AI 短剧、动画视频中的系统界面、全息 HUD、属性面板、技能卡、提示窗、魔法符号、程序化粒子、能量纹理及透明特效叠加层。

## 1. 目标与边界

将系统 UI 和程序化特效制作成**内容准确、参数可控、图层可编辑、时间可复现、空间关系正确、可跨镜继承**的生产资产。

本规范负责：
- 系统 UI 的内容、组件结构、样式、动画、数据驱动和跨镜连续性。
- 2D 粒子、程序化矢量、扫描线、辉光、能量纹理和特效参数。
- 透明通道、图层交付、逐帧检查与特效独立验收。

本规范不负责：
- 剧情、角色身份、人物动作和场景事实的创造；必须继承原剧本与共享事实。
- 正式分镜、人物走位、摄影机轨迹；分别由分镜和运镜专业技能负责。
- 打斗接触、受力和命中特效因果；由 `fight-impact-vfx-cn` 负责。本规范只负责这些事件触发后 UI/粒子如何表现。
- 复杂人物动画、三维骨骼和真实摄影机跟踪的完整求解；按需交给对应工具/专业流程。

## 2. 不可违反的制作原则

1. **文字和数据必须真实。** 标题、对白、数值、单位、技能名和状态来自剧本/SCG/用户数据；图像生成模型不得作为最终文字和数字的权威来源。
2. **界面必须分层。** 面板、边框、标题、正文、数值、图标、光效、粒子和遮挡层必须能独立修改；静帧 PNG 只作预览或参考，不冒充可编辑工程。
3. **每个效果必须有稳定身份。** 使用 `effect_id`；跨镜继承同一效果时不得随机换布局、颜色、图标、数值或动画状态。
4. **参数必须可控。** 常用参数通过 ChatCut 可编辑属性或明确的结构化参数暴露，不把高频修改藏在 JSX 深处。
5. **时间必须可复现。** 动画由帧号/时间和事件驱动；粒子使用固定随机种子和固定时间步长。相同输入应能复现相同帧。
6. **空间关系必须可信。** 明确屏幕空间/世界空间、锚点、变换和遮挡。透明 Alpha 只解决透明背景，不自动解决人物手部遮挡、透视或跟踪。
7. **视觉重点必须克制。** UI 不遮脸、关键动作、对白和接触点；粒子不覆盖必须阅读的文字和数值。
8. **优先复用现有工具。** 首选用户现有 ChatCut Motion Graphics 能力；不重复建设独立渲染器。只有出现已验证的能力缺口时，才引入 Canvas/Three.js/Shader/After Effects 等补充工具。
9. **不得虚报平台能力。** 工具接口、账户方案、透明导出、跟踪和遮罩必须在实际项目中验证。官方文档和 Skill 说明只能证明产品声明或流程设计，不等于用户环境验收。
10. **按复杂度选技术。** 普通 UI 用 JSX/SVG；小型 2D 粒子用 Canvas；数千级粒子或空间效果才评估 GPU/Three.js；需要精细人物跟踪和遮罩时才考虑 AE。

## 3. 共享事实与数据合同

必须沿用导演共享事实/SCG（场景连续性图）中的权威 ID、时间轴、角色、场景、道具和镜头状态。下列字段是本专业的建议扩展，落地前须与现有 SCG 规范对齐，不得创建第二套互不兼容的世界状态系统。

每个 UI/VFX 实例建议至少包含：

| 字段 | 含义 | 规则 |
|---|---|---|
| `effect_id` | 稳定效果 ID | 全项目唯一，跨镜复用 |
| `effect_type` | system_panel / notification / skill_card / particle / energy 等 | 使用受控枚举 |
| `owner_entity_id` | 所属角色/物体 | 没有明确归属时留空，不猜 |
| `anchor_ref` | 屏幕坐标、掌心、道具或空间锚点 | 引用现有稳定 ID |
| `coordinate_space` | screen / world / camera | 必须明确 |
| `content_ref` | 文案和数值数据源 | 文字数据不烘焙进纹理 |
| `style_id` | 样式、字体、颜色、图标体系 | 同系列保持一致 |
| `transform` | position / rotation / scale / perspective | 以场景/镜头坐标约定为准 |
| `event_id` | 触发事件 | 必须可追溯到剧本/分镜事件 |
| `start_frame` / `end_frame` | 显示区间 | 帧率来自项目时间线 |
| `animation_state` | enter / hold / update / exit | 状态转换完整 |
| `particle_params` | 数量、速率、速度、寿命、尺寸、颜色、重力、噪声、seed | 只对粒子类型启用 |
| `occlusion_refs` | 前景人物/手部/道具遮挡引用 | 缺少 matte 时明确标记待处理 |
| `continuity_group` | 跨镜状态组 | 用于继承 UI 内容和空间状态 |

### 3.1 粒子参数最小集合

- 发射：`emit_mode`（burst/continuous）、`count`、`emit_rate`、`burst_count`、`spread`。
- 运动：`speed_min`、`speed_max`、`direction`、`gravity`、`drag`、`noise_strength`。
- 生命周期：`life_min`、`life_max`、`size_min`、`size_max`、`fade_curve`。
- 外观：`color_ramp`、`opacity`、`blend_mode`、`shape`。
- 复现：`seed`、`fixed_timestep`、`event_frame`。
- 空间：`anchor_ref`、`coordinate_space`、`depth_policy`、`occlusion_refs`。

不允许在正式资产中留下未固定的随机数源。若需要自然变化，应由可控 seed 产生。

## 4. 推荐生产架构

### 4.1 第一优先级：ChatCut 直接 JSX

用户已有 `chatcut-motion-graphics` Skill，约定使用：
- 新建图形：`create_motion_graphic_from_code`，内联完整 JSX。
- 修改图形：读取现有源码后 `edit_asset`。
- 时间线放置和变换：`edit_item`。
- 复用现有库资产：`browse_library`。

执行时先读取项目画幅、FPS、时长、人物安全区、字幕和附近画面，再创建自然尺寸的图形；仅当需要全画幅背景效果时才使用全画幅资产。将文案、数值、颜色、字体、尺寸、位置、速度和其他高频修改项暴露为可编辑属性。

当前运行环境若没有上述工具，不得伪造调用或声称已经创建。改为交付可审核的 JSX 源码/参数规格，并标记“未在 ChatCut 运行”。

### 4.2 2D UI 组件

- 使用 JSX 组件组织布局和状态；SVG 绘制清晰边框、图标、路径、刻度、环形进度和扫描轨迹。
- 所有文字使用真实文本节点；图标使用独立 SVG/资产；数值绑定数据。
- 入场/退场、数值变化、扫描线、闪烁和粒子各自独立控制。
- 同一个组件可换皮肤和数据，不为每个角色复制一套硬编码结构。
- 动画采用明确状态机：隐藏 → 入场 → 稳定显示 → 更新 → 退场 → 隐藏。允许按剧情事件跳过中间状态，但不能产生无来源的闪现。

### 4.3 2D 粒子

- 数量不大时优先 Canvas 2D，避免每个粒子创建 DOM 节点。
- 粒子状态至少包含位置、速度、加速度、年龄、寿命、尺寸、透明度和种子。
- 先计算受力和生命周期，再绘制；每帧使用 `dt)，并限制最大时间步长。
- 一次性爆发和持续发射使用不同发射器策略。
- 烟雾/尘埃优先用扩散、增大、淡出的软形状；火花用短寿命、方向性和速度衰减；能量流用路径/流场，不要用随机圆点代替所有效果。
- 数量上升后才考虑空间网格、Three.js GPU Points 和 Shader。

### 4.4 Shader / GPU

仅用于确有收益的程序化材质：扫描、流光、溶解、噪声、扭曲、辉光和大量粒子。
- 动画只由显式 uniform（如 `u_time`、`u_progress`、`u_seed`）驱动。
- 约束循环次数、像素比和渲染分辨率；移动端默认限制 DPR 不超过 2，按需降分辨率。
- WebGL 失败时应有静态/Canvas 降级，不允许整个镜头空白。
- GPU 资源在组件卸载时释放。

### 4.5 透明导出与后期合成

- ChatCut 官方文档声明 ProRes 4444 Alpha 导出属于 Pro 方案；必须先核实账户权限并实际导出。
- WebM/ProRes/PNG 序列需检查 Alpha 通道，而不是只看黑色/棋盘格预览。
- H.264 MP4 不支持 Alpha；如使用纯色抠像，必须明确标注为 chroma-key 兜底，不等同透明通道。
- Alpha 解决透明背景，不解决跟踪、透视和遮挡。UI 位于人物手掌前后时，必须有正确 matte/分层或空间合成方案。
- 对 Straight / Premultiplied Alpha 记录下游软件要求，防止黑边/彩边。

## 5. 标准制作流程

1. 读取原剧本、镜头、SCG 和现有 UI/VFX 资产；锁定内容真值与稳定 ID。
2. 判断观众需要理解什么：状态、提示、技能、属性变化、空间信息还是氛围。
3. 决定屏幕空间或世界空间，明确锚点、尺寸、位置、遮挡和安全区。
4. 先设计稳定显示帧，再设计入场/更新/退场；不要只做炫技动画而忽略可读性。
5. 将面板、文字、图标、光效、粒子、遮挡拆层。
6. 暴露可编辑参数并为粒子固定 seed、时间步长和事件帧。
7. 在现有 ChatCut 工具可用时直接创建/编辑并放置时间线；不可用时交付源文件并标记未运行。
8. 预览首帧、入场中帧、稳定帧、更新帧、退场帧；必要时检查逐帧联系表。
9. 需要透明叠加时导出 Alpha，并用 ffprobe/解码帧或等效工具确认透明像素。
10. 检查人物/道具遮挡、跟踪、透视、字幕/对白/脸部避让和跨镜状态。
11. 独立复检所有错误；修复后重新渲染相关镜头，不重复重做未受影响内容。
12. 保存源码、参数、素材、许可证、导出文件和验收证据。

## 6. 验收门禁

| 门禁 | 通过条件 | 不通过处理 |
|---|---|---|
| G0 内容事实 | 文案/数值/单位与数据源一致 | 回到剧本/SCG，不猜测 |
| G1 组件结构 | 文本、图标、面板、粒子可分层编辑 | 拆层，不接受扁平图冒充工程 |
| G2 参数控制 | 颜色、位置、尺寸、时长、粒子参数可修改 | 暴露参数或调整数据合同 |
| G3 时间复现 | 同 seed/同时间/同输入重复渲染一致 | 固定随机源与时间步长 |
| G4 视觉可读 | 不遮脸、关键动作、对白；文字不裁切 | 降低密度/移动布局 |
| G5 Alpha 交付 | 文件真实包含 Alpha，边缘无明显黑/彩边 | 修正编码/Alpha 模式 |
| G6 空间合成 | 锚点、透视、前后遮挡与镜头移动合理 | 补跟踪/matte，或降级为屏幕空间 |
| G7 跨镜连续 | 同 ID 的内容、样式和状态正确继承 | 回到共享事实和时间轴修复 |

状态必须分开记录：已设计 / 已生成代码 / 已运行预览 / 已导出 / 已验 Alpha / 已完成空间合成 / 已通过跨镜验收。不得用较低状态冒充更高状态。

## 7. 失败诊断

- 文字乱码/数值错误：检查数据源和字体覆盖；禁止用生图补字。
- 面板每镜变样：检查 effect_id/style_id/continuity_group 是否稳定。
- 粒子每次形状不同：检查 seed、固定时间步长和随机数注入。
- 透明视频黑底：检查容器、编码像素格式、Alpha 标记和解码帧；不要只换播放器。
- 人物手指被 UI 盖住：缺少前景 matte/遮挡层，不是透明导出故障。
- 面板随镜头漂移：检查坐标空间、锚点、跟踪和透视；不要用随意补偿位置掩盖。
- 画面过乱：先减少环境粒子和氛围层，再调整主面板。
- 移动端卡顿：降低粒子数、DPR 和 shader 复杂度；停止不可见动画。
- ChatCut 接口不可用：报告缺少真实执行入口，不得宣称完成；保留源文件供后续导入。

## 8. 必须覆盖的回归样例

1. 文字和数字精确，修改数据只改变对应字段。
2. 同一 UI 资产更换主题色，布局和内容不变。
3. 同一粒子参数和 seed 重复运行，关键帧一致。
4. 入场/退场没有突然闪现、残留或裁字。
5. UI 在深色、浅色和棋盘格背景均可读。
6. Alpha 输出真实透明，首尾帧为空，透明边缘无明显污染。
7. 手部前景遮挡正确；没有 matte 时必须明确失败。
8. 镜头轻微移动时世界空间 UI 跟踪稳定；屏幕空间 UI 不应无故漂移。
9. 同一 effect_id 跨镜继承样式、数据和状态。
10. 手机画幅中 UI 不遮挡人物脸、对白和平台安全区。
11. 粒子不覆盖主文字和关键动作。
12. GPU/Canvas 故障有可见降级，不输出黑帧。

## 9. 来源和证据治理

- 现有 ChatCut Skill 是用户已维护的上游生产入口；不复制其专有接口实现，只按其接口约定调用。
- iart-ai 的 Lower Thirds、Particle System、Shader GLSL 和 After Effects 技能可作为公开技术参考；使用其代码/文档时必须保留 MIT 许可与版权声明。
- Motion Graphics / UI Animation 其他候选的许可证必须逐仓库、逐版本核实；不能因为某个合集是 MIT 就推断所有第三方依赖都兼容。
- 每项结论标记 E0–E4 证据等级。仓库内容可读取为 E1；脚本可在隔离环境运行复现为 E3；在目标 ChatCut 漫剧镜头完成对照为 E4。
- 本规范发布不代表已在用户 ChatCut 账户或本地软件安装运行。

## 10. 交付清单

每个正式系统 UI/VFX 资产交付：
- 可编辑源（JSX/Canvas/SVG/Shader 或工程文件）。
- 参数清单和稳定 effect_id。
- 引用的内容数据与素材依赖。
- 时间线位置、事件触发和跨镜状态。
- 透明导出文件（需要时）及 Alpha 验收证据。
- 首帧/峰值/稳定/尾帧截图或联系表。
- 已验证、未验证、阻塞项分开列出。
