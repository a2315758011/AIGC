# 多镜头连续性记忆、世界状态继承与导演交接研究（第七批）

日期：2026-11-01  
研究目标：让一部漫剧的场景、人物、道具和空间关系跨镜头持续存在；镜头只改变被剧情授权的状态，而不是每一镜重新生成一个世界。  
本批证据分为：同行评审论文/论文页面、开源仓库固定提交与许可证、创作者工作流/比较研究。未安装软件、未运行第三方工程、未调用目标视频模型，不把论文结果等同于本机或商业模型实测。

## 一、核心结论

最可靠的工程方向不是“每个镜头都重新写一次提示词”，而是建立：
1. **持续场景记忆**：场景、建筑拓扑、固定家具和世界坐标有稳定身份/版本。
2. **持久资产库**：角色、服装、道具、车辆等使用稳定资产ID和版本，不因重生成而丢失原始资产。
3. **镜头状态链**：每个镜头引用上一个镜头的结束状态；只有明确事件允许状态变化。
4. **摄影机与主体分轨**：镜头换角度不改变人物世界位置；人物移动不伪装成摄影机移动。
5. **人工审批和锁定**：已批准的角色身份、场景锚点和镜头末态不能被AI静默覆盖。
6. **分层验收**：结构化状态通过、白模预演通过、真实图像/视频通过是不同等级，不能相互替代。

这与 AIGC 仓库现有 SCG（实体/关系/事件）、人物站位 V1.9.0 和导演统筹 Skill 的方向一致。本轮新增的是导演层交接元数据，不另造一套镜头世界状态数据库。

## 二、论文与研究方法

### 1. StoryBlender：跨镜头一致、可编辑的3D故事板
- 项目研究说明：https://1fwang.github.io/storyblender2026/
- 论文发表信息：ECCV 2026。
- 关键方法：连续性记忆图连接持续资产与逐镜变量；canonical assets 置于统一坐标系；空间-时间动态描述相机、对象和场面调度变化；通过引擎反馈修订场景。
- 对漫剧的价值：摄影机或人物调度变化应当是同一场景的编辑，而不是每镜重新创建一套人物和空间。
- 限制：这是研究方法/项目论文介绍，不代表任意图像/视频生成模型具备相同的持久场景记忆；本轮没有运行其引擎。

### 2. DreamShot：多参考角色条件与前镜续接
- CVPR 2026 官方论文页：https://openaccess.thecvf.com/content/CVPR2026/html/Huang_DreamShot_Personalized_Storyboard_Synthesis_with_Video_Diffusion_Prior_CVPR_2026_paper.html
- 论文指出，单独生成每张故事板图容易丢失长程时间一致性、角色身份和叙事连贯性。
- 方法包含多参考角色条件模块、角色注意力一致性约束，以及基于前序帧的故事续接。
- 对漫剧的价值：角色身份参考不应只存在于单镜提示词中；跨镜生成应尽可能继承上一镜的视觉状态。
- 限制：论文模型/实验的结果不证明用户当前使用的消费级模型已开放同样的角色注意力控制接口。

### 3. CANVAS：视觉代理式连续性规划
- 论文：https://arxiv.org/abs/2604.13452
- 方法：多 Agent 显式规划人物连续性、持久背景锚点和位置感知的场景规划。
- 论文报告在其基准上相对最佳基线，背景连续性提升21.6%、角色一致性提升9.6%、道具一致性提升7.6%。
- 对漫剧的价值：跨镜检查必须同时检查背景、人物、道具，不能只比对角色脸。
- 限制：指标是论文自建基准结果，不应直接转化为用户生产成功率；未独立复现。

### 4. Story2Board：轻量级多格连续性
- 论文：https://doi.org/10.1111/cgf.70319
- 首次发表：2026-04-08。
- 研究 Latent Panel Anchoring 与 Reciprocal Attention Value Mixing，在不微调模型的条件下增强多格故事板的一致性。
- 采纳启示：对于轻量工作流，可以共享角色锚点并做相邻画格的信息关联；不能将论文算法描述成普通提示词天然具有的功能。

### 5. 绿幕动作参考对提示词流程的对照研究
- 研究页面：https://icct.iacst.org/icct2026/program_paper_view.php?submitno=1781
- 摘要描述：30个故事板任务、保留60条视频，比较同样文字/角色参考和 Seedance 2.5 设置下，是否增加绿幕视频参考。
- 研究报告观察到视频参考组在构图、运动路径和人物出现方面更符合预期。
- 采纳启示：复杂人物走位应优先考虑可视化动作参考/预演素材，而不是只增加文字长度。
- 证据等级：E1。当前页面提供会议论文摘要和方法描述；未获取完整论文数据、原始视频与独立复现，不能把结果当作已确认因果。

## 四、合并后的单剧生产数据流

### A. 剧本与场景底稿
1. 锁定剧本版本、场次 ID、人物出场和剧情事件。
2. 每个固定场景建立 scene_id、world_revision、static_world_revision。
3. 建立角色/服装/道具/场景资产唯一ID与版本。
4. 参考图按职责登记：布局真值、建筑、人物身份、服装、道具、机位；同字段同优先级冲突必须阻断。
5. 用户确认的门窗、家具、人物座位等写入 locked invariants；未知项独立登记。

### B. 镜头链与世界状态
1. 每个镜头有稳定 shot_id，并引用 SCG 的 scg_shot_id。
2. SCG 每镜保存完整世界状态快照；导演交接包只引用 SCG，不复制 entities/relations/events。
3. 下一镜从上一镜的末态继承；若人物位置、服装、道具持有关系或场景状态改变，必须有可追溯的事件。
4. 固定场景拓扑在同一 static_world_revision 下保持不变；剧情破坏/搬动固定物件必须显式批准新版本。
5. 摄影机轨迹单独存储；机位变化不等于人物世界坐标变化。

### C. 生成与审批
1. 每镜保存提示词版本、参考素材映射、生成任务ID和结果文件路径。
2. 失败/拒绝样片保留原因，但不更新已批准的永久连续性状态。
3. 只有人工批准的 End State 才能传递给下一镜 Start State。
4. 已批准状态锁定；后续修改创建新版本，不能覆盖历史原件。

### D. 验收分层
- G0：剧本事实与资产身份一致。
- G1：场景拓扑/布局/参考图职责一致。
- G2：SCG实体、关系、事件和跨镜状态一致。
- G3：人物路径、姿态、朝向、支撑和视线一致。
- G4：摄影机轨迹不篡改主体世界状态。
- G5：真实图像/视频按帧检查，确认模型是否实际服从。
- G6：人工批准 End State，才能进入后续镜头。

## 五、本轮AIGC仓库实施决定

- 不新增第二套 SCG 或重复实体数据库。
- 新增导演层“世界状态交接数据契约”，只存 scene/world revision、资产ID、参考图职责、锁定事实、镜头链引用、时间基准和未知项。
- SCG 继续作为每镜完整实体/关系/事件状态的唯一事实源。
- 事件时间契约继续管理镜头和事件时间；人物站位规则继续管理人物状态；运镜技能继续管理摄影机轨迹。
- 新增独立结构校验，正向/负向测试覆盖：场景版本漂移、镜头前驱错误、参考图权威冲突、未声明资产、绕过事件修改状态、摄影机/人物轨迹混用、重复镜头ID、重复复制SCG状态。
- 所有新增知识暂列低等级候选，直到真实项目、真实图像/视频和独立审片验证。
