# SCG 三维预演与碰撞检查扩展契约 V1

## 目的与权威边界

本规范是现有 SCG 的可选三维几何扩展，不建立新的 shot/entity/state 数据库。

- 场景数据库 `漫剧场景空间数据库_SCHEMA_V1.json`：权威保存固定建筑、家具、静态占地、坐标系和摄影机预设。
- SCG `scene.shots[].entities/relations/events`：权威保存逐镜实体快照、人物/道具动态关系和动作事件。
- 本扩展校验器：读取 SCG 的实体/关系/事件，并用场景数据库的固定几何作为障碍来源。实体 ID 必须稳定对应；不得复制固定家具数据后各自修改。
- 现有二维路径校验器保留，三维校验器补充高度、身体占地和摄影机实体的空间碰撞检查。

## 一、统一坐标定义

场景坐标统一为右手坐标系：X 左右、Y 前后、Z 高度；单位由场景数据库 coordinate_system.units 指定。SCG 中所有 world_position 和路径点必须使用同一单位与原点。

- 固定家具/建筑障碍的 world_position 定义为底面中心。
- 人物胶囊体的 world_position 定义为脚底中心。
- 摄影机球体的 world_position 定义为摄影机光心。
- 禁止把像素坐标、归一化画面坐标、米制坐标混用。场景数据库 units 为 normalized_0_to_1 时，仅允许同一归一化空间内的相对碰撞检查，不得声称真实人体尺寸或建筑净空已验证。
- 缺少 Z、高度、体积或坐标单位时，结果必须是 UNRESOLVED，不得把未知当作零。

## 二、SCG 实体几何字段

在 entity.attributes 中可选增加：

```json
{
  "world_position": {"x": 1.2, "y": 2.4, "z": 0.0},
  "collision_volume": {
    "shape": "capsule",
    "radius": 0.22,
    "height": 1.72
  },
  "collision_role": "actor"
}
```

支持的碰撞体：
- `box`：`width/depth/height`，底面中心锚定于 world_position。
- `capsule`：`radius/height`，竖直胶囊体，底部锚定于 world_position；仅用于直立/近似直立代理。
- `sphere`：`radius`，中心锚定于 world_position；适合摄影机光心或球形代理。

固定障碍可直接引用场景数据库对象 ID，并从对象的 position/footprint/collision_volume 读取几何。若障碍只提供二维 footprint，没有 height，则只能做平面检查，三维检查报告 UNRESOLVED。

当前 V1 的自动碰撞使用保守 AABB（轴对齐包围盒）近似。旋转家具、非凸结构、网格碰撞、骨骼姿态和复杂形状必须由 3D 引擎进一步验收；AABB 命中可能产生保守误报，不能当作精确物理碰撞结论。

## 三、移动事件字段

移动仍使用 SCG event，不另建动作账本：

```json
{
  "id": "EV-MOVE-01",
  "source_id": "SCRIPT-LINE-12",
  "actor": "CHAR-A",
  "action": "move",
  "motion": {
    "entity_id": "CHAR-A",
    "from": {"x": 1.0, "y": 1.0, "z": 0.0},
    "waypoints": [{"x": 1.5, "y": 1.0, "z": 0.0}],
    "to": {"x": 2.0, "y": 1.5, "z": 0.0},
    "start_ms": 0,
    "end_ms": 1600
  },
  "effects": [
    {"kind": "set_position", "entity": "CHAR-A", "to": {"x": 2.0, "y": 1.5, "z": 0.0}}
  ]
}
```

- from/to/waypoints 必须是 XYZ 三维坐标；所有时间使用同一项目毫秒时间轴。
- 角色整体位移轨道与骨骼/姿态动作轨道必须分开；只有路径而没有行走/跑步/坐下等姿态证据，不得宣称动作自然。
- 本校验器只检查代理几何沿线的静态障碍碰撞，不检查关节自碰撞、步态、脚底滑动或动态角色之间的连续物理接触。

## 四、摄影机运动

摄影机必须作为具有稳定 ID 的 SCG entity，使用 sphere 碰撞体描述光心附近的机身/镜头安全半径；摄影机路径也使用 event.motion。

- 摄影机路径独立于人物路径。
- 摄影机光心轨迹不得穿过已知墙体、柱体、家具等障碍。
- 摄影机看向目标/注视点是独立方向通道；不能把一次性 look-at 误认为持续跟随。
- 摄影机无碰撞不代表画面构图合格；视锥遮挡、FOV、焦距、景别和轴线仍需真实相机预览。
- 没有相机实体/路径数据时，标记 UNRESOLVED，不得声称已完成相机避障检查。

## 五、检查结果

- `3D-MOTION-01`：路径点缺少 XYZ 或数值非法。
- `3D-MOTION-02`：移动事件时间区间无效。
- `3D-MOTION-03`：角色/摄影机代理路径与已知三维障碍 AABB 相交。
- `3D-MOTION-04`：路径终点落入已知障碍 AABB。
- `3D-MOTION-05`：移动起点与上一镜世界坐标不一致。
- `3D-MOTION-06`：移动终点与本镜实体世界坐标不一致。
- `UNRESOLVED`：单位、Z、高度、碰撞体、障碍几何或实体 ID 对应关系缺失。

## 六、放行门槛

1. 固定场景数据库结构校验通过。
2. SCG 实体/关系/事件基础校验通过。
3. 三维路径碰撞回归通过，且没有未解释的 UNRESOLVED。
4. 3D 白模中检查俯视、正视、侧视和实际镜头视角。
5. 人物动作需检查起始、中间关键帧、接触/转向点和结束姿态。
6. 摄影机需检查完整路径、墙体/家具避障、注视方向和画面遮挡。
7. 目标视频模型输出必须与预演逐镜对照；白模通过不代表生成模型服从。

任何一项缺失都必须标记未验证/阻塞，不能把结构化数据通过升级成实际视频质量通过。
