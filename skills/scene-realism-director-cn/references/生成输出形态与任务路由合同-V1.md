# 生成输出形态与任务路由合同 V1.0

版本日期：2026-11-01  
适用：场景图、正交俯视图、角色/道具单视角资产、多视角资产组、联系表和信息图。  
目标：防止用户要一张真实场景图，生成器却输出多面板信息图、拼贴、评分报告或把多个视角拼成一张图。

## 1. 先锁定唯一输出对象

每次生成前必须明确一个 output_mode：

| output_mode | 一次任务的目标 | 默认数量 |
|---|---|---:|
| single_scene_image | 一张独立场景实景图、一个机位、一个投影 | 1 张 |
| single_orthographic_plan | 一张独立正交俯视/平面图 | 1 张 |
| single_view_asset | 一张角色、道具或环境单视角资产 | 1 张 |
| multi_view_set | 同一资产的多张独立视角图 | 每个视角单独成图 |
| multi_panel_infographic | 多面板信息图、对照板、联系表 | 仅用户明确要求时 |

**默认原则：一个生成任务 = 一个交付对象 = 一个视角 = 一张独立图片。**

用户明确要求拼图、联系表、信息图、分镜板或评分看板时，才选择 multi_panel_infographic。不能因为历史上下文曾经讨论过看板、平面图、分镜或评分，就自动把它们加入当前单图任务。

## 2. 单张场景图的硬约束

当 output_mode 为 single_scene_image：

- 只生成一张真实场景图片、一个相机机位、一种投影方式。
- 不得附加俯视平面图、侧视图、分镜格、第二机位、局部放大窗或对比面板。
- 默认不在图片中生成标题、说明文字、图例、尺寸标注、评分、勾叉、结论、品牌水印或“已通过”标签。
- 画面必须是用户指定的场景本身，不得将“如何验收该场景”的说明图替代场景图。
- 若用户要求不出现人物、文字或某类物体，必须作为显式约束保留。
- 不得为了填充画面擅自增加与场景用途冲突的对象。

当 output_mode 为 single_orthographic_plan：

- 只生成一张正交俯视图，不得混入人眼视角照片、侧视图或信息图面板。
- 必须明确视图方向和投影类型；正交俯视不能偷换成高角度斜俯视。
- 建筑边界、墙体厚度、开口、家具和通道按任务要求完整呈现。

当 output_mode 为 multi_view_set：

- 每个视角默认单独生成、单独保存、单独验收。
- 多视角一致性必须基于同一份布局/资产真值与稳定锚点逐张核对。
- 把几张看似相似的图片拼在一起，不构成“同一空间/同一角色”的一致性证据。

## 3. 任务路由前置检查

提交前按顺序核对：

1. 当前用户要的是场景成品、平面图、单视角资产、多视角组，还是明确的信息图？
2. 本次任务只包含一个输出对象吗？若包含多个，是否由用户明确要求合并？
3. 机位、视角、投影方式是否唯一且明确？
4. 是否误带了历史任务中的评分、看板、人物剧情、平面图或分镜内容？
5. 当前生成工具是否能够把本次任务描述绑定到真实请求？若工具不暴露有效提示词/请求记录，标记为不可审计，不得将结果用于严格 A/B。

## 4. 结果验收与失败处理

生成后先检查“输出形态”，再检查“场景真实性”：

- 输出形态符合请求：进入建筑、空间、功能、透视、物理、光照和材质验收。
- 输出形态不符合请求：标记 P0，状态为 OUTPUT_MODE_MISMATCH；该图片不得计入场景样本、A/B 配对或资产母版。
- 图片里出现未经请求的评分/“通过”结论：这些文字不是验收证据；按 P1 记录，独立检查仍须重新执行。
- 工具未返回有效请求记录，且结果与目标不符：根因标记 unknown/probable，不猜测隐藏提示词或模型版本。

**首次输出形态错误后必须停止相同工具调用的原样重试。** 先检查任务路由、请求绑定、历史上下文污染和生成适配器；只有确认修正了失败条件，才允许用不同请求或已验证的适配器重新测试。共享服务未健康时，不提交新任务。

## 5. A/B 测试边界

- A、B 每个样本都必须是独立单图，不能用拼贴图替代。
- A/B 必须保持同一场景事实、视角、画幅、模型和可见参数；无法固定种子或模型版本时标记为探索性。
- 先判断输出形态是否合格；形态不合格的样本不进入空间真实性评分。
- 评分、标签和结论必须存在于外部评审记录中，不允许让生成器把自评分数画进图片，再把它当作验收证据。
- 本合同和静态回归只验证任务路由与失败处理规则，不证明任何图像模型必然服从。

## 6. 本仓库回归

运行：

```bash
node skills/scene-realism-director-cn/tests/validate-generation-output-contract.cjs
```

测试夹具位于 `tests/fixtures/生成输出形态回归-V1.json`。测试覆盖单张场景图、单张正交俯视图、明确要求的信息图、未请求的信息图、混合视角、模型自评分、缺少多视角共享参考、错误后原样重试以及请求绑定不可审计等情况。

静态回归通过只说明合同判定逻辑符合预期；真实生成器服从率仍需目标模型实测。
