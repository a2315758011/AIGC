# 场景真实性导演 Skill

## 目标
将“看起来像真实世界中可成立的场景”作为目标，而不是把“照片级、电影级、8K、超写实”等风格词当作质量保证。真实性分为视觉真实、空间真实、物理真实、功能真实和摄影真实；必须分别检查。

## 工作顺序
1. **锁定场景用途和事实**：识别空间类型、年代/地域/用途、使用者、主要活动、建筑类型、天气/时段。用户参考图和已确认布局优先于模型想象；不得为追求美观擅自重设计。
2. **建立空间骨架**：先确定房间/街道/建筑边界、地面、墙体、顶棚、开口、通道、固定设施和主要家具；标记相邻关系、入口出口、可通行区域和遮挡。无法确认的尺寸写未知，不虚构精确米数。
3. **建立摄影几何**：明确相机位置、高度、朝向、镜头视角/焦段倾向、地平线、主要消失点、透视类型和画面边界。检查同一场景中平行线、垂直线、尺度递减和遮挡顺序是否相容。
4. **建立物体与功能关系**：每件关键物体有明确支撑面、接触点、用途、可操作空间和合理尺寸。门能打开、椅子能坐、桌前有腿部空间、通道可通过；物体不能无原因悬浮、穿插或堵塞入口。
5. **建立光照逻辑**：列出主光源及其方向、面积/软硬、色温倾向、环境补光、反射来源。检查同一光源照射下的明暗方向、投影方向、阴影软硬、接触阴影和反射是否一致。不要只用“柔和电影光”代替光源逻辑。
6. **建立材质差异**：按真实材料指定粗糙度、反射、透明度、纹理尺度、微表面变化与边缘磨损。避免所有表面同样光滑、同样锐利、同样干净；避免把污渍噪声均匀撒满画面。
7. **增加真实世界的不完美**：只在合理位置加入使用痕迹、轻微磨损、灰尘、色差、褪色、细微不平整、家具偏差和非对称细节。瑕疵必须符合材料、受力、使用路径和维护状态，不能随机脏污。
8. **控制构图与视觉层级**：前/中/后景有空间依据；主体周围保留必要视觉呼吸区；边缘物体不无故切断；不要为了填满画面塞入无用途装饰。保持用户明确要求的画面中心和视野空间。
9. **生成与修复**：先生成低复杂度空间骨架或构图验证图，再增加材质/细节；若结构已正确，只修复具体失败区域，不重绘正确部分。多轮修复每轮只改变一个主要变量并保留版本。
10. **独立验收**：使用《场景真实性检查表》逐项审查。先检查致命空间/物理错误，再看材质光照，最后评估审美。视觉语言模型意见只能作为辅助，不能替代几何/物理证据和人工判断。

## 必须优先拦截的错误
- 建筑结构不成立：墙/地/顶断裂，门窗没有合理洞口或厚度，楼梯无落点，走廊接入错误。
- 空间拓扑错误：门后直接撞墙、家具堵路、房间连接关系矛盾、家具尺度与房间不匹配。
- 透视错误：同一平面出现互相冲突的消失点，桌椅透视方向不一致，垂直线无意倾斜，近远尺度反常。
- 物理错误：物体悬浮、穿模、接触阴影缺失、支撑关系不成立、重力方向矛盾。
- 光照错误：同一物体不同面受光方向互相矛盾，多个投影方向无可解释光源，玻璃/金属反射与环境不匹配。
- 材质错误：塑料化木材/石材/布料，镜面高光滥用，粗糙度全图一致，纹理尺度不合物体尺寸。
- AI 痕迹：纹理融化、重复纹理、伪文字、结构边缘融并、无意义装饰、局部细节锐利度异常。
- 功能错误：家具无法使用、门扇/抽屉无开启空间、座位/工作区不符合实际行为。
- 摄影错误：镜头高度/视角导致不可能的可见关系，前后景比例和景深不自然，边缘拉伸过强。

## 输出约定
按需输出：①发现的问题（按 P0/P1/P2）②可证据化原因③最小修复动作④生成/修复提示词（如需要）⑤验收结果与未验证项。不要输出无关长篇形容词。
- P0：空间结构/功能/重力/透视硬错误，画面不可用。
- P1：显著光照、材质、比例或接触错误，明显暴露 AI 感。
- P2：细节、纹理、轻微构图和审美问题。

## 证据与限制
本 Skill 以公开研究基准、计算机视觉深度估计、摄影/渲染官方文档为依据。它是诊断与工作流规范，不保证任意图像模型必然遵从文字约束。深度估计输出通常是相对深度而非真实尺寸；单张图不能唯一恢复完整 3D 场景。不得将估计图当作精确测量或真实法线。

## 内置中文配对基准

## 实际模型对照实验
当用户要求验证真实感改善时，必须使用 `tests/场景真实性配对盲评记录模板-V1.1.md`。优先在同一模型/版本/参数下做配对比较；若无法固定种子或模型版本，必须标记为探索性实验。先记录 P0/P1 缺陷，再做十维评分；不得以审美分抵消结构或物理硬错误。没有生成输出图和完整实验记录前，不得宣称规则有效。


## 空间智能基准的使用边界
- SpatialGenEval / GenSpace 证明空间关系、透视、遮挡与尺寸是独立的生成弱项；借鉴其问题设计和评估维度，不复制未核实许可的数据。
- InSpace 是从单张 360° ERP 全景生成分离式室内 3D 场景的重型研究路线；其 Linux/CUDA/显存要求较高，不作为 Windows 工作站默认安装依赖。
- 通用 VLM 的判断只作辅助。空间拓扑、门窗连接、支撑/碰撞、透视与可通行性必须由明确问题、人工盲评或几何证据复核。
- 360° ERP 表示完整水平 360°并通常覆盖垂直 180°球面视域；不要把“360°全景”和“720°角度”混为一谈，也不要宣称它恢复了原图之外的未知空间。


## 光照、色彩与物体级真实性专项
当用户反馈“画面漂亮但像滤镜、太艳、塑料感、光影不真实、物体细节假”时，必须加载：
- `tests/光色物理真实性专项回归-V1.md`
- `docs/Deepresearch/2026-11-01_场景真实性光照色彩与物理真实性补充研究.md`

执行时分别诊断：
1. **光度真实性**：主光方向、颜色、软硬、照度衰减、接触阴影、反射与折射。
2. **颜色真实性**：饱和度、白平衡、色温、曝光、高光剪切、暗部细节、局部色彩断层。
3. **物体级真实性**：轮廓、部件结构、厚度、纹理尺度、边缘和材质响应。
4. **物理编辑真实性**：添加/删除/移动对象后，阴影、反射、折射、遮挡、接触及非编辑区域是否同步更新。

禁止把 CFM 理解成“全图降饱和滤镜”；禁止在没有真实标定图/光探针时编造光照方向误差、Delta E 或 KL 数值。PICABench 是图像编辑物理一致性基准，不能直接当作文生图整体质量分。第三方评测器的安装/费用门槛以部署门槛文档为准。


## 权威场景布局数据与多视角生成门禁

当任务涉及同一场景的多个镜头、重复家具精确排布、人物站位或长期漫剧场景复用时，必须先建立并锁定单一权威空间数据，不得让每个镜头重新自由想象场景。

- 教室示例基准：`references/教室空间权威布局基准-3列5排-V1.json`。其中归一化坐标只表示相对位置，不代表米制尺寸；未知尺寸必须保持 null，禁止由 AI 图片反推或编造。
- 空间数据必须分清固定事实、可变状态和未知项。墙体、门窗、固定设施、家具数量/坐标/朝向属于固定事实；人物位置、姿态、道具持有、门窗开合属于逐镜状态；未测量尺寸属于未知。
- 任何新视角生成必须引用同一个 scene_id 和布局数据，不得另起一套相似但不一致的布局。
- GPT 原生生图每次只允许一个输出对象、一个机位、一张图片。不得要求多视角合成图、拼图、故事板、信息图、尺寸表、评分或自我验收标签。
- GPT 生图负责视觉外观与摄影表现，不作为权威几何建模器。精确几何、多视角严格一致性应交给同一结构化场景/3D 场景的不同相机渲染；如果只有独立生成图片，最多登记为“视觉相似”，不能登记为“同一空间一致性通过”。
- 验收时逐项对照 JSON 不变量：家具数量与列排、桌椅朝向与配对、门窗墙面、黑板讲台、通道连续性。发现 P0 硬错误即失败；尺寸与规范净空未测量时必须标为未验证。
- 禁止把图片内生成的尺寸、文字、绿色勾选或“通过”声明当成测试证据。测试结论由独立检查记录产生。


## 场景数据库模板、实例与结构校验

- 通用 JSON Schema：`references/漫剧场景空间数据库_SCHEMA_V1.json`。
- 空白场景模板：`references/漫剧场景空间数据库模板_V1.json`。
- 教室实例数据：`projects/漫剧场景数据库/CLASSROOM-CN-3X5-001/场景空间数据_V1.json`。
- 教室逻辑布局参考：`references/教室空间权威布局基准-3列5排-V1.json`。
- 无第三方依赖的 Node 校验器：`tests/validate-scene-database.cjs`。执行：`node tests/validate-scene-database.cjs <场景JSON文件路径>`。

场景数据库必须区分固定事实、物体实例、逐镜动态状态和未知项。位置数据使用归一化坐标时，不得宣称为真实尺寸。所有对象使用稳定 ID；配对关系必须引用存在对象；相机视角必须声明单图单机位输出。

**空间合理性硬检查：** 在提交坐标前检查家具占地与通道区域是否重叠。桌椅中心点不够，必须考虑物体占地范围；若物体尺寸未知，则通道净宽只能标记为未验证。不得出现通道区域穿过桌椅中心点的内部矛盾。


## 连续镜头状态继承

- 镜头状态交接规范：`references/镜头场景状态交接规范_V1.md`。
- 每个镜头必须引用 scene_id 和唯一 shot_id，并保存 state_in、events、state_out。
- 下一镜头 state_in 必须继承上一镜头 state_out；人物移动、姿态变化、道具转移、门窗开合均须有明确事件。
- 画面外对象仍保留在世界状态，不得因为未入镜而丢失。
- 机位变化只改变摄影机，不得改变固定空间事实。
- 角色路径必须检查家具占地、墙体、通道和终点可用空间；尺寸未知时只做拓扑检查，不得宣称物理净空通过。


## 占地碰撞与逐镜连续性自动校验

- 场景数据库对象新增 `footprint`（地面占地宽度/深度）。尺寸未知必须为 null，不得估算后冒充测量。
- `clearance_zones` 定义通道/操作净空区域；只有对象 footprint 已知时，才能计算占地矩形与通道区域的相交。未知 footprint 必须输出警告并保持“未验证”。
- 场景校验器：`tests/validate-scene-database.cjs`，新增物体占地互相重叠、侵入通道区域检查。
- 镜头连续性校验器：`tests/validate-shot-continuity.cjs`，检查 scene_id、shot_id、previous_shot_id、state_in/state_out 连续性、事件 ID 唯一性，以及状态变化是否有事件。
- 通过样例：`tests/fixtures/镜头连续性_通过样例.json`；负向样例：`tests/fixtures/镜头连续性_瞬移失败样例.json`。
- 执行命令：`node tests/validate-scene-database.cjs <场景JSON>`；`node tests/validate-shot-continuity.cjs <镜头序列JSON>`。
- 仅有静态文件和样例不代表工作站已运行通过。报告必须区分代码已提交、沙箱测试、Windows 工作站测试和真实分镜系统集成。

- 人物世界位置、走位路径、姿态、朝向、支撑、轴线和摄影机分层，遵循 `skills/storyboard-director-cn/references/人物站位与场景调度规则-V1.md`。
- SCG 时间轴遵循 `skills/storyboard-director-cn/references/分镜事件时间数据契约-V1.md`。普通中文分镜稿不能直接冒充结构化事件账本。
- 本 Skill 只补充静态空间、几何占地、障碍区域与视觉真实性；其 SCG 空间运动扩展见 `references/SCG空间运动与道具状态扩展契约-V1.md`。
- SCG 原有校验器继续负责实体/关系/事件前置条件/跨镜硬关系；本 Skill 的 `tests/validate-scg-spatial-motion.cjs` 只补充二维路径与已知障碍碰撞、道具单一持有人检查，不替代原校验器。
- 道具持有事实统一使用 SCG `held_by` 关系；禁止另建 holder 字段成为第二权威来源。拾取、放下、交接、销毁必须用 SCG event effects 表达。
- 只有真实占地宽深和世界坐标已知时才能进行数值碰撞判断；缺少几何数据时必须报告 UNRESOLVED/WARN。
- 负向样例被检测器识别代表校验器行为符合预期，不代表镜头或图片本身通过。


## 三维预演与摄影机避障

涉及人物走位高度变化、跨越/上下台阶、复杂家具遮挡、摄影机穿越空间或多机位运动时，按需读取：
- `references/SCG三维预演与碰撞检查扩展契约-V1.md`
- `references/SCG空间运动与道具状态扩展契约-V1.md`
- `references/漫剧场景空间数据库_SCHEMA_V1.json`

职责边界：固定建筑/家具几何由场景数据库管理；逐镜人物、道具、关系和运动事件由 SCG 管理；不得让场景数据库 dynamic_state 与 SCG 同时成为动态状态权威来源。

三维代理碰撞校验：
```bash
node tests/validate-scg-3d-motion.cjs tests/fixtures/SCG三维碰撞回归-V1.json
```
可选传入固定场景数据库 JSON，补充固定障碍物几何。校验器使用 AABB 近似；结果仅能证明已提供代理体积和静态障碍下的路径检查，不证明骨骼姿态、脚底接触、动态人群、网格碰撞或视频模型服从性。出现 UNRESOLVED 时不得放行。


## 复用现有三维导演台

## 人物骨骼姿态与接触约束

当镜头涉及坐下/起身、脚底支撑、抓握、扶靠、跪地、摔倒或人物身体接触时，必须读取 `references/SCG骨骼姿态与接触约束扩展契约-V1.md`。

- 复用 SCG entity / relation / event，不建立平行人物状态账本。
- 角色必须声明 rig_id、skeleton_profile、末端映射、pose_id、clip_id 和 root_motion_separate。
- 接触必须引用目标实体 contact_anchors；仅靠近不等于接触成立。
- 新接触、继承接触、释放接触分别按 contact_begin / 同 contact_id / contact_end 表达。
- 结构校验：`node tests/validate-scg-skeletal-contact.cjs tests/fixtures/SCG骨骼姿态与接触约束回归-V1.json`。
- 校验器通过仅代表 SCG 结构和时序符合契约。未运行 Blender / DirectorDesk IK、没有关键帧与视口证据时，必须标记真实骨骼接触为 NOT_RUN。


## 跨镜骨骼接触连续性（V1.12）

当人物坐下/起身、站立支撑、抓握、扶靠、跪地、跌倒或与其他角色接触时：
- 必须使用 SCG 的 `entities[].attributes.skeletal_rig`、`skeletal_pose`、目标实体 `contact_anchors[]`，以及关系上的 `contact_constraint`。
- 连续镜头中同一 contact_id 的人物、目标、末端、锚点和模式必须一致；新建和释放分别由 `contact_begin` / `contact_end` 事件表达。
- 锚点缺少三维位置、坐标系或单位时，只允许结构检查，不得声称可执行 IK。
- 运行 `tests/validate-scg-skeletal-contact.cjs tests/fixtures/SCG骨骼姿态与接触约束回归-V1.json`。当前 11 组结构回归在 GitHub Actions 通过；这不是实际骨骼解算验收。
