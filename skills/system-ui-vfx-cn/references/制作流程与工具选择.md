# 制作流程与工具选择

## 一、先判定镜头需要什么

| 需求 | 首选机制 | 典型实现 |
|---|---|---|
| 系统通知/弹窗 | 可编辑 UI 组件 | JSX + SVG + 真实文本 |
| 属性变化/升级 | 数据驱动动画 | 数值插值、进度条、状态切换 |
| 技能卡/装备栏 | 组件化面板 | 稳定组件 + 数据对象 |
| 魔法阵/符文 | 矢量路径动画 | SVG path、描边绘制、旋转 |
| 扫描线/全息光 | 独立光效层 | SVG/Canvas，必要时 Shader |
| 火花/尘埃/星点 | 粒子系统 | Canvas 2D + 固定 seed |
| 高密度能量流 | GPU 粒子/流场 | Three.js Points + Shader |
| 人物手部投影 | 空间锚点 + matte | 跟踪、透视、前后遮挡合成 |

## 二、ChatCut 直接 JSX 工作流

用户现有的 chatcut-motion-graphics Skill 是首选平台入口。按它的接口契约执行：
1. 读取当前项目画幅、FPS、时间线、目标时长、字幕区域、人物安全区和邻近图形风格。
2. browse_library：查找已有图形，能复用则不新建。
3. 明确最终显示帧、图层结构、动画节拍和自然尺寸。
4. create_motion_graphic_from_code：传完整内联 JSX 源码、名称、尺寸、时长和可编辑属性。
5. edit_item：将图形放到时间线，设置位置、尺寸、时间和层级。
6. 修改已有图形前读取源码，再用 edit_asset 替换完整源码。
7. 回读项目并检查合成帧，不以“创建接口返回成功”代替预览验收。

当前执行环境没有这些 ChatCut 运行时动作时，停止在源码/规格交付，不得声称完成平台内创建。

## 三、组件分层

一个系统面板建议拆为：
1. 底板：面板形状、背景透明度、边缘材质。
2. 边框：SVG 路径、角标、刻度和扫描轨迹。
3. 标题与正文：真实文本节点，文案来自数据源。
4. 数值：独立字段，支持数字滚动/进度插值。
5. 图标：独立 SVG/资产，使用稳定 icon_id。
6. 动画控制：入场、停留、更新、退场状态机。
7. 光效：辉光、扫描线、局部闪烁，能单独关闭。
8. 粒子：单独发射器和生命周期。
9. 遮挡：人物/手指/道具 matte 或明确的深度层。
10. 声音事件：与 UI 事件共享 event_id 和时间锚点。

## 四、粒子系统实现规则

### Canvas 2D（默认）
适合几十到数百个 2D 粒子：
- 每个粒子保存位置、速度、加速度、年龄、寿命、尺寸、颜色和透明度。
- 更新使用固定或受限 dt；不要因浏览器卡顿出现粒子瞬移。
- 发射模式区分 burst（一次爆发）和 continuous（持续发射）。
- 使用固定 seed 的 PRNG；禁止生产测试依赖裸 Math.random()。
- 用寿命曲线控制透明度、尺寸和速度；粒子死亡后销毁或按设计复用。
- 只在粒子有明确来源时发射；火花从碰撞点，尘埃从受力表面，能量粒子从能量源。

### Three.js GPU Points（按需）
适合数千级以上粒子：
- 将位置/速度/seed/life 等作为 BufferGeometry 属性或自定义属性。
- 用 ShaderMaterial 驱动位置和尺寸；避免每粒子一个 DOM/对象。
- 明确透明混合、depthWrite、blend mode 和遮挡规则。
- 限制 DPR、shader octave、纹理读取和粒子总数。
- 组件卸载时 dispose geometry/material/renderer，停止动画循环。

### 复现与取帧
- 提供固定 seed、固定 timestep、指定时刻冻结接口（如 ?t=1.25）。
- 起始、峰值、衰减三个时刻至少各取一帧。
- 同 seed/同时间/同输入重复渲染应得到一致结果。
- 不允许用真实时钟随机抖动来掩盖动画缺陷。

## 五、透明导出与 Alpha

- ChatCut 官方文档说明 ProRes 4444 Alpha 属于 Pro 方案；先检查账户权限。
- WebM VP9 Alpha 适合浏览器/OBS；ProRes 4444 适合 Premiere/Resolve/Final Cut；PNG 序列适合逐帧合成。
- H.264 MP4 不含 Alpha；若必须输出 MP4，只能明确使用纯色背景抠像。
- 验收时检查 ffprobe 的像素格式/Alpha 标记，并解码中间帧确认透明像素存在。
- 在深色、浅色和棋盘格背景检查边缘；必要时检查 Straight/Premultiplied Alpha 解释。

## 六、人物遮挡与空间投影

Alpha 透明只解决底色，不代表 UI 知道人物在哪。
- 屏幕空间 UI：固定在画面坐标，不随人物世界坐标自动移动。
- 世界空间 UI：绑定稳定 anchor_ref，随人物/道具/场景变换。
- 若 UI 需要部分位于手掌后方、部分位于手掌前方，必须拆层或提供 matte。
- 镜头变化时需要透视投影/跟踪；没有跟踪数据时只能标记“空间绑定未验证”。
- 不能用一层透明视频覆盖人物并声称已实现真实遮挡。

## 七、禁止的重复建设

- ChatCut 已能直接制作并放置可编辑 JSX 图形时，不另建一套通用时间线编辑器。
- 普通 UI 不引入 Unreal Niagara。
- 普通矢量动画不引入完整 3D 场景。
- 已有参数化粒子可满足需求时，不重复开发第二套粒子运行时。
- 先测 ChatCut 的 Alpha 权限和现有组件能力，再决定是否使用外部渲染器。
