# 漫剧系统 UI 与程序化特效

## 目标

把系统界面与程序化特效制作成内容准确、参数可控、图层可编辑、时间可复现、空间关系正确、可跨镜继承的生产资产。

## 权威规则

开始前必须读取：
1. ../../docs/漫剧系统UI与程序化特效制作规范-V1.md（本技能权威源指令）。
2. references/制作流程与工具选择.md。
3. 需要数据结构时读取 references/参数化数据合同.md。
4. 交付前读取 references/验收与失败诊断.md 和 tests/系统UI与粒子回归样例.md。
5. 需要复用第三方方法时读取仓库 docs/Deepresearch/2026-11-02_漫剧粒子特效与系统UI可控制作Skill专项研究.md。

不得把本 Skill 当作剧本、分镜、人物调度或打斗动作规则的替代品。

## 职责边界与协作

- 本技能负责 UI 内容组件、可编辑属性、UI 动画、2D/程序化粒子、能量纹理、透明导出和特效验收。
- storyboard-director-cn 提供人物/道具位置、锚点、镜头状态与遮挡事实。
- camera-motion-director-cn 提供摄影机轨迹；本技能不得擅自改变人物世界坐标。
- fight-impact-vfx-cn 负责打斗接触、受力和命中特效因果；本技能只实现对应事件触发后的图形与粒子表现。
- 用户私人 chatcut-motion-graphics 是 ChatCut 直接 JSX 的上游生产入口；本技能补充漫剧系统 UI/VFX 专业规范，不重复实现其平台接口。

## 默认工具路线

1. **首选 ChatCut JSX**：复用现有 ChatCut Motion Graphics Skill，读取时间线尺寸/FPS/时长和安全区，复用已有库资产，直接创建或修改可编辑 JSX 图形，再放置时间线。
2. **UI 图层**：JSX 组织组件，SVG 绘制边框、图标、环形刻度和路径；真实文本和数值独立绑定数据。
3. **普通 2D 粒子**：Canvas 2D；粒子量不大时不使用 DOM 节点堆叠。
4. **高密度/复杂能量场**：只有性能和视觉需求明确时才使用 Three.js GPU Points / Shader。
5. **透明交付**：先核实 ChatCut 账户是否支持 ProRes 4444 Alpha 并实测；无权限时才评估独立透明渲染流程。
6. **空间合成**：透明 Alpha 不等于人物遮挡/跟踪。需要手部前后遮挡、透视或镜头跟随时，补 matte/跟踪/合成，不得用透明导出冒充完成。

当前会话若无 ChatCut 运行时工具，必须明确标记“未在 ChatCut 运行”，只交付可审查源代码/参数，禁止声称真实创建或导出成功。

## 强制工作流

1. 锁定剧本、SCG、镜头、角色、道具、事件和数据源；未知字段保持未知。
2. 明确观众需要读懂的内容和 UI 的屏幕空间/世界空间属性。
3. 建立稳定 effect_id、style_id、continuity_group 和锚点引用。
4. 先完成稳定显示帧，再设计入场、更新、退场；确保状态完整。
5. 将底板、边框、文字、图标、光效、粒子和遮挡层拆分。
6. 将文案、数值、颜色、字体、尺寸、位置、动画时长和粒子参数暴露为可编辑属性。
7. 粒子必须固定 seed、时间步长和触发帧；不得依赖不可复现的随机源。
8. 在 ChatCut 可用时直接创建/编辑并放入时间线；优先复用已有资产。
9. 检查首帧、入场中帧、稳定帧、更新帧、退场帧；必要时生成逐帧联系表。
10. 需要透明叠加时检查真实 Alpha 通道、边缘和首尾空帧。
11. 检查人物/道具遮挡、锚点、透视、字幕/对白/脸部避让和跨镜连续性。
12. 保存源文件、参数、素材依赖、许可信息和测试证据。

## 核心控制要求

- 文案/数值来源必须是剧本或结构化数据，不能由生图模型生成最终真值。
- 所有高频修改属性必须能通过属性面板或参数对象修改。
- 一个 UI 的外观不能每个镜头重新随机生成；同一 effect_id 必须继承样式和状态。
- 粒子参数至少包括发射模式、数量/速率、速度范围、方向/扩散、寿命、尺寸、重力、阻力、颜色、透明度、混合模式、seed 和锚点。
- GPU 效果必须有性能预算、移动端降级和资源释放策略。
- UI 不遮挡人物脸、对白、关键动作、命中点或必须阅读的数据。

## 验收状态

逐项报告：已设计 / 已生成代码 / 已运行预览 / 已导出 / 已验 Alpha / 已完成空间合成 / 已通过跨镜验收。

必须通过 references/验收与失败诊断.md 的门禁。仅有代码、静态图或官方产品说明，不得标记为真实镜头通过。
