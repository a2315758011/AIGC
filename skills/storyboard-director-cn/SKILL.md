# 分镜导演与独立质检 Skill

## 适用范围
仅处理剧本转分镜、镜头导演设计、分镜连续性、独立自检与修复。不得混入小游戏制作、Cocos 或其他无关项目规则。

学员只需提供原剧本（或待审分镜）及已有的人物、场景、道具参考。不得假设学员能访问原作者 GitHub 仓库。

## 激活后必须完整读取
1. `references/剧本转分镜指令.md`
2. `references/剧本转分镜自检指令.md`

两份规则均为离线完整快照 V2.10.6。必须读取正文，不可只看本页、文件名或摘要。缺失或截断时，明确报告缺失文件，不得声称已加载完整规则。

涉及多人站位、场景调度、走位路径、摄影机轴线或双人近景时，必须读取：
- references/人物站位与场景调度规则-V1.md（V1.9.0，含平台创作者实战方法）

如需结构化镜头状态校验，再按需读取：
- `references/分镜SCG数据契约-V1.md`（使用结构化分镜或生成段落时读取）
- `references/分镜穿帮专项回归样例-V1.md`
- `references/分镜事件时间数据契约-V1.md`
- `references/SCG骨骼姿态与接触约束扩展契约-V1.md`（涉及坐姿、支撑、抓握、扶靠、跌倒、身体接触时必须读取）

## 执行顺序
1. **锁定事实**：读取剧本、人物/服装/场景/道具资产与目标模型能力；缺失信息标为未知，不得补造。
2. **导演推演**：先拆视觉节拍，再拆镜头。检查观众信息、动作链、逐镜面部表演可见证据、跨镜/跨 10 秒或 15 秒生成段落的表演尾态继承，防止无依据恢复中性脸，再检查镜头新增信息、景别/机位/轴线/视线的可实现性与提示词负载。
3. **编写完整初稿**：遵守主指令，确保每镜的景别、实际可见身体范围、身体朝向、头部朝向、视线、动作起止、道具状态与镜间衔接明确。景别不得诱发人物无依据位移。
4. **独立自检**：按自检指令检查原文覆盖、动作因果、人物与道具连续性、面部表演连续性/僵尸脸风险、镜头价值、节奏和生成可执行性。
5. **结构化校验**：按任务风险运行程序。使用 SCG 时运行 SCG 校验器；若存在 `generation_segments` 或 `facial_performance` 结构化数据，必须运行面部表演连续性校验器；若存在持续动作、前置依赖、互斥动作、机关接合/持续操作、多人逐一可见展示等高风险时序，建立事件时间账本并运行事件时长校验器。不能把普通中文稿直接交给程序并声称已检查；动作串并行含糊时标记 `NEEDS_REVIEW`，不得让程序猜测。
6. **修复与重写**：默认修复 P0/P1；结构化校验或独立自检发现问题后，修复最早冲突决策，复检受影响的前后镜头，并重新运行相关校验器。用户明确要求“只审核不修改”时才只报告问题。
7. **如实交付**：区分规则读取、文本自检、SCG 结构校验、事件时间校验和实际视频生成验收。未运行的测试不得声称通过。

## 交付规范
- 默认输出完整、可直接使用的分镜正文；不把内部账本、分析过程或 SVG 当作必交付物。
- SVG 不是必需项。若无法清晰表达空间关系，就使用结构化文字说明，不得为凑图而绘制误导性示意图。
- SCG 仅在工作流需要跨镜状态交接或结构化校验时使用，不得让内部 ID、JSON 或错误码污染普通分镜正文。
- 不能把“文字自检通过”说成“实际视频已验证”。

## 可选 SCG 程序校验
在技能根目录运行：
```bash
node scripts/分镜SCG校验器-V1.js tests/分镜SCG回归样例-V1.json
```
若环境没有 Node.js，可跳过并明确标记“SCG 程序校验未执行”。程序通过只证明校验器覆盖的规则通过，不代表实际视频生成质量通过。

## 跨镜/跨生成段落面部表演连续性校验

当结构化 SCG 使用 `generation_segments` 或 `facial_performance` 时，在技能目录运行：
```bash
node scripts/validate-facial-performance-continuity.cjs tests/面部表演连续性回归样例-V1.json
```
校验器检查段落分组与模型时长上限、可见面部状态字段、上一可见表演尾态继承、跨 10 秒/15 秒等生成段落边界、剧情事件触发和段内表演推进。它不判断文字情绪是否符合剧本，也不证明模型生成视频真实服从。

## 高风险时序：事件时长校验
存在持续动作、前置依赖、互斥动作、机关接合/持续操作或多人逐一可见展示时，先建立结构化事件时间账本，并按 `references/分镜事件时间数据契约-V1.md` 核对字段，再在技能根目录运行：
```bash
node scripts/分镜事件时长校验器-V1.js tests/分镜事件时长回归样例-V1.json
```
校验器只检查结构化账本，不解析普通中文分镜稿。只有明确实测或硬约束的最小时长才可触发硬错误；估算阈值只产生警告并进入 `NEEDS_REVIEW`。源文不能判定动作串行/并行时，不得猜测，应先标记待复核。回归样例全部符合预期只证明校验器行为符合测试，不代表实际视频生成质量通过。


涉及俯视站位图、角色身份映射、全景背景、路径避障或身体部位跟踪时，必须读取并遵守 `references/人物站位与场景调度规则-V1.md` 最新版本；站位图与机位构图图分开验收，避免把画面左右当作世界坐标。


若当前环境提供已授权的结构化3D导演台/MCP，可按站位规则执行“先读工程状态与稳定ID→小步修改→验证→局部撤销”；没有该工具时不得假装可操作，也不得为单次任务擅自安装第三方软件。人工锁定的站位/关键帧优先于后续AI建议。


## 人物骨骼与接触关系强制校验

凡镜头涉及坐下/起身、脚底支撑、抓握道具、扶靠桌墙、跪地/跌倒、搀扶或身体碰撞：
1. 在现有 SCG entities 中声明角色 skeletal_rig / skeletal_pose，在目标实体声明 contact_anchors。
2. 在现有 relations 中声明 contact_constraint；不得另造人物/道具状态账本。
3. 逐镜保持 contact_id、人物、目标、末端和锚点一致；建立/释放必须有 contact_begin / contact_end 事件。
4. 运行场景真实性技能中的 `tests/validate-scg-skeletal-contact.cjs` 与对应回归夹具。
5. 结构校验通过不等于 IK 已执行。没有 Blender / DirectorDesk 解算报告、关键帧和视口证据时，骨骼接触实测必须标记 NOT_RUN。
