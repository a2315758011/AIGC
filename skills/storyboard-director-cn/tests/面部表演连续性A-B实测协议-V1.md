# 面部表演连续性 A/B 实测协议 V1.0

- 状态：预注册协议；尚无真实视频结果。
- 建立日期：2026-11-04
- 基线提交：79008f4cd541152e7623abd1c8c4cd629225d3f8
- 目的：验证结构化面部表演状态机是否比等语义的普通自然语言提示，更稳定地控制真实视频中的表情、视线、口型与跨片段继承。
- 本协议是视频实测协议，不把静态 JSON 校验、CI 通过或生成任务排队视为视频验收。

## 1. 研究问题与假设

研究问题：在同一视频模型、同一人物参考和同一镜头条件下，将完全相同的表演意图表达为结构化状态机，是否能减少表情重置、僵脸、微表情突变、视线漂移及跨段不连续？

预注册假设：
- H1：B 组无剧情触发的情绪重置次数低于 A 组。
- H2：B 组的眉、眼、嘴、下颌协调度和跨段状态继承评分高于 A 组。
- H3：B 组不得以牺牲人物身份、自然度、对白口型或动作真实性换取状态一致。
- H4：若质量无明确提升，或生成耗时/费用增加超过 25%，不将 B 组设为默认生产路线。

## 2. A/B 唯一变量

### A 组：普通自然语言表演提示

- 使用普通提示词描述角色身份、情绪意图、表情变化顺序、视线目标、对白节奏和跨片段承接。
- 不注入机器可读的 facial_performance 状态字段。
- 不故意删掉剧情信息，不使用弱化提示词。

### B 组：结构化状态机表演提示

- 使用同一剧情、同一人物、同一表演目标和同一时间点。
- 将 A 组的同一语义信息编码为 SCG facial_performance：entry_state、beats、exit_state、continuity、acting_role、face_visibility。
- 状态字段遵循 storyboard-director-cn 当前校验器与 SCG 合同。
- 不增加 A 组没有的表演内容、参考图或额外生成参数。

两组的提示语义必须等价。A/B 唯一有意改变的是表演信息的表达与约束形式（自然语言 vs 结构化状态机）。如果 B 组获得更多剧情事实、更多参考图或更强模型参数，该轮比较作废。

## 3. 固定控制变量

每个配对样本必须锁定并记录：
1. 视频提供方、模型精确名称/版本、接口版本、运行日期。
2. 人物母版及参考文件 SHA-256；服装、发型、妆容、年龄设定与角色身份。
3. 场景、灯光、背景、镜头焦段/景别/机位、相机运动。
4. 视频时长、分辨率、帧率、画幅、运动强度、采样器/步数/CFG（提供方支持时）。
5. 随机种子；若模型不支持固定种子，明确标记为非严格配对，不得声称完全控制随机性。
6. 完全一致的对白文本、音频、语速、停顿、重音、呼吸与口型同步要求。
7. 两组完整提示词、SCG 文件、工作流版本、模型元数据、生成任务 ID、原始视频路径及 SHA-256。
8. 排队、生成、下载、失败、重试次数、耗时与费用。失败任务不得静默删除；重试必须记录。

任一关键控制变量不一致，标记 INVALID，只保留流程观察数据，不计入质量胜负。

## 4. 最小测试集：三组配对视频

### FP-01 情绪跨片段继承（建议总长 2×8—10 秒，实际时长以模型能力证据为准）

表演目标：角色压抑愤怒，第一段以克制、紧绷但未爆发的表情结束；第二段从同一表演状态继续，随后由明确剧情事件触发短暂情绪升级，再恢复克制。

观察点：
- 第二段开头是否继承眉眼、嘴部、下颌紧张度和视线状态。
- 是否无故回到中性脸或突然换成另一种情绪。
- 触发事件前不得提前变化；触发后变化须有可见的渐进过程。
- 切段处头部姿态、视线目标和表情强度是否连续。

### FP-02 微表情与情绪节拍（单段 8—10 秒，实际时长以模型能力证据为准）

表演目标：平静聆听 → 察觉意外 → 短暂惊讶 → 压住反应 → 恢复克制。每个节拍都必须由明确事件触发，不能只按时间机械切换。

观察点：
- 眉、眼睑、瞳孔/视线、嘴角、唇部张力和下颌是否协调。
- 表情变化是否平滑，有无抽搐、跳变、脸部融化或过度夸张。
- 情绪含义是否可辨认，是否出现“全程同一张脸”。
- 非主表演人物不得无理由抢戏或出现同步夸张表情。

### FP-03 对白、倾听反应与跨镜承接（建议 2×8—10 秒，实际时长以模型能力证据为准）

表演目标：说话者完成一句对白；倾听者保持注视并产生轻微反应；切镜后倾听者继续保留上一镜形成的情绪，直到新的对白/事件触发改变。

观察点：
- 说话者口型与对白节奏大致同步，非说话者不出现无意义口型。
- 倾听者的目光、眉眼和嘴部状态连续。
- 镜头切换不能造成角色表情、视线或头部姿态无因重置。
- 反应必须符合角色意图，不得出现僵硬的“假笑/假惊讶”。

## 5. 时长与分段规则

- 先读取目标模型官方文档或真实测量记录，核实单段时长上限。
- 不得将测试夹具中的 10 秒/15 秒示例当成当前模型真实能力。
- 若单段时长不足，按时间轴拆段；前段 exit_state 必须与后段 entry_state 对齐，后段标记正确的 segment_boundary 与 from_shot_id。
- 分段边界处的状态继承属于本实验的核心测量对象，不得用剪辑隐藏跳变。
- A/B 使用完全相同的分段方案与时间码。

## 6. 结构校验与生成前门禁

B 组生成前运行：
```bash
node skills/storyboard-director-cn/scripts/validate-facial-performance-continuity.cjs <scene.json>
```

若 A 组也输出 SCG，则仅用同一校验器检查其人物身份、镜头、事件和分段元数据；不得为了通过结构校验而偷偷向 A 组注入 B 组的状态机控制字段。

校验器只证明结构字段、事件引用和分段时码满足合同，不证明真实视频表演自然或连续。

## 7. 盲评与评分

- 最少 2 名独立人工评审，推荐 3 名。
- 评审者不得是本轮唯一提示词作者或生成操作者。
- A/B 视频先替换为随机盲码，随机左右顺序；评审者不知道组别。
- 每位评审先独立标注 P0—P3 缺陷，再按下列维度逐项打 1—5 分，最后给配对偏好。
- 保留每位评审原始分数和证据时间码，不只保存协商后的平均分。
- 多模态模型评分只能辅助，不能单独放行。

评分维度（每项 1—5 分）：
1. 情绪意图可辨认性。
2. 眉眼嘴颌协调度。
3. 微表情变化自然度。
4. 表情时间连续性与无故重置次数。
5. 跨生成段/跨镜头状态继承。
6. 视线目标与眼神稳定性。
7. 对白口型与语气节奏匹配。
8. 头部姿态与面部表演协同。
9. 人物身份、脸型与五官稳定性。
10. 真人表演可信度（无僵脸、抽搐、融化、过度夸张）。

证据时间码格式：`00:00:03.200`。每个 P0/P1 必须记录发生时间、可见现象、涉及角色和对剧情的影响。

## 8. 缺陷分级与硬门禁

- P0：人物身份/脸型严重漂移；面部畸变或不可接受的生理错误；关键剧情情绪完全反转；表演状态无因重置导致剧情含义改变。
- P1：明显僵脸/木偶脸；关键微表情缺失或无因跳变；眉眼嘴颌明显不同步；视线持续错误；口型严重错位；跨段状态明显断裂。
- P2：局部表情不够细腻、轻微眼神漂移、轻微口型偏差或短暂表演过度。
- P3：不影响剧情理解的轻微审美偏差。

任一适用 P0 即该样本 FAIL。P1 必须逐项列明；不得用平均分掩盖硬缺陷。证据不足标记 UNVERIFIABLE，不计 PASS。

## 9. 预注册判定门槛

只有同时满足以下条件，才可称 B 组在本轮小样本中“初步更优”：
1. 三组视频均有效，模型、参数、人物参考、对白、场景和分段控制变量一致。
2. B 组 P0 数量不高于 A 组，且无新增身份漂移、面部畸变或对白严重失配。
3. B 组在“表情时间连续性、跨段继承、眉眼嘴颌协调”三项的配对结果中至少两项胜出，且总体盲评偏好至少 2/3 配对支持 B。
4. 至少两名独立评审完成，且保留独立原始分数。
5. 额外耗时与费用分别报告；若增加超过 25% 且没有清晰质量收益，不判 B 胜。

三组样本只能形成工程初步信号，不代表统计显著或对所有模型/题材普遍有效。出现评审分歧、模型随机性过大或无效配对时，应扩展样本，不得硬判胜负。
