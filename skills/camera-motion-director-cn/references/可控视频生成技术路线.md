本文件记录真正能够将相机运动条件输入视频生成模型的开源项目。与纯提示词技能区分：这些项目包含研究代码、模型权重、条件构造或可运行推理流程。

## 二、统一相机控制条件分类

A. **语言控制**：自然语言描述推拉摇移、方向、节奏和动机。易用但几何精度有限。

B. **相机位姿控制**：逐帧 3×4 / 4×4 camera-to-world 或 world-to-camera 矩阵；精确但必须声明坐标系、单位、轴向、帧率和 FOV。

C. **参考视频控制**：从一段运镜视频估计相机轨迹，再迁移到目标内容；保留时间节奏，但估计可能混入主体运动。

D. **参考轨迹视频控制**：用 Blender/Three.js/虚拟场景导出的中性相机参考视频描述路径和速度，降低自然语言歧义。

E. **多视角锚点控制**：为人物/商品提供不同视角参考，降低大角度运动时身份/结构漂移。

F. **深度/点云/3DGS/4D 控制**：通过几何重建支持更大位移和遮挡变化；代价是预处理、显存、模型和算力要求更高。

## 三、推荐决策树

1. 只有单张图，短镜头、轻微变化：先使用提示词型 I2V 运镜技能，采用小幅单主运动。
2. 单张图，希望路径可视化：用深度估计 + 3D 点云相机路径编辑器预演；检查 API 成本和视图重建。
3. 有角色多视角参考，需要大角度绕拍：优先研究 WorldCast 类多视角锚点方案。
4. 有视频，希望重新选择摄影机路径：研究 TrajectoryCrafter、WorldinWorld、Vid-CamEdit、CameraNoise。
5. 需要精确每帧相机位姿：研究 SCoPE / GEN3C / CameraAnything 等轨迹条件模型。
6. 同一条轨迹需要文字、Pose、参考视频多种表达：研究 TriMotion / OmniCamera。
7. 需要摄影机和多个物体同时按 4D 轨迹运动：研究 VerseCrafter。

## 四、重要限制

- 研究代码不等于普通用户可直接使用的软件；检查显卡、模型权重、依赖、许可证和推理入口。
- 论文指标和演示视频不能代替本地运行验证。
- 模型支持某类条件，不代表每条轨迹都能精确执行。
- 大角度环绕必须有隐藏表面或多视角锚点证据。
- 轨迹控制与人物动作控制要分别指定；若两者耦合，必须明确谁是主导变量。
- 没有明确许可证的仓库仅登记和研究，不复制源码/模型/文档正文。
