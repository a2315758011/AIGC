# 程序化视频工作流中文速查 V1

本文件是上游 video-director 的中文执行索引，不替代 `references/upstream-SKILL.md` 和四份上游参考原文。

## 一、核心判断

视频质量主要来自制作流程、数字参数和检查器，而不只是提示词长度。短简报可以启动工作流，但不能跳过事实锁定、时间计划、静帧确认、逐帧渲染和独立审片。

## 二、13 项核心原则

1. **时间是帧的唯一输入**：每帧只由时间 t / frame index 决定；禁止隐式状态和未设种子的随机过程。
2. **先用数字规划**：先确定时长、FPS、镜头区间、节拍、文字停留、音效 cue 和切点。
3. **先做低成本产物**：简报 → 创意方案 → 静帧 → 低分辨率草稿 → 最终渲染。
4. **一个核心视觉概念**：避免同时塞入多个主张、多个主角和多个视觉高潮。
5. **揭示必须有 cue**：揭示点要落在动作、台词、音乐节拍或阅读结束点上。
6. **按观众速度安排信息**：动作可以快，文字与关键事实必须留够阅读时间。
7. **连续性由对象承担**：跨镜对象、颜色、形状和屏幕方向要有可追踪的连续关系。
8. **颜色有明确语义**：强调色只负责一个主要含义，避免无目的渐变和装饰性光效。
9. **声音与画面共用时间轴**：音乐、旁白、字幕和 SFX 都从同一时间表派生。
10. **测量最终交付文件**：检查最终 MP4 的响度、峰值、同步、冻结和切点，而不是只测源文件。
11. **看静帧和连续帧条**：检查 beat sheet、overview sheet、fast-move strips 和 phone sheet。
12. **构建者不独自审片**：安排独立审查，记录缺陷和接受/拒绝理由。
13. **事实术语要可见、可核验**：关键术语按需要同时在旁白和画面中出现；数字与承诺必须能追溯到来源。

## 三、推荐工作流

1. 需求简报与事实锁定；
2. 写 TREATMENT，比较三种结构；
3. 从已批准 SCG/事件时间账本派生 timeline.json；
4. 先出 styleframes / 首帧 / 高潮帧 / 结尾海报；
5. 编写纯函数式动画；
6. 设计音乐、旁白、字幕和 SFX；
7. 逐帧渲染 MP4；
8. check_timeline.py 预检；
9. qa_video.py 后检；
10. 联系表 + 独立审片；
11. 单变量局部修复与范围外帧差异检查；
12. 归档源码、MP4、报告和 SOURCE_LOCK。

## 四、三个时间基准

- `music`：画面事件与音乐节拍/小节对齐；loop 时必须符合整小节长度。
- `voice`：画面事件与真实旁白词级时间戳对齐；ESTIMATED 只能作为临时草稿。
- `reads`：按观众理解和阅读时间安排；没有音乐/旁白主时钟时使用。

FPS 必须由项目规格给出，不设全局默认值。秒数先保留浮点数，最后才换算帧。

## 五、上游工具职责

- `check_timeline.py`：编码前检查场景时间、空隙、beat、切点、Hero、静音、字幕速度、Hook/CTA、术语和文字停留时间。
- `qa_video.py`：渲染后检查首帧、闪帧、画面突变、冻结、平帧、剪辑点、loop seam、文字大小/对比度、响度、true peak、静音和联系表。
- 两个脚本都不能判断剧情是否忠实、真人表演是否可信、人物手部是否正确、镜头是否有审美价值。

## 六、适配 AIGC 仓库的特别限制

- SCG 负责世界状态；事件时间账本负责事件时序；本技能不另造 entities / relations / events。
- timeline.json 只保留 shot_id/event_id 引用并负责渲染层 cue。
- 真人仿实拍片中的真实演员不能由程序化角色动画冒充；程序化方法适合字幕、UI、粒子叠加、解释图形、转场和预演。
- 机器 QA PASS 不等于目标模型服从、真实视频验收或最终成片通过。
