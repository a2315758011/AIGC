# 多宫格视觉分镜联系表 Skill

## 1. 触发条件

用户要求影视、AI 漫剧、真人短剧、广告或动画的 4格、9格、12格、25格分镜图、镜头联系表、分镜板或逐格画面总览时调用。

本 Skill 的交付对象是**独立画格 + 程序排版的联系表**，不是正式漫画页面。用户明确要求一张整图概念稿时可以生成整图草案，但必须标记为草案，不能冒充逐格生产结果。

## 2. 能力分工与必须复用的上游 Skill

不得重写已有导演规则。按媒介调用：

- **所有叙事分镜**：先读取 `skills/storyboard-director-cn/SKILL.md`，再按其要求完整读取主编写规则、自检规则；涉及多人站位、走位、摄影机轴线时读取其人物站位与场景调度规则。
- **真人/仿实拍短剧**：额外读取 `skills/live-action-safety-storyboard-cn/SKILL.md` 及真人影视视觉锁定规范。必须是真人摄影质感，不得输出漫画、动漫或插画风。
- **正式漫画页面**：转交 `skills/comic-production-director-cn/SKILL.md`。本 Skill 只可作为漫画前期镜头预演工具，不管理漫画气泡、对白排字或出版页面。
- **场景空间与跨镜连续性**：按上游分镜 Skill 要求读取 `skills/scene-realism-director-cn` 对应规则与校验器。涉及坐姿、抓握、支撑、身体接触时，必须按上游规则读取骨骼姿态/接触约束扩展。
- **结构化镜头状态**：如镜头存在跨镜实体状态、道具持有、多人走位或复杂时序，沿用现有 SCG（场景连续性图）数据契约与校验器；不得另造冲突的第二套事实账本。

若上游文件缺失或读取不完整，明确标记 BLOCKED，不得声称完整加载。

## 3. 用户输入与事实锁定

优先从项目已有文件恢复，不要求用户重复提供已存在资料。输入包括原剧本/广告脚本、批准镜头清单、角色母版、服装版本、场景母版、道具参考、人物姿态与空间状态、镜号/景别/机位/时长及目标格数。

事实来源优先级：用户明确锁定 > 原剧本/批准资料 > 已批准资产 > 明确标注的推断 > 未知。不得补造人物、座位、道具、场景结构、动作或剧情。缺失信息只标为未知或待确认。

## 4. 格数与布局

| 用户格数 | 布局 | 容量 |
|---|---|---:|
| 4格 | 2×2 | 4 |
| 9格 | 3×3 | 9 |
| 12格横向 | 3×4 | 12 |
| 12格纵向 | 4×3 | 12 |
| 25格 | 5×5 | 25 |

默认从左到右、从上到下。顺序必须来自权威镜头清单中的 `order`，不得按文件名、生成时间或模型输出顺序猜测。

## 5. 逐格生产工作流

### 5.1 建立镜头清单

每格必须有稳定 `shot_id`、连续 `order`、独立图像路径 `image`，可选 `timecode`。镜头描述、角色、场景、机位、动作和参考资产由上游导演规则维护；不要把长篇剧情塞进排版 manifest。

### 5.2 逐格生成，不先让模型画宫格

- 默认一张图只表达一个镜头瞬间；每个镜头单独生成、单独保存。
- 同一角色使用同一批准参考图和视觉锁定描述；同一场景沿用固定建筑结构、光线方向、道具位置与空间锚点。
- 每格提示必须明确媒介、角色/资产引用、景别、机位、身体朝向、视线、动作瞬间、场景锚点和禁止擅自新增项。
- 不让图像模型生成镜号、时间码、字幕、对白或联系表边框；这些由程序绘制。
- 不用一张 4/9/12/25 格生成图裁切后冒充独立画格。整图生成只可作为 A/B 对照样本，必须单独标注。
- **防止模型擅自加戏**：单镜提示词必须列出本镜唯一主要可见动作，并把“原文未要求的手部接触、卷袖、查看伤处、握持道具、额外表演动作”列为禁止新增项；特写不自动授权加入人物面部或其他身体部位。
- **身体部位与方向锁定**：涉及左/右手臂、左右手、肩/肘/腕时，必须在提示词和质检表中单独锁定；无法从批准参考图确认时标记未知，不得以模型生成结果反向确认。
- **超自然效果不得改变皮肤几何**：能量印记优先描述为完整皮肤表面上方的薄层光投影/贴附式发光图层，避免“vein-like、etched、crack、under the skin、branching tendrils”等容易生成皮下脉络、裂纹或伤痕的表达；明确禁止符号形状、纹身图案或伤口，除非剧本/批准资产明确要求。
- **因果特效分层**：金属反光掠过、能量印记出现、光纹扩散属于不同可见事件；若原镜头要求同一镜头内呈现，必须确认静态画面能表现的是哪个关键瞬间，不能遗漏触发线索或擅自添加新动作；复杂过程应由连续独立画格表达。
- 失败时只重做对应镜头，不得无授权重做已批准角色母版、场景母版或其他画格。

### 5.3 逐格质检

检查人物身份/服装、场景结构/固定锚点、道具数量与位置、景别/机位/视线/朝向、动作起止、镜头轴线、相邻镜头状态继承、媒介风格，以及意外文字/拼图边框。跨镜检查按上游 SCG/场景真实性规则执行。排版程序不理解图像中的人物身份、动作或空间连续性。

### 5.4 生成联系表

使用仓库 `tools/storyboard-contact-sheet/` 中的程序：

```powershell
python -m pip install -r requirements.txt
python contact_sheet.py --manifest manifest.json --output contact-sheet.png
python contact_sheet.py --manifest manifest.json --validate-only
```

实际运行时将工作目录设为工具目录。manifest 参考 `manifest.example.json`，字段约束见 `manifest.schema.json`。

程序支持 2×2、3×3、3×4、4×3、5×5；按 order 排序；等比例适配并留边；添加镜号/时间码；拒绝数量不符、重复 ID/顺序/源图、缺图、路径越界、图像损坏、标签溢出和输出覆盖源文件。源画格只读。

## 6. 真人镜头的可控特效合成

当生成模型反复把能量光效画成皮肤裂纹、伤痕或纹身时，停止反复重抽整张人物图，转为分层制作：
1. 先取得无特效、动作正确的真人底图；底图不允许包含未批准的符号、纹身、伤口或额外道具。
2. 手工/经批准的分割工具制作同尺寸皮肤区域灰度蒙版；白色仅覆盖允许叠加的皮肤表面，黑色覆盖其余区域。
3. 使用 `tools/storyboard-vfx-overlay/` 在蒙版内绘制表面光纹和单独金属反光；路径使用归一化坐标，不自动推断解剖位置。
4. 保留独立透明 RGBA 特效层和最终合成图；原始底图不得覆盖。
5. 验收蒙版外零泄漏、皮肤几何未改变、无伤口/裂纹观感、特效位置正确。没有合格底图和蒙版时状态必须为 `BLOCKED`，不得声称已完成正式镜头。

## 7. 最终交付合同

每次交付应包含独立原图、权威镜头 manifest、程序生成的 PNG 联系表、逐格审核结果与返工记录、生成模型/版本/参考资产/关键参数及未验证项。用户只要联系表时，可将独立画格放在同一交付目录，不必在聊天中逐张铺开，但不能删除独立源文件。

## 7. 失败与状态规则

- 源镜头数量与布局容量不一致：BLOCKED。
- 镜号/顺序/源图重复：BLOCKED。
- 缺少角色/场景参考但任务要求严格连续性：BLOCKED 或降级为概念草案。
- 图像模型把多个镜头拼成一张图：不能计入独立画格验收。
- 联系表程序通过：只证明排版与文件合同通过。
- SCG 通过：只证明已实现的结构化规则通过。
- 只有独立画格逐格审查与跨镜连续性审查通过，才能标记视觉验收通过。
- 真实视频/动画生成未执行时，不能宣称动态表演或运动连续性已验证。

状态必须区分 PASS / FAIL / BLOCKED / NOT_RUN。禁止把代码存在、CI 通过或一张好看的宫格图说成完整生产验收。

## 8. 版本与当前限制

版本 1.0.0 beta。当前已具备确定性联系表排版器和自动化回归；GPT 原生生图的逐格一致性、25 格生产 A/B、真实项目端到端生成仍需单独验收。未经测试，不得提升为 production-ready。
