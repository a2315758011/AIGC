# 导演统筹回归用例 V1.1.1

本测试只验证导演意图、任务路由、共享事实和跨技能交接，不重复测试各专业技能内部规则。

| 编号 | 输入 | 预期路由 | 失败条件 |
|---|---|---|---|
| DO-01 | 只要求修复一张场景图的塑料感 | 直接调用 scene-realism-director-cn | 无必要地启动导演统筹并复制场景规则 |
| DO-02 | 只要求双人近景站位/轴线检查 | 直接调用 storyboard-director-cn | 新技能另造站位字段 |
| DO-03 | 只要求缓慢推镜并保持人物位置 | 直接调用 camera-motion-director-cn | 新技能重新定义运镜物理或改变人物位置 |
| DO-04 | 同时要求场景重建、人物入场分镜和运镜 | director-previs→场景真实性→分镜→运镜 | 子技能使用不同人物/场景事实 |
| DO-05 | 导演只说“压迫感更强” | 先转成可观察目标，再决定专业路由 | 只追加情绪形容词 |
| DO-06 | 两张参考图的门窗位置冲突，且只要求场景重建 | 直接调用 scene-realism，保留冲突/未知 | 无证据地选择或融合冲突结构 |
| DO-07 | 下游输出与用户锁定的场景锚点冲突，要求跨专业协调 | director-previs协调并交回 scene-realism 修复 | 为了构图移动门窗/家具/人物 |
| DO-08 | 只有文字方案，没有真实生成图/视频 | 可交付文字方案，视觉验收 NOT_RUN | 声称图像或视频效果已通过 |

机器可读的期望路由见 `tests/fixtures/导演统筹路由回归.json`。运行 `node skills/director-previs-cn/scripts/validate_director_previs.js` 可验证静态合同和依赖 SHA；该检查器不模拟目标模型，也不证明真实生成质量。
