# 导演统筹与场面预演 Skill

## 1. 核心定位

本技能是导演层的**统筹与交接入口**，不是另一套场景、分镜或运镜规则。

唯一增量职责：
- 把剧本/创意转成导演可执行的场面目标。
- 明确观众此刻应知道、误解、期待或暂时看不到什么。
- 把情绪与人物关系变化转成可观察的场面事件和视觉信息。
- 判断需要哪些专业技能，按正确顺序调用并传递同一组事实。
- 汇总各专业技能结果，检查冲突、遗漏和不必要的复杂度。

## 2. 专业技能路由（权威分工）

| 任务类型 | 必须调用的技能 | 该技能负责什么 |
|---|---|---|
| 场景图假、建筑拓扑、空间功能、透视尺度、物理接触、光材质、参考图保真、俯视/全景 | `scene-realism-director-cn` | 场景真实性诊断、结构约束、局部修复和独立验收 |
| 正式逐镜分镜、人物站位/身体朝向/头部朝向/视线、走位、轴线、连续性、自检修复 | `storyboard-director-cn` | 分镜生产、人物调度和跨镜状态验证 |
| 推拉摇移、跟拍、环绕、摄影机轨迹/速度、图生视频运镜和运动审片 | `camera-motion-director-cn` | 摄影机运动设计、模型适配和运镜质检 |
| 拳脚/兵器/能量战斗、攻防因果、接触/受击、打击节奏、命中特效、环境反馈和声画同步 | `fight-impact-vfx-cn` | 打斗动作因果、受力可读性、特效设计与审片 |

**调用规则：**
- 单一专业任务直接调用对应技能，不额外加载本技能；单独打斗动作/打击感/命中特效任务直接调用 `fight-impact-vfx-cn`。
- 同时跨越两个或多个专业领域，或用户明确要求导演统筹/整体预演时，调用本技能组织它们。
- 打斗场面需要跨专业协作时，按需采用：场景真实性（如涉及环境破坏/复杂空间）→打斗动作因果与特效→正式分镜/人物调度→摄影机运镜；不需要的技能跳过。
- 不得复制专业技能中的规则字段、参数表或校验器；以专业技能当前 main 版本为准。
- 本技能发现某专业规则缺失时，先回读对应技能和 SOURCE_LOCK，不凭记忆另造第二套标准。

## 3. 导演统筹流程

1. **锁定创作目标**：媒介、时长、画幅、受众、剧情节点、必须保留项和交付物。
2. **导演意图简报**：用简短语句说明场面目标、观众信息、人物关系变化和主要情绪转折。
3. **建立事实清单**：区分用户明确事实、参考图可见事实、多源印证、合理推断和未知；参考图/已确认母版优先。
4. **拆分专业任务**：场景真实性、人物/分镜、摄影机运动、打斗动作/特效分别派给对应技能；不需要的技能不调用。
5. **共享同一份事实底稿**：场景锚点、人物身份、道具状态、时间/光线、剧情动作、武器/接触事实和硬约束只维护一份，不在子技能中各自改写。涉及动态走位时，人物根节点路径与身体动作/姿态分开；路径记录起点、途经点、终点和时间/关键帧；脚底防穿地与支撑脚锁定分开；摄影机位置路径与注视点/视线目标路径分开；多人错峰和跨镜末态单独记录。
6. **整合专业输出**：检查空间、人物、镜头、运镜是否互相矛盾；发现冲突回到最早产生冲突的环节修复。
7. **导演验收**：检查观众能否读懂动作和关系变化、画面是否符合常识、专业约束是否一致、目标模型是否有能力执行。
8. **如实报告**：分别标记已完成、已验证、未验证和阻塞；文字方案通过不等于真实图像/视频通过。

## 4. 导演意图最小合同

每个场面只需回答：
- **场面目的**：这一场必须让剧情发生什么变化？
- **观众信息**：观众现在知道什么、误以为什么、还不知道什么？
- **人物关系**：关系发生了什么变化，谁主动、谁回应？
- **可见事件**：观众实际能看到的动作/空间变化是什么？
- **视觉重点**：此刻最重要的信息是什么，哪些内容应保持次要？
- **结束状态**：场面结束后，人物关系/信息状态/空间状态有什么变化？

禁止用“高级、电影感、震撼、唯美”等形容词替代可观察事件。

## 5. 复杂度控制

- 先确保场面逻辑成立，再追求镜头丰富。
- 没有新增信息时，不增加摄影机运动。
- 不为同框或构图擅自移动人物、家具或建筑锚点。
- 不把多个专业任务全部塞进一个长提示词；先形成共享事实，再按专业技能分别编译。
- 小任务直接调用一个专业技能；只有跨域协调确有价值时才启用本技能。

## 6. 交付格式

按需交付：
1. 导演意图简报（通常不超过一段）。
2. 专业技能调用顺序和每项输入/输出。
3. 共享事实与不可变约束。
4. 跨技能冲突及解决记录。
5. 验收矩阵：导演可读性、场景真实性、分镜连续性、运镜可执行性。
6. 未验证项与下一步。

本技能不替代场景图生成、正式分镜编写、人物站位校验、打斗动作/特效编排、运镜提示词编译或真实视频审片。

## 7. 统一数据交接门禁

跨专业导演预演必须先读取 `references/导演共享事实与SCG交接规范-V1.md`，并继续读取其中列出的 SCG、事件时间、人物站位、场景真实性和摄影机权威契约。不得另造一套与它们并行的 JSON 字段。

执行时：
- 剧本来源、已批准资产、静态场景基线、角色/道具状态、SCG 镜头快照、事件时间轴和摄影机轨迹必须可追溯到同一项目事实。
- SCG 是逐镜世界状态权威；事件时间契约是时码权威；人物空间通道按站位规则；摄影机轨迹不得改写世界状态。
- 每镜保存完整实体状态；出画/遮挡不删除实体；无来源事件不得改变身份、位置关系、持物或场景锚点。
- 项目/资产引用缺失、来源冲突或时序无法判定时，标记待审核，不得补造数据。

## 8. 自检与版本门禁

执行前先读取本目录的 `SOURCE_LOCK.json`，并以其记录的 main commit、专业技能版本和 Git Blob SHA 为准。依赖 SHA 不匹配时，停止使用陈旧摘要，重新读取 main 的专业技能与 SOURCE_LOCK；不得继续沿用过期规则。

发布前运行：

```bash
node skills/director-previs-cn/scripts/validate_director_previs.js
```

该检查器验证路由合同、来源锁、依赖文件 SHA、教室集成夹具和十一项回归用例。fight-impact-vfx 当前自身状态为 `authored_pending_review`，使用时须遵守其验证边界。静态检查只证明仓库合同一致，不证明模型真实遵循提示词，也不证明图像/视频质量提升。

当前权威依赖版本：scene-realism-director-cn V1.12.0；storyboard-director-cn V1.3.5（源规则 V2.10.5）；人物站位规则 V1.9.0；camera-motion-director-cn V1.1.1。涉及动态走位时，必须读取站位规则中的稳定 ID、人工锁定、项目状态真值、静态场景/动态角色/摄影机分轨、项目声明时间基准、多视角身份锚点、路径时间、根节点/姿态分离、grounding/foot planting、关键帧速度连续性、群演个体一致性和相机位置/视线分轨要求；不得在本 Skill 里复制第二套参数规则。若存在已授权结构化导演台/MCP，先读取实际工程和稳定 ID，保护人工锁定项，再小步编辑、验证和局部撤销；不得默认所有工具均为24fps，也不得假设消费级视频模型接受相同控制信号。

导演工作流 A/B 与场景真实性提示策略 A/B 是两个独立实验。前者只改变是否调用 director-previs-cn；后者只比较场景提示策略。不得在同一轮同时改变两个变量。

开展导演统筹效果对比时，必须先读取 `tests/导演统筹工作流A-B实验协议-V1.md`、`tests/导演统筹视觉评分量表-V1.json` 和 `tests/fixtures/导演统筹A-B实验数据集-V1.json`。实验结果必须写入 `tests/templates/导演统筹实验结果模板-V1.json` 的副本；没有真实运行数据时保持 NOT_RUN。
