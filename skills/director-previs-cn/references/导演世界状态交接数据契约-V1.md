# 导演世界状态交接数据契约 V1

版本：1.0.0  
所属技能：`director-previs-cn`  
目的：在剧本、导演统筹、场景真实性、人物调度和摄影机运镜之间传递同一场戏的世界上下文，防止各专业技能各自重建场景。  
边界：本契约只管理导演层的场景身份、资产引用、参考图职责、锁定事实和镜头链引用；**不复制分镜 SCG 的实体、关系、事件或每镜世界状态快照**。

## 1. 单一事实源

| 数据 | 唯一权威来源 | 本契约如何引用 |
|---|---|---|
| 场景实体、道具、关系、存在/可见/遮挡状态 | `storyboard-director-cn/references/分镜SCG数据契约-V1.md` | 引用 scene_id / scg_shot_id；不复制 entities / relations |
| 允许改变世界状态的事件及前置条件 | SCG 的 events | 只允许 SCG event 改变硬状态 |
| 镜头/事件时间 | `分镜事件时间数据契约-V1.md` | 统一引用同一时间基准；本契约默认毫秒 |
| 人物身份、世界位置、身体/头部/视线、路径、支撑、人工锁定 | 人物站位与场景调度规则 V1.9.0 | 使用稳定 character_id 和约束引用 |
| 场景拓扑、门窗、墙体、固定家具与参考图权威 | `scene-realism-director-cn` | 使用 scene_id、world_revision、asset_id 与参考图职责表 |
| 摄影机位置、朝向、注视点、焦距与轨迹 | `camera-motion-director-cn` | 以独立 camera_track_ref 引用，不写入人物路径 |

禁止在导演交接包中复制完整实体状态并另行维护第二份“真值”。需要读取或修改某个镜头的角色/道具状态时，回到对应 SCG shot snapshot；需要变更时建立有来源的 SCG event。

## 2. 顶层结构

每份交接包只描述一个场景版本（scene revision），推荐字段：

- `schema_version`：契约版本。
- `handoff_id`：交接包唯一编号。
- `project_id`：单剧项目编号。
- `source_script`：剧本文件/版本/来源场次。
- `scene`：稳定 scene_id、world_revision、static_world_revision。
- `timebase`：时间单位、起点定义；有帧率时显式记录，不假定所有工具都是24fps。
- `canonical_assets`：人物、场景、道具等权威资产 ID 与版本。
- `reference_map`：每张参考图的 reference_id、对应 asset_id、用途、权威字段、优先级和允许覆盖字段。
- `invariants`：用户或导演已确认的不可变约束。
- `shot_chain`：镜头顺序、SCG shot ID、前后镜头引用、时间区间和独立摄影机轨引用。
- `continuity_policy`：状态变更权限、静态世界修订门禁、人物/摄影机分轨规则。
- `unknowns`：尚未确定的信息，不能被下游技能静默补成事实。

## 3. 场景版本与镜头链

- 同一份 handoff 只包含一个 scene_id 与一个 static_world_revision。
- 同场戏的所有镜头必须引用相同 scene_id 和 static_world_revision。
- 如果剧情确实改变墙体、门窗、固定家具、道路或其他静态拓扑，先记录批准的结构变化和新 world_revision，再建立新 handoff；不得仅因摄影机换角度而修改静态世界版本。
- 每个镜头使用稳定 shot_id，并引用已有 SCG 的 scg_shot_id。镜头链中的 predecessor_shot_id 必须指向前一个镜头。
- 时间采用明确的全局或场景局部毫秒时间轴；不得混用毫秒、秒和帧。帧率是可选的项目属性，不是全局常量。
- 摄影机轨迹只能放入 camera_track_ref；不得把摄影机移动写成人物世界坐标变化。

## 4. 参考图职责与冲突处理

每份参考图必须标明：
1. reference_id 和文件/资产引用；
2. role（例如 layout_truth、architecture、character_identity、wardrobe、prop_shape、camera_view）；
3. authority_fields（它对哪些事实有权威性）；
4. priority（数字越小优先级越高）；
5. may_override_fields（允许影响的字段）。

同一 authority_field 若有两份同优先级来源，必须报冲突并要求导演/用户裁决；不能把两张互相矛盾的俯视图拼成一个新布局。角色图不得覆盖桌椅布局，俯视图不得擅自覆盖人物身份，风格参考不得覆盖建筑拓扑。颜色标注只能辅助识别，不能替代稳定 ID。

## 5. 不可变事实与未知项

- 用户确认的站位、场景拓扑、角色身份和道具归属写入 invariants，标记 locked。
- 推断项标记 derived，并记录 source_id / rationale；不得伪装成用户明确事实。
- 未知项写入 unknowns，注明影响和需要何种证据解决。
- 下游专业技能只能在明确授权字段内提出修改；不得无理由覆盖 locked 项。
- 需要修改锁定项时先输出冲突对象、当前值、拟改值和影响，取得明确授权后才修改。

## 6. 状态连续性与验证

- 本契约验证交接包结构、场景/资产/参考图/镜头引用和不可变规则。
- SCG 校验器负责每镜完整实体全集、关系和事件合法性；跨镜未授权变化应由 SCG 状态继承/事件规则拦截。
- 事件时间校验器负责镜头时间、事件持续时间、依赖、互斥动作和可见事件。
- 人物站位规则负责角色世界坐标、朝向、视线、根节点路径、身体姿态、支撑和多人避让。
- 运镜规则负责摄影机轨迹、注视点、焦距/视场和运动预算。
- 本契约通过不等于 SCG、分镜、图片或视频通过；必须分别运行相应校验器和真实视觉验收。

## 7. 最小校验门禁

机器校验至少检查：
- 必填字段、版本和稳定 ID；
- canonical asset / reference / shot ID 唯一；
- reference_map 只能引用已登记资产；
- 同字段同优先级冲突必须阻断；
- 镜头链顺序、前驱引用和时间区间合法；
- 所有镜头共享相同 scene_id 与 static_world_revision；
- 世界状态只允许由 SCG events 改变；
- 摄影机轨迹与人物路径分开；
- 不允许在 handoff 中复制 entities / relations / events，防止形成第二个状态事实源。

执行：
```bash
node skills/director-previs-cn/scripts/validate_world_state_handoff.js
```

## 8. 验收等级

- 结构校验通过：仅表示交接包字段/引用合同有效。
- SCG / 时间轴校验通过：表示结构化镜头状态和事件账本通过相应检查。
- 白模预演通过：表示空间/路径/摄影机意图在预演工具中成立。
- 真实图像/视频通过：必须检查真实生成结果，不能由上述静态检查代替。
